寫成一份給編輯早上直接看的稿單提案。

**評分、入榜、排序、跨大分類聚合全部由候選 json 決定，不是你的職責**：你不重新

## 每題輸出

依候選 json 的順序（已經照分數排好，不要自己重排），每題輸出六個欄位，
**區塊順序固定為：稿頭 → 角度 → 建議形式 → 素材行 → 缺什麼 → 分派建議**
（不要調換，範例見本節最後）：

1. **稿頭**：3–6 字短標題，濃縮新聞切角（`common/11`「稿頭」節），不是逐字新聞
   標題，不套固定字庫。
2. **角度**：一句話，這題現在該怎麼切、為什麼值得做（不是複述摘要）。若這題
   建議併入另一題（見上方「同 canonical」說明），也寫在這欄。
3. **建議形式**：三選一，判準：
   - **CTV**（CNN Newsource 單一 story 全流程寫稿，`cnn/01`）：`ctv_ids` 非空。
   - **SOT**（一般外電配稿、有引言）：`ctv_ids` 為空，且這題 ≥2 個不同來源
     （看 `items[].src`）且至少一則 `bite` 有值（不是 `false`）。
   - **BS**（主播稿，無合適引言／單一來源）：其餘情況。
4. **素材行**：照 `common/11`「素材代碼」＋「短摘要」＋「選用標記」規則，**每則
   各佔一行**：
   ```
   {素材代碼} ({備註}) [(BITE)] {摘要}▎畫面：{逐項}▎BITE：「{濃縮引言}」
   ```
   或 `▎無BITE。`。**摘要直接沿用 `items[].summary`**，不用重新改寫，`備註`
   沿用 `items[].notes`（空字串就不寫括號），`BITE` 濃縮自 `items[].bite`
   （非 `false` 時）。⛔ **同一題多則素材一律分開各寫一行，不套用
   `common/11`「素材代碼」節「同一則故事用 ` / ` 相接」那條規則**——那條是給
   人工整理外電清單用的，這裡每則素材對應候選 json 裡獨立一個 `items[]`
   元素，一行只放一則，讓編輯看得出到底有幾支帶。
5. **缺什麼**：直接沿用候選 json 的 `missing`（沒有就寫「無」）；`items_omitted`
   非 0 時視情況比照上方說明附註。
6. **分派建議**：只填**角色**，四條判準依序檢查、符合第一條就定案：
   - **連線**：屬突發傷亡事件，或 `items` 裡「現場側錄」類素材（看 `notes`／
     `summary` 是否明顯是記者在現場連線、side-recording）佔多數。
   - **體育**：`tc.T`（候選 json 沒有直接給 `tc`，看該題素材 `notes`／`summary`
     內容或 `bigs` 是否為體育類）含「體育」。
   - **影音**：至少一則 `hilite=true`（🔖 畫面好）且該題整體沒有可用 `bite`
     （所有 `items[].bite` 皆為 `false`）。
   - **其餘**：外電編譯。
   **⛔ 不准填人名**——D16 裁決記者名單尚未提供，AI 不能自創分派對象。

**範例**（單一題目，區塊順序照上面固定順序）：

```
俄烏空襲升級
俄羅斯昨夜對基輔發動大規模空襲，烏方稱多處民宅受損，值得追蹤傷亡數字是否上修。
SOT
RT1124 (現場濃煙) 基輔民宅遭飛彈擊中冒出濃煙▎畫面：民宅損毀、消防灌救▎BITE：「當地居民描述爆炸瞬間」
AP4674931 (官方說法) 烏克蘭官員證實傷亡人數上修▎畫面：記者會畫面▎無BITE。
缺什麼：無
分派建議：外電編譯
```
