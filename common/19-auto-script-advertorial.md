## 一句話

需求單＋官方新聞稿＋散裝帶 → SOT 格式完成稿。畫面跟 BITE 只能來自盤點後的 `#XX`。

## 觸發

使用者說「自動寫稿(業配)」「Advertorial」「廣編」，或交付業配需求單／案件資料夾並下令寫稿。  
**不明確下令不寫。** 若只說「先分析能不能開寫」「沒批准不得寫稿」→ 只回覆蓋判斷，不盤點全文、不寫稿。  
稿名結尾「準」走準連，不走本流程。

## 與 06 的優先序

| 層 | 管什麼 | 誰贏 |
|---|---|---|
| 格式鐵則 | 完成稿＝CTV（稿頭／SUPER／BAR 1-4／BAR1 內文、OS 每行≤14 去標點、SB 中文分行去標點） | **cnn/01**；NS 指令行是業配加的，不上字不配音 |
| 呈現 | 時長、必講／禁講、要用哪段訪問、多段 NS、口語 | **需求單；使用者當場改口再蓋過需求單** |
| 事實 | 活動名、日期、人次、官方說法 | **官方新聞稿**；BITE 逐字保留口白，不拿新聞稿改受訪者數字 |
| 畫面 | 能出什麼鏡頭 | **盤點後的素材**；新聞稿有、畫面上沒有的元素預設不寫 |

## 輸入（檔名寬認）

案件資料夾必備三類。**認內容，不因檔名差兩個字就停問。**

| 角色 | 慣例檔名 | 實戰也算數 |
|---|---|---|
| 需求單（呈現必守） | `{SLUG} 業配需求單.txt` | `{SLUG} 業配說明.jpg`／掃描圖／郵件截圖。能讀就用；能轉 txt 更好，**不擋開寫** |
| 官方新聞稿（事實基礎） | `{SLUG} 官方新聞稿.txt` | `{SLUG} 新聞稿.txt`；PDF／Word 先轉 txt |
| 散裝影音 | 原檔名可保留 | 無編號、無 shotlist |

兩者內容都找不到 → 停問，不寫稿。  
需求單的呈現要求 vs 新聞稿的數字／用詞矛盾 → 停問，不擅自選邊。

需求單上的 **Google Drive 連結不是自動缺件**。先對本機檔名（與檔案大小）。對得上＝已到。對不上才停問「要不要下載」。

## 落檔

```
G:\我的雲端硬碟\Claude共用\業配自動寫稿測試\{SLUG}\
```

至少放：`{SLUG} 完成文稿.txt`、`{SLUG} 素材清單.txt`、用到的 ASR。原片不強制改名、不強制搬進此夾。對話交路徑＋總長度＋SB 數；不要把長稿重複貼兩次。本機另存 `D:\Downloads` 依使用者產出慣例。

## 開寫前（實戰必做）

1. 讀需求單全文＋官方新聞稿。
2. 列出影音，對需求單點名的必用畫面／BITE。
3. **先回能不能開寫**（缺件／對得上／有條件開寫）。沒批准不寫稿。
4. 使用者批准或直接下令寫稿後，才做完整盤點與完成稿。

## 盤點

把散裝帶編成 `#XX`，產出 `{SLUG} 素材清單.txt`，**不強制改名原片**。

```
#XX｜原檔名｜BITE/B-ROLL/混合｜可用畫面一句｜BITE 一句（無則「無」）｜時長｜限制／備註
```

另附 `#XX` → 原檔路徑。編號依**原檔名升冪**，`#01` 起；需求單指定順序則跟需求單。每支最多一次 transcription。

### 「第二個訪問」

需求單寫「用處長第二個訪問／第二段」時：

- **先假設同一條長帶裡有兩段 take**，不是另缺一檔。
- 中間若有「再講一次／處長你又要講／OK 好」＝分段點。
- **用後面那段**；第一段常見問題：口白還在預告活動沒結束、品質較差。
- Drive 單檔連結若內容就是這條長帶，本機有長帶就夠。

## 寫稿 overlay（只在這裡加，不改 06）

完成稿格式＝SOT。必讀順序仍是 `00` → `auto-script-learning/INDEX` 的 PROMPT → `10` 分層讀法 → `07` 找 TC。本檔與 06 衝突時：呈現跟需求單，格式跟 06。

### 活動名與閉幕必須進 OS

主播稿頭**不隨 PKG 播出**。活動全名、閉幕時點（例如「2026花蓮FUN暑假」昨(20)日圓滿落幕）**一定要寫進記者 OS**，不能只放稿頭。可用口語改寫，不可省略。收尾若再點一次「已經落幕」可以，但不要寫成還在預告的「即將謝幕」去打臉已落幕。

### 只寫畫面上有的

新聞稿裡的裝置／體驗（千陽號、天鵝船、YOYO、角色展等），盤點沒拍到 → **OS 預設不提**。  
例外：閉幕、活動名、官方人次／天數等「有所本的事實」可進 OS，畫面配活動現場即可（不要把 8/16 夜秀寫成 8/20 閉幕當日）。

使用者當場說「這些可不用提、寫素材有的畫面」→ 跟這條，壓過新聞稿清單。

### 數字

- OS：官方新聞稿（例：37 天、約 49 萬人次）。
- SB：受訪者原話（例：每天約 1 萬人），**不准改口白去對齊新聞稿**。
- 兩套數字並存時，OS 不要複誦 BITE 那套去打臉官方稿。

### 口語

記者 OS 用能唸的口語（擠滿、這一甩、晚上、跟著、跑完），少用書面修辭（會呼吸的光、暑假派對、輪番）。使用者丟「人工改」→ **以人工改為底再修**，不要拿 AI 初稿覆蓋。

### NS 與 BITE

- 需求單／使用者要「多段 NS 串接」時，可連放數段短 NS（人潮→火舞→水舞→煙火），每段都要有起訖，秒數計入總長。
- 同一受訪者可出兩段 SB（不同句），前後都要有 OS 橋。
- 中文訪問：SB 第 5 行＝口白原文（繁體校正後），與第 3 行一致。

### 時長

需求單的秒數為預設目標（例：SOT-60 秒）。使用者當場改（例：1 分 50 以內）→ `--target-seconds` 跟當場。交稿前跑：

```
python scripts/validate_sot.py "{SLUG} 完成文稿.txt" --mode sot --target-seconds N
```

不新增 mode。風格檢核表（`10` 第 12、15 節）仍要跑。

### 自補 AP 照片

業配無外電清單 → **跳過並在對話註明**，不因此 FAIL。

## 上字／BAR／SUPER（製片，跟 CTV）

完成稿的主標／次標仍走 SOT 17.5–18.5。**燒進影片的字**改跟 [`production/03-subtitle-burn.md`](../production/03-subtitle-burn.md) 與 CTV：

| 層 | 業配上字規格 |
|---|---|
| Cap（OS／SB 逐句） | 每行 ≤**14** 全形（`script_width`：全形 1、半形 0.5）。長句在上字時折行，不改完成稿 |
| Bar | **16.5–17.5** 全形。由主標題壓縮，不上 18 字的 SOT 主標 |
| Super | ≤**16.5**；只在 SB。職稱短銜＋姓名 |
| 樣式／安全框 | 與 CTV 相同：MarginL/R 140、Cap MarginV 220、Bar／Super MarginV 300 |

時間軸（2026-08-21 花蓮暑假2400 踩雷後入規）：

- OS／SB Cap **直接用完成稿那一行**（已 ≤14、無標點），對上該句 synth／SB 語音區間。不要再把長句折行。
- **NS 預設 1.5–2 秒**，只出 Bar 不出 Cap。禁止用 OS 字幕填 NS。
- 尾字 +0.15s 不得跨出本段、不得吃下一句。
- 驗證：抽掉 `NS` 行後可跑 `validate_sot.py --mode ctv`。不要為業配去改驗證器。

實作：`scripts/production_advertorial/make_subs.py`。不要改 `scripts/production/make_subs.py`。

## 停問

| 條件 | 動作 |
|---|---|
| 需求單與新聞稿內容都找不到 | 停問 |
| 需求單與新聞稿事實矛盾 | 停問 |
| 需求單必用畫面／BITE 本機對不上，且 Drive 也確認沒下 | 停問 |
| 使用者只要分析、沒批准寫稿 | 只回覆蓋，不寫 |
| 完成稿 `#XX` 在清單找不到檔 | 停手 |
