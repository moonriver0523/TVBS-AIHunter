1. 逐列讀索引表所有非歸檔列（ID、問題、來源、優先、狀態、備註）。統計各狀態數量（✅／🔶／⬜／👁／⏸／❌／🚫 等）。
2. 對每一列判定「帳面狀態」與「實際狀態」是否一致，用以下證據交叉查：
   - `git log`（含 `--all` 看分支；用 ID 如 `R53`、`T15`、`A47` 搜 commit message；也搜關鍵檔名／函式）。

3. 對每一列給出分類：
   - `一致`（不用動）
   - `已完成未更新`（程式／規則已上線，但狀態仍為 ⬜／🔶）→ 附證據與建議狀態

   - `矛盾`（索引表與詳情檔、或兩列之間說法相反）

4. 檢查帳本內部問題：索引表與 `master-detail` 是否有 ID 對不上、已完成列是否仍留在索引表而未歸檔、路徑是否已失效（例如寫 `D:\Downloads\…` 的報告路徑應改指 repo 內檔案）、❌ 明文不做段與實際是否一致、不可 merge 殘留分支清單是否過期（用 `git branch -a`／`git log` 驗證分支是否已合併或刪除）。
