### 2.2 算法與限制

- calls：唯一 `tool_use.id`；requests：唯一 assistant `message.id`，合併 streaming chunks 後取最後 usage，避免把 thinking/text/tool chunks 重複加總。
- wall：result 的 `duration_ms`；API time 另有 `duration_api_ms`，兩者不混用。launcher R 的 wall 還含啟動等小額開銷，故可能略大。
- 工具等待：以 tool_use→對應 tool_result 的 timestamp 區間取聯集，避免平行工具重複計時。剩餘時間＝wall−聯集，是 **model/harness residual**，不是純 inference latency。
- 有效產出率＝result output_tokens／residual 秒數；只能找異常，不能以它證明服務商 throttle。沒有逐 request server queue／TTFT／decode telemetry。
- 模板 SHA：將 `prompt_snapshot.systemPrompt` 各段以兩個 LF 接合，UTF-8 SHA256，表中只印前 12 碼；字元是 Python Unicode code points，不是 tokens。
- M 的 repo/規則 hash 是事後記帳；`dirty:true` 意味著不能單憑 commit 時間保證全輪的每個檔案未變。本次在關鍵轉折另核對 C 中實際注入的 user prompt、MEMORY、system snapshot。
- 未重跑線上掃帶或付費模型，未做模板 A/B；所以輸出的是可被否證的因果假設與已知機制，不是假裝完成控制實驗。

## 7. 分級與可執行優先順序（供裁決）

### 7.1 小修就有感：先補定位能力與減少確定返工

1. **P0a runtime指紋與報表**（掛A1/T1/A35，A45新發現）：每輪開工記system snapshot hash/char count、初始input、CLI/provider/model、工具schema摘要hash、MEMORY hash、實際prompt/rule hash、repo dirty與run/session對映；收工區分wall/tool wait/residual。驗收：0700/1100 fixture必能標出斷點，同checkpoint多run不合併，stream chunks usage不重算。這能讓後續實驗有效，不承諾本身降wall。
2. **P0b raw receipt最小防呆**（R13/D7/R14家族）：單一run專屬絕對路徑、寫入成功receipt含run_id/site/checkpoint/fetched_at/schema/hash/row_count；解析前核對receipt、拒絕把字符串當素材列表、同名旧檔不可作fallback。驗收：舊檔/錯站/錯run/字串payload都明確失敗，完整src_text保留。這是資料傳輸契約，不是重啟被裁不做的固定collector。
3. **P1 A43真實採用驗收**：先觀察既有已上線版本，不再加一個patch工具。記Edit→patch是否真的轉移、整份Write/inspect/rebuild是否補漲。品質不退化、同量/同runtime輪的總wall/cost改善才算有感；不能只驗單元測試或一個build runtime。
4. **P1帳本摘要對帳**：裁決後逐條更新過期索引、詳細歷程只加不改；priority不以「✅」「待做」單欄判斷。沒有實作授權的D21接線、D5看門狗等仍待裁，不可把摘要修正當授權。

### 7.2 值得整個模組重構：以穩定契約逐步替換

**P2：站級機械管線**（A24/T9/T12/D19/A39～44）。介面接受「已抓好的RawReceipt＋既有state唯讀投影＋agent decision patch」，輸出「candidate/validation/coverage/repair suggestions」；agent負責素材判斷，工具負責形狀轉換、分頁與固定步驟。保留NS/AP/RT、ENEX/ABC adapter。單站有界失敗，不用任意shell字串批次器。先抽loader/inspection避免bridge反向依賴整個3897行CLI，再試同站獨立reads的T14 deterministic fan-out。驗收以相同raw replay的IDs/src_text/category/tc/skip/dropped守恆，不追求生成文字逐字相同。

**P3：正式收工協調與receipt**（A3/D22/R31/A7/A41）。將取得輸入快照、清單對帳、render、結果彙整接成有序程序；語義疑點仍交agent，真失守需帶原因，0新稿可為合法完成。至少區分complete/degraded/aborted，而不是僅success/DONE；禁止用舊txt存在當本輪完成。平台補ID集合／skip理由／coverage receipt，count相等不足證明無漏收。D22已列管待實作但未指派，先沿它的只警告政策設計，不擅自升全站硬閘。

**P4：state domain/read/write分層＋單writer契約**（F5/8）。明確傳state path與run identity；查詢模組import不得探測當日G槽。writer集中revision/SHA、原子替換、併發衝突處置，外部整併也遵循；browser lease與資料寫入lease分責但過渡期保留既有掃帶排他策略。先用隔離雙writer replay驗證lost-update被擋，再考慮生產替换；不在本次引入資料庫或改所有state schema。
