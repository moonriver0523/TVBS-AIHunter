## 一、使用者的需求修正（比修 bug 更重要）

前一手做的是「**篩選過的候選清單**」，使用者要的是**兩件不一樣的事**：

### 1. 列出**所有**段落供人挑，不是列「候選」

現行 `build_candidates()` 有一堆過濾：`CAND_MIN_SEC = 8` 秒以下丟掉、有官方文稿時**只**列官方引言（`if not quotes:` 才走 ASR 段落）、超過 25 秒截斷。
使用者要的是**整支素材的所有段落都列出來**，由人自己看、自己選——工具不要替人篩掉東西。

**改法方向（給接手者判斷，不是命令）：**

- 預設列出**完整逐字段落**（whisper 的 segment／或合併後的 utterance），一行一段、附 TC 與秒數。
- 官方引言標記、秒數落在 10–25 秒、疑似交接語……這些**降級為標籤／排序提示**，不再當成「入選條件」。
- 過濾器改成 UI 上可切換的開關（例如「只看官方引言」「只看 ≥8 秒」），預設全開＝全部顯示。
- 有官方文稿時，官方引言仍要標出來（用字以官方稿為準這條**不變**，見 §三）。

### 2. 中文翻譯要自動產生

前一手把第 3 行（中文翻譯）留白手填，理由是「那不是機械產物」——**使用者不接受**，要工具產出中文。
這等於原計畫書的 **Phase 1b**，現在是必要功能不是選配。

**必須遵守的翻譯規格（`00-寫稿通則.md` §4）：**

- 中文**不帶「」引號**。
- **`P-037`**：原文代名詞（He／They／it）指涉不明時，用**半形括號**補主詞，例「(普欽)知道…」；補的主詞要有素材依據，不可自行推定。
- **不可殘譯**——中文必須完整對應英文原句，不可為排版砍半。
- 繁體中文，臺灣新聞用語（川普／普欽／澤倫斯基這類固定譯名）。
- 第 5 行原文**一律取官方文稿逐字**，ASR 只用來定位時間（這條與翻譯無關但常一起搞錯）。

實作選項：呼叫 Claude API（Key 只放本機環境變數，**不進 repo、不進 HTML**——記取 AICG 那次把 Key 烙進公開網頁的教訓）。

## 二、目前程式現況與**可疑的壞點**（未經證實的推測，請自行複驗）

檔案：

| 檔案 | 狀態 |
|---|---|
| `scripts/sb_format.py` | 可信度較高，20 測試全綠。**建議保留** |
| `scripts/test_sb_format.py` | 20 項全綠 |
| `scripts/bite_workbench.py` | 後端 API curl 可通，但設計不符新需求（見 §一） |
| `scripts/test_bite_workbench.py` | 15 項全綠，但測的是舊的「候選」語意，改需求後多數要重寫 |
| `scripts/assets/bite_workbench.html` | **從未在瀏覽器開過**，使用者實測為壞 |

**四個最可疑的壞點（推測，未驗證）：**

1. **轉錄會把整個服務卡死。** `/api/transcribe` 是同步阻塞的，65 分鐘素材要跑 160 秒以上，期間 uvicorn 單 worker 完全不回應，前端 fetch 可能直接超時——症狀就是「按下去什麼都沒發生／整頁死掉」。**應改成背景工作＋輪詢進度**。
2. **點候選不會跳到 TC。** `pickCandidate()` 直接設 `player.currentTime`，但剛切換素材時 `<video>` 還沒 `loadedmetadata`，這個賦值會被靜默忽略。**要等 metadata 或監聽事件重試**。
3. **無 Range 的請求會把整支影片讀進記憶體**（`/media` 的 `f.read()`），231MB／522MB 素材直接爆掉。**應一律走串流**。
4. **中文檔名的 URL 編碼**在瀏覽器與 curl 行為不同，素材選取／`/media` 可能 404。

⚠️ 以上是推測。**請自己打開瀏覽器、看 console 與 network，實際確認症狀是什麼**，不要照抄我的猜測去改。
