# 合併改動計畫

前提：

- 第1項 AP coverage 已存在於 commit `3aeb6a7`，本計畫不重做。
- 本計畫不修改任何 `common/*.md`、不改規則文字、不改 ENEX/ABC 既有 escape flags。
- 實作者只應修改下列程式與測試檔；目前 worktree 若已有其他變更，全部保留。
- 建議拆成 4 個 commit，順序為：項目3 → 項目4 → 項目2 → 項目5。

## 共用原則

1. 所有 hard gate 都要在 mutation/save 前完成。
2. 錯誤一律包含：

   - 穩定錯誤碼。
   - 受影響的 ID。
   - 為何拒絕。
   - agent 下一步可直接照做的修復方式。
   - 明確說明尚未寫入，避免 agent 以為已成功。

3. `needs-review` 備忘殼與真素材分開判斷：

   ```python
   script_status == "note" and not raw_entry
   ```

   這類項目可以使用 `source: "?"` 或空白 source，不得套用真素材的 source/ID gate。

## Source 常數

在 `s2_state.py` 建立單一權威常數，避免各 command 各寫一套：

```python
SOURCE_VALUES = frozenset({
    "AP", "RT", "NS",
    "SIDE_CNN", "SIDE_NHK",
    "YT", "YNA", "CNA",
    "ENEX", "ABC",
})
```

另保留兩個相容規則：

1. `YNA`／`CNA` 目前有兩種既存寫法：

   - `source: "YT"`，ID 是 `YNA01`／`CNA01`
   - `source: "YNA"`／`"CNA"`，ID 同前綴

   兩種都接受，不在本項強制統一。

2. `OTH` 是 `common/17` 後來加入的受控例外。若 ID 符合 `OTH\d{2,3}`，source 可為既有實際平台名，但仍須：

   - 非空。
   - 單行字串。
   - 不得是 TODO／測試／fake token。
   - 不得把任意不符合 ID 的普通 source 放行。

## ID 規則

新增 `SOURCE_ID_RULES`，只驗識別碼形狀，不解讀新聞內容：

| Source | 合法 ID 形狀 |
|---|---|
| `RT` | `RT` + 4 位數 |
| `AP` | `AP` + 7 位數，或 `APcctv`／`APcns` + 6 位數 |
| `NS` | `[A-Z]{2,6}-\d{1,4}[A-Z]{2}`，例如 `WE-006WE`、`DIG-01TU` |
| `SIDE_CNN` | `CNN [MM-DD ]?HHMMSS` |
| `SIDE_NHK` | `NHK [MM-DD ]?HHMMSS` |
| `YT` | `YT:<YouTube video id>`，另接受既有 `YNA##`／`CNA##` 相容形 |
| `YNA` | `YNA` + 2–3 位數 |
| `CNA` | `CNA` + 2–3 位數 |
| `ENEX` | `ENEX` + 4–8 位數 |
| `ABC` | `ABC` + 6–16 位數 |
| OTH 例外 | `OTH` + 2–3 位數 |

`RTV1234` 仍先走既有 `norm_id()` 轉成 `RT1234`，不要另創第二套正規化。

## TODO／假項目檢查

新增大小寫不敏感的 ID placeholder deny list，例如：

```python
PLACEHOLDER_ID_RE = re.compile(
    r"^(?:TODO|TBD|N/?A|UNKNOWN|NONE|TEST|SAMPLE|FAKE|DUMMY|"
    r"PLACEHOLDER|SCRIPT[-_ ]?TODO|CATEGORY[-_ ]?FIX|RT[-_ ]?MISC)",
    re.I,
)
```

至少拒絕：

- `SCRIPT-TODO`
- `CATEGORY-FIX-1`
- `RT-MISC-20-30`
- `TODO`、`TBD`、`FAKE`、`DUMMY` 等。
- source 與 ID 不相符的說明文字。

不要對新聞標題、`src_text` 或正常摘要做寬鬆的 substring 搜尋，避免把正常新聞內容中的 `test`、`sample` 等字誤判成假項目。

```python
def validate_material_row(row, *, context="add"):
```

## `src_text` validator

新增純函式：

```python
def validate_src_text(source, src_text, *, note_shell=False):
    """回傳錯誤清單，不寫 state。"""
```

對 RT/AP/NS 真素材檢查：


## Recovery flag

新增：

```text
--allow-missing-src-text
```

但只允許放寬「缺少／空白」的 src_text，不允許放寬「已混入 agent 說明」。

帶 flag 時：

- 缺 src_text 的 RT/AP/NS 可寫入。
- 每筆自動加入 `needs_review`，例如：

  ```text
  src_text_missing: 明確使用 --allow-missing-src-text，待人工回補站方原文
  ```

- stdout/stderr 必須明確列出受影響 ID。
- 不得讓正式排程流程預設傳此 flag。

## `cmd_add_batch()` mutation 順序

在目前 `new_topics` 登記及 `state["items"]` 寫入前：

1. 讀取並拆 envelope。
2. 執行既有 `_reject_bare_array()`。
3. 執行項目3的 source/ID schema preflight。
4. 對所有「即將新增」的 RT/AP/NS 真素材執行 src_text gate。
5. Gate 全部通過後，才進入現有分類、T/C、BITE、lint、`new_item()` 和 save。

既有 `needs-review` note shell 不走這條路徑。

## Compare pure core

把目前 `cmd_compare()` 內的比對邏輯抽成純函式，例如：

```python
def compare_items(raw_items, batch_items, *, site=None,
                  required=DEFAULT_REQUIRED, allowed_missing=()):
    """回傳 CompareReport，不 print、不 exit。"""
```

回報至少包含：

```python
{
    "missing": [...],
    "extra": [...],
    "duplicates": [...],
    "gaps": [{"id": "...", "fields": [...]}],
    "src_text_issues": [...],
    "clean": False,
}
```

`cmd_compare()` 負責輸出與 exit：

- 無差異：`exit 0`。
- 有 missing、extra、duplicate、field gap 或三站 src_text contamination：`exit 1`。
- 輸出：

  ```text
  ⛔ compare 未通過；不可接續 add-batch。
    raw 有但 batch 沒有：...
    batch 缺欄位：...
    下一步：修正 batch 後重跑 compare，只有 exit 0 才能繼續寫入。
  ```

保留目前 raw/batch 讀檔錯誤的既有離開碼語意。

`main()` 必須接住 command return value：

```python
rc = args.func(args)
if isinstance(rc, int):
    sys.exit(rc)
```

## Build 寫檔前 gate

`cmd_build()` 的 normal branch 與 skeleton branch 都要在 `_write_or_preview_build()` 前呼叫同一個 compare core。

- Normal branch 的 expected raw IDs 排除現有 `skip_of()` 明確排除項目。
- Skeleton branch 使用 skeleton rows 作為 expected rows。
- 有 missing/extra/duplicate/gap 時，`batch.json` 不得產生。
- `--dry-run` 也必須失敗，不得只印預覽成功。
- `parse_draft_entry()` 的 `raw_entry` fallback 和「同時有 entry/raw_entry」exit 2 行為維持不變。

這樣即使 agent 沒有手動執行 standalone `compare`，主線 `build` 也會在 batch 寫出前擋住；standalone `compare` 的非零結果則不能再被 shell 流程忽略。

## 必測案例

- RT/AP/NS 都有非空純站方 `src_text`：正常寫入。
- 任一筆缺 `src_text`：`exit 2`、state hash 不變、沒有部分寫入。
- `src_text=""`、全空白、非字串：`exit 2`。
- 尾端混入中文 agent 說明：`exit 2`。
- `--allow-missing-src-text` 只放行缺漏，並寫 `needs_review`。
- 污染的 src_text 即使帶 recovery flag 仍拒絕。
- ENEX/ABC 的 `s2_platform_merge` 既有缺 src_text hard fail 和 escape flags 回歸測試通過。
- `compare` clean 為 0，存在差異為 1。
- `build` compare 不通過時不產出 batch。
- `build --dry-run` compare 不通過時也不產出檔案。
- `parse_draft_entry()` 的 raw_entry fallback 仍可用，entry/raw_entry 衝突仍為 exit 2。

## 統一 reconcile schema

`s2_reconcile.py` 建立：

```python
SITE_ORDER = ("RT", "AP", "NS", "ENEX", "ABC")
RECONCILE_SCHEMA = "s2-reconcile/v1"
```

每輪格式：

```json
{
  "_schema": "s2-reconcile/v1",
  "finished_at": "2026-09-17T22:05:00+08:00",
  "RT": {
    "status": "ok",
    "source": "RT",
    "evidence_path": ".../_audit_rt_2200.txt",
    "list": 42,
    "got": 42,
    "missing": 0,
    "missing_ids": [],
    "cross_day": [],
    "ts": "..."
  },
  "AP": {},
  "NS": {},
  "ENEX": {
    "status": "not-scheduled",
    "source": "ENEX",
    "reason_code": "NOT_SCHEDULED",
    "reason": "本輪固定掃帶未啟用 ENEX"
  },
  "ABC": {}
}
```

允許的 status：

| Status | 意義 | 是否算收工已留痕 |
|---|---|---|
| `ok` | evidence 存在且對帳一致 | 是 |
| `needs-review` | 明確記錄站台不可用或數量落差 | 是，但要告警 |
| `not-scheduled` | 本輪明確未排該站 | 是 |
| `missing-evidence` | 沒有 evidence，也沒有明確例外 | 否，finish 回非零 |

`needs-review` 不是 `ok`，統計和通知必須分開呈現；但不可因此讓無人值守輪次停死。

## RT/AP/NS adapter

保留 `s2_audit.reconcile()` 的既有核心：

- `parse_list_file()`
- RT bare code 補 `RT`
- cross-day 判斷
- window_start 到本輪 checkpoint 的時間窗
- needs-review 中「不收／重複／排除」的去重邏輯

只在外層轉成統一 record，補上：

- `status`
- `source`
- `evidence_path`
- `schema`
- `ts`

`_reconcile_section()` 應改為回傳 records，正式 state 寫入集中由 `s2_finish.py` 一次完成，避免每站讀寫一次造成覆蓋或 race。

## ENEX/ABC adapter

將 `s2_platform_reconcile.py` 目前的主體抽成純函式，例如：

```python
def reconcile_candidate(doc, true_count, site):
    """回傳統一 reconcile record，不直接寫檔。"""
```

輸入：

- candidate JSON 的 `counts.掃描`
- `counts.收錄`
- agent 用健康檢查取得的 `true_count`
- `site` 必須是 `ENEX` 或 `ABC`

record 對應：

```text
list          = candidate counts.掃描
got           = candidate counts.收錄
missing       = abs(true_count - counts.掃描)
missing_ids   = []
true_count    = true_count
reported_count = counts.掃描
delta         = true_count - counts.掃描
```

規則：

- delta 為 0：`status="ok"`。
- delta 非 0：`status="needs-review"`、`reason_code="COUNT_MISMATCH"`。
- candidate 缺 `counts.掃描`：`missing-evidence`，不可猜成 0。
- 沒有 candidate 或沒有 true count：除非明確傳入 unavailable，否則是 `missing-evidence`。
- `--apply` 的既有行為仍保留：可把 mismatch 備註寫回 candidate。
- 新增 `--state-file`、`--checkpoint`、`--site` 時，另可把正式 record 寫入 state 的 `reconcile_log`。
- 舊的單純 `--file --true-count` 呼叫行為與 exit code 必須保留。

## 明確的站台不可用例外

`s2_finish.py` 提供：

```text
--unavailable "NS=登入逾時，無法取得清單"
--unavailable "AP=站方回 5xx"
```

這會寫成：

```json
{
  "status": "needs-review",
  "reason_code": "STATION_UNAVAILABLE",
  "reason": "登入逾時，無法取得清單",
  "evidence_path": null,
  "list": null,
  "got": null,
  "missing": null,
  "missing_ids": []
}
```

不可把「找不到快照」自動當成站台不可用，否則 agent 忘記做稽核會被假裝成正常例外。

固定掃帶未啟用的 ENEX/ABC，必須由 `s2_scan.ps1` 明確傳：

```text
--not-scheduled ENEX --not-scheduled ABC
```

若本輪實際執行 ENEX/ABC，則必須提供 candidate + true count，或明確 unavailable。

## `s2_finish.py` 流程

執行順序：

1. 解析 checkpoint、state path、scratch path。
2. RT/AP/NS 使用明確傳入的快照；未傳入時只尋找「檔名 checkpoint 相符」的快照。
3. 不可只取 scratch 內最新檔，避免拿到上一輪快照。
4. ENEX/ABC 使用明確 candidate／true count。
5. 對缺證據、站台不可用、未排程分別產生不同 status。
6. 一次寫入完整五站 `reconcile_log`。
7. 重跑同一 checkpoint 必須冪等，不重複 append、不刪掉其他站 record。
8. 所有五站都有 `ok`、`needs-review` 或 `not-scheduled` 時回傳 `0`。
9. 有 `missing-evidence` 時回傳 `1`，但不可讓 PowerShell catch 直接中斷後續收工記錄。

## `s2_scan.ps1` 接線

在目前 agent 結束後、DONE／Ntfy 通知前：

1. 呼叫 `s2_finish.py`。
2. 捕捉 `$LASTEXITCODE`，不要讓 finish 非零直接觸發外層 crash。
3. 重新讀 state。
4. 通知中分開列出：

   - reconcile 缺 evidence。
   - station unavailable needs-review。
   - not-scheduled。
   - missing IDs。

5. finish 本身失敗時只加入 `$bad`／`Write-Run`，仍釋放鎖並完成輪次收尾。

## `s2_render.warn_unreconciled()`

保留舊資料相容性：

- 沒有 `_schema` 的歷史 log：仍以 RT/AP/NS 三站判斷。
- 新的 `s2-reconcile/v1`：以五站判斷。
- `needs-review` 顯示「已留痕、待人工」，不可顯示成「完全沒做」。
- `not-scheduled` 不告警。
- `missing-evidence` 才顯示缺站。
- 絕對不要加入 `sys.exit()`；render 的 reconciliation warning 仍不能卡死無人值守輪次。

## 必測案例

- RT/AP/NS 三站快照正常，ENEX/ABC 明確 not-scheduled：完成且 exit 0。
- 五站都有 evidence 且數量一致：五站 status 全為 ok。
- ENEX/ABC count mismatch：formal log 寫入 needs-review，candidate `--apply` 行為正確。
- RT/AP/NS 任一站明確 unavailable：寫入 `STATION_UNAVAILABLE`，finish 不阻塞。
- 找不到快照但沒有 unavailable 宣告：寫 `missing-evidence` 並 exit 1。
- 不可把上一輪快照當本輪 evidence。
- 同一 checkpoint finish 連跑兩次：log 不重複、不遺失其他站。
- 舊三站 log 仍能被 render 正確處理。
- `warn_unreconciled()` 對所有缺站／needs-review 情況都不 `sys.exit()`。
- `s2_scan.ps1` finish 非零時仍完成 DONE、通知、解鎖。

# 第四階段：項目5——R32 純結構性 FMT 單筆 strict gate

## 修改檔案

| 檔案 | 位置／函式 | 工作 |
|---|---|---|
| `scripts/s2_batch_prep.py` | `HARD_GATE_REASONS` 後 | 新增單筆 strict 白名單 |
| `scripts/s2_batch_prep.py` | `collect_build_lint_reasons()` 附近 | 新增單筆 reason 收集 |
| `scripts/s2_batch_prep.py` | `_enforce_build_hard_gate()` | 先執行單筆 gate，再執行既有 ≥5 gate |
| `scripts/test_s2_batch_prep.py` | 現有 hard gate 測試 | 改用 R32 名稱並新增單筆／排除測試 |

## 單筆 strict 白名單

新增：

```python
SINGLE_ENTRY_STRICT_REASONS = frozenset({
    "FMT_FIRST_NOTE_BITE",
    "FMT_MISSING_FOOTAGE_SEG",
    "FMT_BITE_TAG_WITHOUT_SEG",
    "FMT_BITE_SEG_WITHOUT_TAG",
    "FMT_BITE_CONFLICT",
    "FMT_NO_ENDING",
    "FMT_TRAILING_CONTENT",
    "FMT_MISSING_SUMMARY_DELIM",
    "FMT_SECOND_PAREN_NOT_BITE",
    "FMT_CONTAINS_GMT",
})
```

這些屬於可由結構直接判定的錯誤：

- 缺固定段落。
- 括號／BITE 標記不成對。
- 結尾形狀錯。
- 摘要缺分隔符。
- 素材行出現 GMT。
- 行尾出現不允許內容。

## 明確排除

以下不得觸發單筆 strict：

```text
FMT_NOTE_FILE_USAGE
FMT_OPERATIONAL_NOTE
FMT_BITE_NO_SPEAKER
FMT_WRAP_WITHOUT_NOTE
FMT_PKG_DONUT_NEED_SOT
```

原因是它們含有詞彙政策、內容判斷、講者判斷或素材形式語意。

這些 reason：

- 維持現有同 reason `>=5` 的 aggregate hard gate，或維持 warning。
- 尤其 `FMT_PKG_DONUT_NEED_SOT` 單筆不得擋，避免把正常素材形式判斷錯誤當成格式錯誤。

`HARD_GATE_REASONS` 不要刪除這些項目，否則會改變既有批次門檻。

## `_enforce_build_hard_gate()` 行為

執行順序：

1. 將 warning 分類成穩定 reason code。
2. 若單筆 strict reason 出現，立即 `exit 2`。
3. 否則才執行原本同站同 reason `>=5` gate。
4. skeleton、normal、`--dry-run` 三條路徑都共用。

訊息格式：

```text
⛔ 【R32 單筆格式硬閘】RT 站有素材未通過結構格式檢查，batch 尚未寫入。
  • ID：RT9001
  • reason：FMT_BITE_TAG_WITHOUT_SEG（有 (BITE) 但缺 ▎BITE： 段）
  • 修復：回到 entries.json 修正該筆 entry。
  • 下一步：重新整批 Write，重跑 build --dry-run，確認該 reason code 為 0。
  • 不要逐筆 Edit／patch-entry 修補後再繞過 build。
```

離開碼：`2`。

## 必測案例

- 正常一筆格式：exit 0、batch 正常寫出。
- 單筆 `FMT_MISSING_FOOTAGE_SEG`：exit 2、batch 不存在／原檔不變。
- 單筆缺 BITE 括號：exit 2。
- 單筆 `FMT_CONTAINS_GMT`：exit 2。
- 單筆 `FMT_PKG_DONUT_NEED_SOT`：不得因單筆而擋。
- 單筆 `FMT_BITE_NO_SPEAKER`：不得因單筆而擋。
- 被排除的語意型 reason 達 5 筆：仍走既有 aggregate gate。
- `SEM_BITE_UNTRANSLATED`、摘要長度、BITE 翻譯品質等 warning 不得因單筆而擋。
- normal、skeleton、`--dry-run` 三種 build 都覆蓋。
- `parse_draft_entry()` raw_entry fallback 及衝突 exit 2 測試保持通過。

# 實作時的高風險點

1. `add-batch` 必須在 `new_topics` 登記前完成 preflight，否則 gate 失敗仍可能污染 registry。
2. 缺 `src_text` 必須是寫入前拒絕，不可先 `new_item()` 再 warning。
3. `--allow-missing-src-text` 只能放行缺漏，不能放行 agent 說明污染。
4. `needs-review` 的 `source: "?"` 是合法備忘殼，不能被真素材 source whitelist 誤擋。
5. 不可把 ENEX/ABC 的既有 lint escape flags 移除或改語意。
6. reconcile 缺快照不可自動當成 station unavailable；必須區分 `missing-evidence` 與明確 `needs-review`。
7. ENEX/ABC count mismatch 要留正式 `reconcile_log`，不能只寫 candidate `needs_review`。
8. 固定輪未執行 ENEX/ABC 時，要寫 `not-scheduled`，不能把它們當作漏做。
9. 歷史三站 reconcile log 要能相容讀取，否則舊檔會全面誤報。
10. 項目5最容易誤擋正常稿件：`FMT_PKG_DONUT_NEED_SOT` 等語意型 reason 絕對不能納入單筆 strict。
11. `compare` 只回傳報告而不傳遞 exit code，仍等於資訊性 warning；必須同時修正 command return、`main()` 傳遞，以及 `build` 寫檔前 gate。
12. 不可用上一輪最新 snapshot 充當本輪 evidence，否則 reconcile 會產生假陽性。
