### 4.2 擬議欄位與型別

以下都是新增中繼資料契約；不修改 state 根 `schema_version`，版本只放在 platform，避免不必要的全檔遷移。現行外電庫會拒絕不支援的根 schema 版本。[s2_warehouse.py，第465–469行](../../scripts/s2_warehouse.py#L465)

| platform 欄位 | 型別／缺值 | 擬議規則 |
|---|---|---|
| `meta_schema_version` | 整數；新產生值為1 | 無此欄仍是合法舊資料；未知新版不得使 S2 整輪拒收 |
| `site` | 字串 | NS／AP／RT／ENEX／ABC；既有 ENEX／ABC 值維持 |
| `source_ids` | 物件陣列，可空 | 每筆 `namespace:string,value:string,status:string,raw_field:string`；status 為候選或已確認。另可帶 `version:string|null`；opaque ID 不改大小寫 |
| `guid` | 字串或 null | RT 真實完整來源 GUID，保留版本；供既有 A16 下游讀取 |
| `source_item_id` | 字串或 null | AP 請求／回應 itemid；未知永久性標候選，不代替 state.id |
| `bitcentralFusionId`、`source_record_id` | 字串或 null | 分別保留 NS UUID 候選、ENEX 來源 `_id` 候選；各有 namespace 與來源證據 |
| `newslinkId`、`detailId`、`storyNumber` | 既有型別維持 | 不把舊數字／字串強制轉型；`source_ids[].value` 則統一轉無損字串，保留原欄位值供核對 |
| `published_at_utc`、`transmitted_at_utc`、`updated_at_utc`、`created_at_utc`、`arrived_at_utc` | RFC 3339 UTC 字串或 null | 分別映到外電庫 `source_*_at_utc`；只有語義與時區有依據才填，永不塞入 shotlist 日期 |
| `source_created_date` | `YYYY-MM-DD` 字串或 null | RT GUID 內建立日；精度為日期，不製造午夜 UTC |
| `raw_times` | 物件 | 白名單來源時間原值，值可為字串／數字／null；不包含憑證或完整回應 |
| `time_evidence` | 物件陣列 | 每筆 `raw_field,raw_value,semantic,source_timezone,timezone_basis,precision,at_utc,date_value,quality,extractor_version`；未知值留 null，品質與衝突分開 |
| `meta_provenance` | 物件 | `generated_by,extractor_version,raw_sha256,raw_row_key,receipt_ref,run_id,checkpoint`；收據／run 未提供可為 null，不造 fetched_at |
| `meta_missing_reason` | 物件陣列，可空 | 每筆 `field,code,detail`；detail 用繁中，容許部分欄位缺失 |
| `meta_issues` | 物件陣列，可空 | 時間衝突、身份不一致、候選永久性、推定時區等問題，不混入正文或現有 needs_review |

### 4.3 時區、來源與身份政策

1. ISO 值帶 Z／offset 直接轉 UTC，保留原值及精度；epoch 必須明確單位為毫秒，不用值的大小猜秒／毫秒。ABC Available 無 offset 依已確認 `Asia/Taipei` 契約解析。若實際標示 ET，使用 `America/New_York` 處理夏令時間，不能固定加12／13小時。[外電庫計畫，第126行](2026-10-02-外電資料庫與跨日檢索架構計畫書.md#L126)
2. 日期精度留曆日；主 shotlist 日期仍由既有下游日期解析器決定，本保存器不重作日期分類。無 offset 未驗值、RT at 語義未知、ABC Complete 未驗契約，正規化欄為 null，保留證據與問題。[外電庫計畫，第106、119、126–128行](2026-10-02-外電資料庫與跨日檢索架構計畫書.md#L106)
3. `source_ids` 是來源鍵證據，不立即建立全庫 material_id。RT guid 可供已確認模板產 permalink；AP／NS／ENEX／ABC 永久性未驗的鍵標候選。版次是否應併為同素材另裁，不能自行剝 RT 尾碼。[外電庫計畫，第132–148、273–279行](2026-10-02-外電資料庫與跨日檢索架構計畫書.md#L132)
4. meta_provenance 的 raw hash 由固定程式對實際輸入計算，清單／detail 可分別引用；同輪每檔只計算一次。雜湊與 generated_by 不構成不可偽造授權，仍保留 E9 的同帳號任意 shell 可繞過風險。[外電庫計畫，第403–405行](2026-10-02-外電資料庫與跨日檢索架構計畫書.md#L403)

## 6. 成本與不變式

### 6.1 每輪增量估算

- **瀏覽器／API：新增0次。** RT／AP detail 只保留原請求鍵；NS／ENEX 只加同回應投影；ABC 使用既有 CSV。來源契約驗證放在離線工程階段，不能在無人輪逐則補查。
- **工具／LLM：新增0次固定呼叫、0個決策欄。** 擷取、from-raw、build、extract、merge 都在原呼叫內完成；預設提示表／stdout 不印 platform 明細，缺值只寫中繼資料。預估固定命令參數／一次性規則增量為少量字元，LLM token 增量應接近零，不能保證數學上的0。若 raw 白名單結果仍貼回 context，會增加 token；須沿現有 filename 落檔與卸載規範，並實測輸出大小。[13c2，第424–450行](../13c2-S2-執行版-下-狀態檔與指令.md#L424)
- **本機：** 預估每 item 增加約0.5–2 KB JSON，200筆約0.1–0.4 MB；為規劃預算，尚未量測。每檔一次 hash、每筆常數欄位解析；AP 建索引後線性匹配，不逐筆重讀清單。目標小於1秒本機增量，若超過則記錄量體／原始大小再評估，不以此作無人輪硬閘。
- 保持原一站一次 add-batch，不新增 turn 或每筆 meta 查驗。呼叫數是現行成本主因，機械步驟原本應在同一次工具呼叫完成。[13c2，第118–124行](../13c2-S2-執行版-下-狀態檔與指令.md#L118)；[13c3，第164–169行](../13c3-S2-執行版-下-收工與防卡.md#L164)

1. **txt 位元組完全一致：** 固定同一 raw、同一人工決策、同一窗口／年月日、同一 formatter／編碼，舊版與新版 render 輸出 SHA-256、長度、原始位元組皆相同；不能只比 normalized 文字或素材行。`render_item` 只投影正文／標記，`render` 仍用原欄位組檔頭。[s2_render.py，第216–241、408–424行](../../scripts/s2_render.py#L216)

3. **既有稽核維持：** lint／格式驗證／ID來源驗證／新題 gate／src_text 比對／對帳照跑；基線既有告警不得增加，meta 缺值不變成正文警告或新的阻擋項。此案不調整質量判準。[13c2，第223–255行](../13c2-S2-執行版-下-狀態檔與指令.md#L223)；[13c3，第21–39行](../13c3-S2-執行版-下-收工與防卡.md#L21)
4. **非阻擋：** 單筆缺 ID、缺時間、型別錯、epoch越界、未知 offset、關聯衝突、保存器例外，都只在 platform 記 `meta_missing_reason`／`meta_issues`，素材仍按原管線處理。理由碼擬用 `field_absent / payload_not_retained / timezone_unknown / semantic_unverified / identity_join_conflict / parse_error / extractor_error`；原因帶原始錯誤類型與有限長度繁中說明，不外洩憑證。純 helper 的 import／執行也要有隔離 fallback，不能只包日期解析。
5. **非阻擋的精確邊界：** 不降低原始 JSON 損壞、缺正文、ID非法等既有驗證；meta 失敗才走非阻擋。state 整檔不可寫的既有失敗仍如實回報，不能承諾在所有磁碟故障下還能保存理由。理由優先併入同一次既有 state save，不另起日誌 writer。

重播時若舊 slim 已丟掉 GUID／時間，只能從同輪已封存清單或請求收據由固定工具重建，並保留原檔與派生檔的關聯；不能手填、猜值或連網重抓。沒有足夠證據的欄位只測缺值路徑，新欄位成功保存的正向驗收留給受控真實輪，不把舊缺欄樣本當成已證明保存成功。

renderer 使用顯式 `--file`、`--base-date 0930`、`--date 2026-09-30`、隔離 `--out`、`--no-touch-state`；原權威txt只讀。首次投影驗證可在隔離測試關閉跨日自動查找，完整驗收再提供隔離前日資料跑全部檢查；不對原檔用 `--force`。現有旗標證據見 [s2_render.py，第601–616行](../../scripts/s2_render.py#L601)。舊版重渲染未必等於封存txt，兩者差異另列既有漂移；本案硬要求的是相同輸入的新舊版位元組一致。

### 7.3 影子與小量真實輪

### 7.4 擬議回復開關

新增 **`S2_SOURCE_META=off|on`**（目前不存在）：初期預設off；on才在Python機械投影附加新meta，所有站同一版本保存器讀取。off不新產生／刷新擴充欄，也不刪已保存metadata；既有 platform.duration／detailId等照常。回復時只關閉此增量，renderer／writer／排程維持原版本；新raw多的白名單鍵可被舊工具忽略，不必回寫歷史state。

若驗收發現正文／HTML差異、額外呼叫、身份錯配或錯誤UTC，停止該站增量並保留失敗fixture；不以reset／覆寫舊snapshot回復。首階段不需根schema遷移，因此舊reader仍可讀。若第二階段另改update，開關必須同時關閉meta更新分支，確保舊文字更新行為不變。
