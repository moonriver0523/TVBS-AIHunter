## 五、手機推播失敗

**不是我造成的。** `s2_notify.ps1` 最後修改是 2026-08-10,今天沒動過。

實測(在掃帶流程外獨立重現):

| 測試 | 結果 |
|---|---|
| DNS 解析 ntfy.sh | ✅ 159.203.148.75 |
| TCP 443 連線 | ✅ 通 |
| `curl https://ntfy.sh/` | ✅ 200,4.4 秒 |
| PowerShell `Invoke-RestMethod` | ❌ 逾時 20 秒 |
| 原生 `HttpClient` 走主機名稱 | ❌ 逾時 20 秒 |

| `Invoke-RestMethod` 打 api.github.com(對照) | ✅ 209 毫秒 |

**根因:.NET 走主機名稱連 ntfy.sh 會卡死,走 IP 就正常;curl 完全沒問題。**
是這台機器的 .NET 名稱解析路徑問題,與掃帶程式無關。

已用 curl 實測送出一則推播:**HTTP 200,906 毫秒**——通道本身是好的。

**修法**:把 `Send-Ntfy` 從 `Invoke-RestMethod` 換成 `curl.exe`(Windows 內建)。
改動約 5 行,可立即測試驗證。
