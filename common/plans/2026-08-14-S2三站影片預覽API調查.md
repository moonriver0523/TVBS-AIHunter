# S2 三站影片預覽／下載 API 調查

- 日期：2026-08-14
- 性質：**調查報告，不是規則、不是授權實作**
- 範圍：AP Newsroom／Reuters Connect／CNN Newsource 的**預覽圖、預覽片、成片下載** API
- 不包含：改 S2 掃帶流程、自動下載成片、獨立 collector
- 相關：[`2026-08-14-S2三站API與省Token建議計畫.md`](2026-08-14-S2三站API與省Token建議計畫.md)（清單／稿件 API）；照片預覽見 [`2026-08-10-AP照片-API抓圖可行性計畫.md`](2026-08-10-AP照片-API抓圖可行性計畫.md)
- 實測環境：Playwright 持久 profile、三站已登入；**沒有對任何成片做 `tick`／Signiant Download**

> 本檔不寫 token、cookie、簽章 query。預覽 URL 只記 host＋路徑形狀。

---

## 一、先講結論

**三站都能用 API 找到「預覽」；能當掃帶「先看畫面」用的，只有預覽圖＋官方預覽片通道。成片下載是另一條、會計費或走傳輸客戶端。**

| 站 | 海報／預覽圖 | 預覽影片 | 成片 | 清單就有 URL？ |
|---|---|---|---|---|
| **AP** | 可以，最乾淨 | 可以（508p 浮水印） | `downloadnr/tick` 才扣點 | 清單有 rendition 中繼；真 MP4 要再換簽章 URL |
| **NS** | 有 JPG URL | 有 MP4 URL | 頁上 Download／Signiant | **清單就有** `thumbnailUrl`／`videoPreviewUrl` |
| **RT** | 有圖（CDN preview／`image-url`） | 有 `/api/preview/video`（再轉簽章 CDN） | `/api/download/video` 或 `/rendition` | 清單 transit 裡有 CDN 圖；影片預覽在**單則** `preview-url` |

共通禁忌：

1. **不要把清單裡的 S3／CDN 裸鏈當「一定抓得到」。** AP 是 `http://` mixed-content；NS／RT 預覽 CDN 頁內 `fetch` 常 CORS。
2. **不要用成片通道當預覽。** AP `rel=Main`、RT `/api/download/…`、NS Download 鈕。
3. **不要做獨立 collector。** AP 要 cookie＋正確 TopicId；NS token 不准出頁面；RT hash 會變（0803=`klwn20`，今日=`-eak9bv`）。

## 二、AP Newsroom

### 2.1 清單還是那支，topic 頁不會比較快

`https://newsroom.ap.org/topic?id=116e9ab7aa044476925398d731289267&mediaType=video&…`  
就是 All Latest 的 Video 分頁。頁面打的仍是：

```
POST https://api.newsroom.ap.org/v1/nrsearch/search/topic
PageSize: 16
TopicId: 116e9ab7aa044476925398d731289267
MediaTypes: ["video"]
```

與 `/home` 點 Latest、與掃帶 `evaluate` 範本 **同一支、同一個 body**。  
開這個 URL 再捲動，Network 會連打幾十次 `search/topic`。  
API 一次（今日實測）：約 **2.7 秒、16 則**。當掃帶入口只會更慢。

`TotalRows`≈10.8 萬是**全庫總數**，不是一次撈到的筆數。  
`PageNumber=2`＋`PageSize=16` 有時會怪吐約 100 則（0100 的 116 則就是這樣加總），**不是**合法 bulk API，也**不能**因此把 `PageSize` 調大（會靜默換排序抓舊稿）。

### 2.2 清單就有的 rendition（尚未換可播 URL）

每則 `_source.renditions[]`（清單、詳情都有，約 8 筆）：

| rel | title（實測） | 用途 |
|-----|----------------|------|
| `Preview` | Preview (MP4) 576／720／904 寬、約 1.5 Mbps | 預覽片中繼 |
| `Thumbnail` | Thumbnail (JPG 1920×1080) | 海報中繼 |
| `Main` | Full Resolution 1080p、10–50 Mbps | **成片，禁止當預覽** |
| `PhysicalMain` | Legacy Videotape | 成片／封存 |

`href` 形狀是 `http://docs.core.prod.s3.amazonaws.com/…`（**未簽章、http**）。https 頁面 HEAD 會 **mixed-content** 失敗。不要用這條直抓。

### 2.3 真的能播的預覽片（已通）

官方播放器走：

```
GET /v1/nrproxy/getMAPIUrl/{itemid}/preview
  ?filename={itemid}.0/signed/vid-508p-preview-overlay/preview.mp4
  &isOverlayPreview=true
```

回 JSON `{ item_id, url }`，`url` 是 `mapi.associatedpress.com` 的 **CloudFront 簽章** MP4。  
實測：約 0.86 秒換到 URL，Range 前 1KB **206 `video/mp4`**，檔頭是真 MP4（`ftyp`）。檔名含 `preview-overlay`＝**帶浮水印的 508p**。

海報圖（與照片同一條，已通、免登入）：

```
https://mapi.associatedpress.com/v2/items/{itemid}/preview/AP{friendlykey}.jpg?s=540x360
```

同一條改 `.mp4` → **400**。預覽片不走 mapi `/preview/*.mp4`。

### 2.4 計量分界（已對過 `check`，沒有 `tick`）

`POST /v1/downloadnr/check`（免費）對影片只列出 **Main／PhysicalMain 的 HD**（1080i50／1080i60／1080p，含標題帶 Screener 的 HD）。  
**沒有 `rel=Preview` 那支 508p。**  
`Term.DownloadActionTypeText=WithinAge_Download` 指的是「這則成片現在能下載」，不是預覽片。

結論：預覽走 `nrproxy`，**不在扣點目錄**；成片才 `tick`（`Role=Main`）。這次沒 tick。

## 三、CNN Newsource

### 3.1 清單就要抄頁面 body（精簡包會 400）

頁面實際 `POST /api/v3/stories` body 含 `facets`／`filters`／`language:["en","es"]`／`sort:{order,type:"relevancyDate"}`／`from`／`size`／`date`。  
13c 註解裡那種精簡 `{ scriptOnly, from, size, sort:[{createdDate}] }` 今日 **400**。  
另有 `POST /api/v3/stories/latest`（頁面輪詢用）與 `GET /api/v3/stories/{內部id}`（點 Preview 才打）。掃帶取預覽 URL **不必**逐則 GET。

Token 仍只准活在 `page.evaluate()` 裡。

### 3.2 清單就有預覽 URL（5／5 則都有）

每則頂層：

| 欄位 | 內容 |
|------|------|
| `videoPreviewUrl` | `https://fusion.proxies.newsourcecloud.com/…/{編號}_{標題}_{uuid}.mp4` |
| `thumbnailUrl` | 同一套路徑、副檔名 `.jpg` |
| `alternateIds.bitcentralId` | 素材編號（如 `SN-10TH`） |
| `alternateIds.bitcentralFusionId` | 播放器用 UUID |

實測 PKG／DONUT／LOOK LIVE／VO/SIL／SOT 皆有。  
播放器另打短路徑 `fusion…/{uuid}/3`、`/a` 等畫質檔；清單那支 `.mp4` 是完整預覽檔名。

點頁上 **Preview**（沒點 Download）後，`<video>` 的 `currentSrc` 就是 `fusion.proxies.newsourcecloud.com`。頁內 `fetch` 同一 URL → **CORS 失敗**。媒體元素播得起來。

### 3.3 計量分界

**Download** 是另一顆鈕（Signiant 傳成片）。預覽走 fusion，下載走另一條。  
沒證據預覽 MP4 會扣 NS 下載額度。這次沒點 Download。

落地預覽：不要在 `evaluate` 裡 `fetch` fusion（CORS）。用 Playwright 對已在播的 `<video>` 存檔，或瀏覽器下載通道。海報若同樣 CORS，先當「有圖可播」即可。

## 四、Reuters Connect

### 4.1 清單 vs 單則

- 清單：`POST /api/search-api?hash={當輪從頁面照抄}`  
  body 仍是 `search-scope=:my-feed`、`content-api-filters=med://vid`、`limit=60`、`sort=ts`、`cursorMark=*`。  
  **hash 今日是 `-eak9bv`，不是 0803 的 `klwn20`。** 寫死會打空。  
  回應仍是 transit。裡面看得到  
  `cdn2.agency.thomsonreuters.com/preview/…` 與 `/watermark/…`（簽章、有過期）。清單層主要是**圖**（`VIEWIMAGE:768X432` 這類），不是成片。
- 單則：`GET /api/item/{guid}?live=false`（純 JSON）。預覽影片欄位在這裡。

### 4.2 單則上跟預覽有關的欄位

| 欄位 | 實測 | 用途 |
|------|------|------|
| `preview-url` | `/api/preview/video/tag:reuters.com,…` | **官方預覽片** |
| `image-url` | `/api/preview/image/tag:reuters.com,…` | 海報圖 |
| `video-shotlist-url` | `/api/preview/video-shot-list/…` | shotlist，不是影片 |
| `screener-url` | 有的則有、有的則 `null` | 備援預覽，不可當必有 |
| `file.url` | `/api/download/video/…` 或 `/api/download/rendition/…` | **成片下載** |
| `renditions["stream:700s:16x9:mp4"]` | 有檔名、**沒有 url** | 像轉檔預覽；不能當下載鏈 |
| `renditions["stream:700"]`／`2000`／`5128`／`8256`／`1080` | url 都是 `/api/download/video/…` | 低碼到高碼**下載**，當計費 |

`stream:700s` 檔名帶 `_T_`，比較像 preview transcode，但 API 沒給 url，不要猜。

### 4.3 預覽通道怎麼走

`GET {origin}{preview-url}` 在頁內 `fetch`（含 `redirect:manual`）得到 **opaqueredirect**＝同源入口再 **302 到跨域 CDN**。  
Network 已見過：`cdn2.agency.thomsonreuters.com/preview/…`＋`Expires`／`Signature`／`Key-Pair-Id`。  
這跟 AP `nrproxy → 簽章 mapi`、NS `fusion` 同一類：**播放器預覽，不是 download API。**

頁內直抓 CDN 或 follow redirect 會 CORS／失敗。播放器自己播得起來。

### 4.4 計量分界

`/api/download/video`、`/api/download/rendition`＝下載。  
`/api/preview/video`、`/api/preview/image`、清單 CDN `/preview/`＝預覽。  
這次沒打任何 `download` 成片。`HEAD` 過一筆 download／rendition（文稿 txt）回 200、`content-length: 0`（HEAD 不可靠，不要用 HEAD 當「能下」）。

## 五、三站對照（實務怎麼用）

| 要什麼 | AP | NS | RT |
|--------|----|----|----|
| 只想認人／構圖 | mapi JPG（頁內就能抓） | `thumbnailUrl`（fetch 可能 CORS） | `image-url` → preview CDN 圖 |
| 想看動的預覽 | `nrproxy/getMAPIUrl` → 508p overlay | 清單 `videoPreviewUrl` | 單則 `preview-url` → CDN |
| 成片（不要當預覽） | `check` → `tick` Role=Main | Download／Signiant | `/api/download/video` |
| 掃帶要不要為預覽加呼叫 | 海報 0 次（組 URL）；預覽片每則 1 次 proxy | **0 次**（清單已帶） | 每則 1 次 item（稿本來就要打） |

對 S2 掃帶（現況仍以稿＋三段式為主）：

- **最低成本先看畫面**：AP 海報 JPG。NS／RT 的圖要過 CORS，收益看要不要「看圖才決定收不收」。
- **NS 預覽片最省**：URL 已在清單，不必加 API。
- **RT 預覽片順便**：`/api/item` 本來就要打，多讀一個 `preview-url` 幾乎零成本；落地仍要處理 CDN 簽章／CORS。
- **AP 預覽片**：要額外 `getMAPIUrl`；掃帶若只為分類，海報就夠。

## 六、若之後要做（未授權動工）

建議只做「配方＋落地契約」，不做 collector：

1. AP：evaluate 內 `getMAPIUrl` → 只回「成功／失敗／毫秒」，簽章 URL 不離開頁面；要落地就在同一個 evaluate 存 blob。
2. NS：`s2_batch_prep` 白名單加 `videoPreviewUrl`／`thumbnailUrl`（只記有無、host，或 scratch 自用）；13c 清單 body 改抄頁面那包，避免 400。
3. RT：slim item 加 `preview-url`／`image-url`；禁止把 `renditions.*.url`（download）當預覽。
4. 三站落地一律：預覽歸 scratch、檔名帶站＋編號＋`preview`；成片通道預設關閉。

不要做：調大 AP `PageSize`、寫死 RT hash、evaluate 把 fusion／簽章 URL `return` 進 transcript、為了預覽去點 Download／`tick`。
