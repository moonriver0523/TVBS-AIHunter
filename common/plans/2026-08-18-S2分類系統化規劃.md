## 4. P1：跨輪一致性基礎設施（裁決後第一層）

### 4a. 主題登記簿（topic charter）——讓「開名」有判準可查

現況：`list-topics` 只印**名稱＋則數**，agent 看得到「有這格」看不到「這格收什麼」，於是【日本歷史修正爭議】底下混進內閣改組。

- 狀態檔中主題結構加兩個欄位：`charter`（一句「收什麼」，開名當下由 agent 寫）＋ `aliases`（同義名，人工合併時自動記錄，如 高球→高爾夫、美斯→梅西——**港台譯名這種零共同字的重複，判過一次就永久記住**）。
- `list-topics --compact` 輸出帶 charter 一行；新素材掛既有中主題前先對 charter，對不上才開新名。
- **常駐層一般化**：A6 的 `s2_resident_topics.json` 從「烏俄兩格」擴充成通用常駐表（含 charter），建檔輪自動帶入——跨天延續的長線故事（加薩、關稅…）名稱不再每天重取。
- **跨天延續**：建檔輪把**昨天則數 ≥N 的中主題名稱＋charter** 帶進今天的參考清單（只當參考不預建空格），topic_dedupe 跨天檢查既有邏輯不動。
- 硬限制沿用：**只併不改名**——中主題名字寫下就不准動（使用者明講才例外）。
- 💰 token 帳：charter 每格 ~15 tokens、每天 40–55 格 ≈ 每輪 list-topics 多 <1k；aliases 不進每輪 prompt，只給收斂 agent 與 dedupe 用。**每輪近中性**。

### 4b. 分類判例庫——讓人工糾正只錯一次

沿用「自動寫稿持續校稿機制」的成熟模式（使用者已熟悉）：

- **輸入**：三種糾正來源自動落檔——①使用者口令改分類（13c §2a 表）②收斂 agent 的 MOVE 被套用 ③audit ④ 命中後的人工修正。每筆記 `{素材摘要一句, 錯放, 正解, 日期}`。
- **分級**：NEW（首見）→ REPEATED（同型再犯）→ CONFIRMED（三次同型，**晉升進決策卡的例外表**）→ RETIRED（規則改版後失效）。
- **套用**：⛔ 不是整庫塞 prompt——只有 CONFIRMED 級精選進 13 的決策卡例外表，**上限 ~20 列**（現行歸位通則表就是它的雛形，只是從沒有晉升機制）。REPEATED 以下只給收斂 agent 讀。
- 💰 每輪 prompt 增量被上限鎖死；判例落檔由既有寫入路徑順手記，不加呼叫。

### 4c. 新素材入庫前的內容比對——解決「同一事件散落他處」（2026-08-18 使用者補案）

**症狀**：新到素材明明是既有中/小分題已在講的同一事件，卻沒併進去，另開了一個新小題，散落他處。

**根因分層**（跟「開新中主題判斷不一致」是同一個家族，但更前一步）：

1. **看不到內容，只看得到名稱**——`list-topics` 現況只印名稱＋則數。中主題名字短還能靠字面／charter 猜個大概，**小分題是自然語句、字面相似度已實測對它無效**（白海豚案），agent 純靠當下記憶判斷「這跟前面那則是不是同一事件」，跨輪（甚至跨小時）記憶必然衰減。
2. **沒有強制檢查步驟**——現行流程「開新中主題前跑 list-topics」只管中主題層，小分題層完全沒有對應的「開新前先查」動作，等於放任每則各自判斷。
3. **既有工具方向對但用途窄**——`s2_batch_prep.py dedup-check` 已經能做「兩則以上逐字/語意比對、判斷是不是同一則的不同版本」，但目前只在**收斂 agent 事後**、且**明確給定 id 清單**時才用；掃帶輪當下入庫新素材時，沒有「拿這則新素材去既有清單裡搜可能重複」的反向查詢。

**機制建議**（P1 落地，D-e2 定案後生效）：

- 擴充 `s2_batch_prep.py`（或 `s2_state.py`）新增一個**候選比對子指令**（暫名 `find-similar`）：輸入新素材的摘要/標題文字，在既有**當日**中/小分題（含 charter）裡做粗篩（關鍵詞／實體重疊，不是逐字），回傳 Top-N 候選 id＋所屬中/小分題，供 agent 用 `dedup-check` 精判是否真為同一事件。
  - 粗篩用既有實體（地名／人名／機構名，若素材行已含這些線索）當比對鍵，避免像小分題 LCS 那樣被「風豪雨」這種通用詞誤湊——**沿用 4a 的 charter／aliases 而非重新發明相似度算法**。
  - 找不到候選就明講「無相似項」，不是靜默略過（護欄：欄位全空要明確失敗，同一套原則）。
- **流程位置**：`add-batch`／`set-category` 之前，一站累積草稿階段（沿用 13c §2 ①b「稽核前置」的順序，不加新的呼叫時機，插進既有的「送出前檢查」那一步）。
- **失敗模式要對稱處理**：找到候選但其實不是同一事件（誤判會合併不相干素材）與沒找到候選但其實是同一事件（漏判會繼續散落）——`dedup-check` 現有的「機械只回答比對結果、要不要合併是編輯判斷」原則照用，不自動合併，只降低「沒被想起來檢查」這個成本。
- 💰 token 帳：粗篩是機械比對（腳本內，不經 LLM）；只有精判（`dedup-check`）才耗 token，且只在有候選時才觸發，比現在「靠記憶判斷、判錯了事後靠收斂 agent 補救」便宜。

⚠️ 這條**不等於**取代 P2 的小分題接連機制（D-f）——4c 是**入庫當下**防止散落（治本、防呆），D-f／收斂輪是**事後**發現已散落的補救（治標、兜底）。兩層都要，防呆優先於補救。

## 6. 與標籤化提案的關係（岔路正面交代）

使用者已裁示：標籤採**封閉／開放字典分治**、**HTML 升格為權威、TXT 逐步退場只當備份**。本規劃與它的關係：

- **本規劃＝過渡期方案，標籤化＝終局**。兩者不衝突，且多數投資帶得過去：
  - ✅ **帶得過去**：P0 的層級裁決（＝封閉字典「主題大分類組」的定義）、charter/aliases（＝開放字典的治理機制，正是標籤化最缺的「新造標籤給人看」那條）、判例庫（維度無關）。
  - ❌ **帶不過去**：TXT 線性排序的工程（小分題接連、中主題靠攏）——HTML facet 篩選後排序問題消失。
- **因此痛點②只做最便宜的版本**（D-f 建議 A 案：收斂 agent 順路提示，零新輪次零演算法），⛔ 不再往 txt 排序演算法投資（C 案的「地區｜事件」前綴實質是結構化標籤，留給標籤化一起做）。這個取捨明列於此，由使用者在 D-f 拍板。

## 6b. T/C 標籤矩陣併入本規劃（2026-08-21 使用者補案）

**背景**：使用者提案把大分類拆成兩組正交標籤——**T 組**（議題：戰爭／天災天氣／政治／社會／財經／科技／娛樂／話題…）與 **C 組**（國家/地緣：台灣／中國大陸／美國／日本／南韓／歐盟…），任一小分題可複選兩組（同一題可跨國家、跨議題），但**每組至少要有一個 tag**。網頁篩選改矩陣（T×C）呈現，跟既有篩選機制整合。經討論，**T/C 不是獨立於 A10 的新工程，應併入 P0/P1 一起裁決與實作**，理由與細節如下。

### 6b-1 與 D-a 的關係（不重新發明）

現行 `s2_state.py` item schema 只有 `category`（大分類/中主題），**沒有結構化的地點/國家欄位**。但 D-a 裁決題本身已規劃把大分類拆成「**題材格**」＋「**地緣格**」兩級制——這正好就是 T/C 的雛形：**題材格＝T，地緣格＝C**。D-a 一次裁決兩用，不必另立標籤工程跟大分類模型打架成兩套並行的權威來源。

### 6b-2 固定模板 + 機動擴充（2026-08-21 使用者補案）

- **C 組**：國家/地緣清單**近乎永久固定**，走封閉字典。起手模板（沿用歷史大分類慣例，P0 §3a 歷史語料分析時一併驗證覆蓋率）：台灣／中國大陸／美國／日本／南韓／歐盟／中東／烏俄／東南亞／其他地區／國際（跨國無單一主體，如氣候峰會、WHO 決議）。
- **T 組**：核心議題清單**基本固定**（同上封閉字典起手：戰爭／天災天氣／政治／社會／財經／科技／娛樂／話題），**但額外開放機動 TAG**——根據當下重大議題臨場新增（例：「XX地震」「XX爭議」），**與既有 T 組固定 TAG 相容並存、不互斥**（例：地震事件同時掛「XX地震」機動TAG ＋「天災天氣」固定TAG，兩個都是 T 組成員，複選）。
  - 機動 TAG 治理比照 A6 常駐主題／4a charter 機制：**開 TAG 當下由 agent 寫一句 charter**（收什麼），登記進狀態檔一個機動 TAG 表；**只併不改名**（跟中主題同一鐵律）；事件冷卻後（比照常駐主題的降級邏輯，或人工下令）標記 RETIRED，不刪除歷史小分題上已掛的 tag，只是不再收新素材。
  - 機動 TAG 不進封閉字典，**避免污染 T 組固定清單**——固定清單只有 P0 歷史分析或使用者明示才能新增/調整，機動 TAG 隨時可開、隨事件冷卻可收，兩者治理層級不同。

### 6b-3 判定粒度與一致性機制

- 只在**小分題**層判定 T/C（自然語句的最小敘事單元，最適合當標籤錨點）；**中分題**的 T/C 由子項聯集自動彙整（規則式，不用 agent 二次判斷，避免跟小分題結果打架）；**素材**不單獨判定，繼承所屬小分題。
- 比照 4a charter／4b 判例庫模式：小分題狀態加 `T_tags`/`C_tags` 欄位＋**append-only** 的 `tag_history`（每次因新素材併入而調整，新增一筆 `{加了什麼tag, 何時, 哪則素材觸發}`，不覆寫舊值）——這解決「前一輪判的 T/C，下一輪新素材併入後可能要調整」：**不必每輪對全部小分題重判**（成本太高），只在**該小分題有新素材併入時**觸發增量判斷「這則有沒有把 T/C 範圍撐大」，順路掛在既有收斂輪（P2 `s2_reclass_prompt`）或入庫流程，不加新輪次。

### 6b-4 反向引導入庫比對（跟 4c find-similar 協同）

T/C 一旦結構化，可以當 4c `find-similar` 機制的**第一層硬性過濾**：新素材先判 C（地緣格線索通常比議題格明確、好判），只在**同 C** 的既有小分題裡做 `find-similar`/`dedup-check` 粗篩，候選集合先砍一輪，比全庫比對省 token、也降低通用詞誤湊的誤判率（規劃書 §4c 提到的「風豪雨」類問題）。**C 軸判斷通常比 T 軸穩定**，建議 C 軸粗篩可以先上線試水溫，T 軸等 D-a 固定清單定案、機動 TAG 治理跑過幾輪觀察期後再接上。

## 7. 不變式清單（既有結論，後續 agent 不得推翻重試）

1. 中主題**只併不改名**（改名比重複更糟——編輯會找不到）。
2. 小分題**不用字面相似度**做自動靠攏（白海豚案已實測否決；LCS 對自然語句失效）。
3. `s2_topic_dedupe` **不加回內文模糊比對**（0803 實測假警報蓋過訊號）。
4. 收斂 agent **不寫狀態檔**（無鎖，lost update；只產建議檔由掃帶輪套用）。
5. 22:00／23:00 重輪**不加新工作**。
6. 機動格由使用者當天決定，agent 不自行開。
7. 烏俄兩格固定名稱照 A6 常駐機制，不臨場另取。
8. 任何小分題機制不得改變側錄則數合併結果。
9. 每個新機制附 token 帳；每輪 prompt 增量須近中性，量大的內容給收斂 agent 讀不給掃帶輪讀。
