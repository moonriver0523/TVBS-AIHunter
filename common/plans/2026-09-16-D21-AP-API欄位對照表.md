## 已查證、確定不建議補回的欄位

| 欄位 | 原因 |
|---|---|
| `filings` | 肥大且高度重複，600個story ID跨item不共用，對去重無幫助 |
| `firstcreator` | 只是`firstcreated`的拆欄物件，無額外資訊 |
| `friendlykey` | 內部識別碼，已有`itemid`/`editorialid`，無篩選價值 |
| `itemstartdatetime` | 600/600與`firstcreated`完全相同，無獨立價值 |
| `language` | 600/600都是`en`，對現行TopicId無辨識力 |
| `recordsequencenumber` | 分布0:511/1:82/2:7，疑似修訂序號但單一快照無法可靠判斷 |
| `transmissionsources` | 600筆僅三種固定組合，現行query已排除`restoredfromarchive`，保留幫助有限 |

## 關鍵結論（供D21後續實作參考）

1. **`comp`（`compositiontype`）在這個TopicId下100%常數`StandardLibraryVideo`，完全不能用來判斷「即時新聞 vs 花絮/圖庫批次」。**
2. **真正的判準是`function`**：`BroadcastVideo`（對應`signals`含`NewsroomReady`）＝廣電新聞素材，適合當D21 anchor；`OnlineVideo`（對應`ConsumerReady`）＝合作夥伴/UGC批次，不適合當anchor，但**不代表無新聞價值**，不應變成下游「一律不收」的判斷依據。
3. **`ts`舊版誤用`firstcreated`（內容建立時間）**，應改用`arrivaldatetime`（真正到站/排序時間）；`APttc003012`實測落差528小時就是舊版誤判的直接證據。
4. **媒體類型過濾（`MediaTypes:['video']`）已證實有效**，清單裡看到的「照片」其實是每則影片項目`renditions`裡正常附帶的JPG封面縮圖（`rel=Thumbnail`），不是清單混入非影片內容。
5. D21 `s2_ap_coverage.py`的`check-overlap`現行「全體嚴格遞增」判準太嚴，建議改「最長遞增子序列(LIS)命中數≥min_hits」（詳見 MASTER D21列）。
