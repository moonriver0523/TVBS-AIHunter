# AP 照片改走 API：可行性調查與導入計畫

> **狀態**：✅ **Phase 0 實測完成（2026-08-10 14:5x）**，搜尋／取圖／`check` 路徑已實測驗證。
> ⚠️ **`tick` 之後的下載寫法未驗證**（只觀察、未自打），連同另 3 個殘留未知見 §八——**實作前先讀 §八**。
>
> **範圍**：只處理 [`common/06-auto-script-sot.md`](../06-auto-script-sot.md) §10「完稿後自補三張 AP 照片」
> 與 [`ap/02-photo-search.md`](../../ap/02-photo-search.md) 的**執行層**。
> **不改產出契約**（檔名、路徑、三張不同人物／場景、無事件照片就回報、MeterExpired 立停）。

---

## 一、結論（先講）

**可行，而且比預期好很多。** 三站 API 化裡最乾淨的一案：

| 關鍵發現 | 影響 |
|---|---|
| **Preview 圖裸抓即可，不需要任何認證、不扣計量** | 「先看圖再挑」完全免費，這是整案的地基 |
| **`/downloadnr/check` 是免費的前置查詢，一次可批次問 N 張** | 下載前就知道會不會被擋，`MeterExpired`／`content older than allowed` **可以預先攔掉**，不必用「點下去試試看」來探路 |
| **`/downloadnr/tick` 才是真正計量的那一步** | 計量點被精確定位，兩段式設計成立 |
| **`PageSize` 地雷不適用**（與影片端點相反） | 一次要幾張就給幾張，不必分批 |

一輪完整流程 **≈ 4 次工具呼叫**（搜尋 → 抓 N 張 preview → check ＋ tick → 落地），
取代現行「讀列表文字 → 逐張點 ⬇ → 查 Downloads → 改名」。

**最大的品質改善不是省 token，是挑片方式**：現行流程 agent **從來沒真的看過那張照片**，
只讀 caption 文字判斷，但 `06` §10 卻要求「三張要挑不同人物或不同場景」——這條目前根本無從判起。

> 📌 **0810 實測第一張就撞到這個問題**：`AP26222118750061` 的 caption 寫
> 「Air Force Col. Christopher M. Robinson … salutes as **Air Force One with president Donald Trump on board**, taxis…」，
> 純讀文字會判定「川普登機畫面，可用」。但實際看圖——**畫面裡根本沒有川普**，
> 只有兩名敬禮軍官的背影和一架滑行中的飛機。**這就是純文字挑片的失效樣態。**

## 二、目前流程的痛點

現行 `06` §10／`ap/02` 是**純瀏覽器點擊流**：搜尋 → 讀列表卡片文字 → 逐張點 ⬇ →
去 `D:\Downloads` 確認 `AP{ID}.jpg` → 改名 → 搬資料夾。

- **挑片是「讀文字」不是「看圖」**（見上方實例）
- **點擊流不穩**：`ap/02` 已記錄兩種已知失敗（點擊沒反應要去查 network log、媒體分頁會自己跳回 Video）
- **用「點下去試試看」來探測授權**：`MeterExpired_Shutdown` 與「content older than allowed」
  現在都是**下載失敗後**才知道。`check` 端點讓這變成事前可知
- **改名是額外一步**：下載檔名固定 `AP{ID}.jpg`，要再對照哪個 ID 是哪張圖

## 三、目標流程（使用者已拍板）

```
① POST /v1/nrsearch/search           …… 1 次呼叫，取 N≥6 筆（含 caption／攝影師／itemid／friendlykey）
② 裸抓 N 張 preview（免認證、免計量）  …… Read 逐張看圖，判相關性／主體／構圖／場景是否重複
③ POST /v1/downloadnr/check          …… 對挑中的 3 張批次前置查詢（免計量），確認可下載
④ POST /v1/downloadnr/tick           …… 唯一計量點，取回簽章 URL → 直接用最終檔名落地
⑤ 搬進 SOT自動寫稿測試\{SLUG}\
```

> ✅ **2026-08-10 使用者已拍板採用兩段式**（「你的建議很好，照你建議做」）。
>
> **為什麼是兩段式**：`ap/02` 記錄的兩種下載失敗都跟額度／授權有關，代表照片下載是計量的。
> 實測已證實計量點就在 `tick`。用免費的 preview 判讀、只對選中的 3 張 tick，
> **完整保留「先看圖再挑」的意圖，計量成本卻跟現在完全一樣（3 張）**。
>
> ⚠️ **退場條件已解除**：原訂「若 preview 解析度低到判不出構圖就退回抓 6 張全解析度」——
> 實測 540px／1024px 都足以判讀（見 0-6），**退場條件不成立，兩段式定案**。

## 四、不動的產出契約（API 版是 drop-in 替換）

以下全部沿用 `06` §10／`ap/02`，實作時不准簡化：

- 檔名 `{簡短圖說}（圖／達志影像美聯社）.jpg`（**不是** `{SLUG} #XX {來源}` 那套）
- 落地 `G:\我的雲端硬碟\Claude共用\SOT自動寫稿測試\{SLUG}\`
- 三張要**不同人物或不同場景**
- 找不到事件本身的照片 → 回報「無事件照片」，**不湊數**
- `MeterExpired_Shutdown` → **立即停止**，回報帳號授權問題，不換關鍵字重試
- 關鍵字**要短**（1–2 字），0 結果才逐步拆解
- 對話只回檔名 + 一句圖說 + 有無限制，不貼 Photo Metadata 全文

**API 版改善兩處**：① 直接用最終檔名落地，省掉改名步驟；
② 授權／計量問題從「事後踩到」變成「事前 `check` 就知道」。

# 附錄 A：API 規格書（2026-08-10）

> **驗證程度不一致，逐節標示**：A-2／A-3／A-4／A-5① 為**實測定版**；
> **A-5②（`tick`）為 network log 觀察所得，agent 自打與落地寫法未驗證**（見 §八-3）。

## A-1 端點契約

| 用途 | 方法 | 端點 | 驗證 | 計量 |
|------|------|------|------|------|
| 關鍵字搜尋 | POST | `https://api.newsroom.ap.org/v1/nrsearch/search` | cookie（同源 `credentials:'include'`） | ❌ 免費 |
| 取 preview | GET | `https://mapi.associatedpress.com/v2/items/{itemid}/preview/AP{friendlykey}.jpg?s=1024x1024` | **完全不需要**（裸 curl 可取） | ❌ 免費 |
| 下載前置查詢 | POST | `https://api.newsroom.ap.org/v1/downloadnr/check` | cookie | ❌ 免費 |
| **實際下載** | POST | `https://api.newsroom.ap.org/v1/downloadnr/tick` | cookie | 🔴 **計量點** |
| 單張完整詳情 | POST | `https://api.newsroom.ap.org/v1/nrsearch/search/item/details` | cookie | ❌ 免費 |

- 認證＝ AP 的 `session_user` cookie（httpOnly，**7 天**，見 `13b`）。
  **沒有 token，不需要 NS 那套「token 不離開頁面 JS」的特殊寫法**，同源 `page.evaluate` fetch 即可。

## A-2 搜尋 body（照抄頁面實際發出的，只改 `Query`／`PageSize`）

```json
{"SearchType":"keyword","Date":"Anytime","IsSavedSearch":false,"IsSharedSearch":false,
 "PageNumber":1,"PageSize":50,"persons":[],"Sort":["arrivaldatetime:desc"],"ShareToken":"",
 "digitizationType":null,"language":"","Query":"Trump","MediaTypes":["photo"],
 "SemanticSearch":false,"isTopicSearch":false,"TopicId":null,"FootageType":[],"GraphicsType":[],
 "IgnoreSpellCheck":false,"ProductGroup":"","query_from_date":null,"itemId":null,
 "isSemanticItemIdSearch":false,"Semantic":null,"MyPlanSearch":false}
```

### 🎯 `PageSize` 地雷**不適用本端點**（與 `13b` §2 影片端點相反，2026-08-10 實測）

`13b` 寫「`PageSize` 一個字都不准改，只能照抄 16」——**那條是 `/search/topic` 端點的規則，不要套到這裡**。

實測 `PageSize` 50／6／24 三種，**前三筆完全一致且排序正確**：

```
PageSize=50 → 26222118750061@03:21:16, 26222106391090@02:58:39, 26222029572084@00:49:51
PageSize= 6 → （完全相同）
PageSize=24 → （完全相同）
```

**原因**：本端點的 body 裡 **`Sort` 是明寫的**（`["arrivaldatetime:desc"]`），
排序不依賴後端預設，所以改 `PageSize` 不會被靜默換掉。topic 端點沒有這個欄位，才會踩雷。

- ⚠️ **但 `PageNumber` 一樣不可靠**：`PageSize=6` ＋ `PageNumber=2` **回了 100 筆**，
  跟 topic 端點同一個病。**照片流程只需要第 1 頁，不要碰 `PageNumber`。**

## A-3 抽取白名單（實測定版）

回應是 `{Query, TotalRows, TotalPages, Page, PageSize, Items:[{_id,_source,…}]}`，
**不是** ES 原生的 `hits.hits`。

✅ **欄位存在率已實測**（`Gaza` 查詢 50 筆，逐筆檢查）：`caption` **50/50 是物件**（`.nitf` 為非空字串，
不是「內容為 JSON 的字串」）、`ratings[0].rating` 50/50、`photographer.name` 50/50、
`friendlykey` 50/50、`renditions` 含 `rel:"Main"` 且有 `code` 50/50。
`clean()` 實跑輸出正常文字（例：`Displaced Palestinian beekeepers harvest honey… (AP Photo/Jehad Alshrafi)`）。

```js
const slimPhoto = (s) => ({
  id:    'AP' + s.friendlykey,     // ⭐ 照片的編號是 friendlykey（14 碼），不是 editorialid
  itemid: s.itemid,                //   32 碼 hex，組 preview URL 與 check/tick 都要用
  title:  s.title,
  cap:    clean(s.caption && s.caption.nitf),   // 一句話圖說（HTML，含攝影師署名）
  photog: s.photographer && s.photographer.name,
  srcType:(s.sources||[]).map(x=>x.type).join('/'),   // AP／ThirdParty
  ts:     s.arrivaldatetime,       // 排序基準（不是 firstcreated）
  type:   s.compositiontype,       // StandardPrintPhoto
  stars:  (s.ratings||[])[0] && s.ratings[0].rating,  // 編輯評分 1–5，可當挑片參考
  preview:'https://mapi.associatedpress.com/v2/items/' + s.itemid +
          '/preview/AP' + s.friendlykey + '.jpg?s=1024x1024'
});
```

### ⚠️ 三個容易抄錯的地方

1. **照片的編號是 `friendlykey`，不是 `editorialid`**。`13b` §2 影片版用 `editorialid`，
   **照片的 `_source` 裡根本沒有 `editorialid` 這個欄位**。`friendlykey`（如 `26222118750061`）
   才是下載檔名 `AP{ID}.jpg` 的那串。前綴 `AP` 一樣要自己補（`13b` 的前綴踩雷同樣適用）。
2. **`renditions` 在照片這邊要保留，不是雜訊**。`13b` §2 寫「`renditions` 一律不取」——
   **那是影片的規則**。照片的 `renditions` 帶 Full／Preview／Thumbnail 三層尺寸資訊，
   是判斷畫質與組 URL 的依據。**照抄影片白名單會把它砍掉。**
   （實務上 URL 可由 `itemid`＋`friendlykey` 自組，不一定要留整個 `renditions`，
   但**理由要寫在規則裡**，避免日後有人拿影片那句話來「清乾淨」。）
3. **`binarypath` 是 `"None"`**，`renditions` 裡**沒有現成 URL**，一定要自組。

## A-4 Preview 取圖（實測：裸抓可用）

```
https://mapi.associatedpress.com/v2/items/{itemid}/preview/AP{friendlykey}.jpg?s={W}x{H}
```

- **不需要 cookie、不需要 Referer、沒有簽章參數**——本機 `Invoke-WebRequest` 直接 200。
  頁面版網址尾巴有 `&tag=app_id=1,user_id=…`，**可整段省略**。
- **`s=` 參數有效**，實測：
  | `s=` | 實得 | 檔案大小 |
  |------|------|---------|
  | `540x360` | 540×359 | 33 KB |
  | `1024x1024` | 1024×682 | 72 KB |
- ⚠️ **preview 有「Distributed by The Associated Press」浮水印**，**只能判讀、不能當成品**。
- 📐 **建議用 `s=540x360` 判讀**：33 KB、540px，實測足以判斷主體／人物／構圖，
  比 1024 省一半頻寬。需要看細節（例如分不清是不是同一個人）才個別調 1024。

## A-5 下載：`check` → `tick` 兩步

### ① `POST /v1/downloadnr/check`（免費，可批次）

```json
{"ItemIds":["{itemid}","{itemid}",...],"IsClip":false,"IsNonSalable":false}
```

回傳每張的 `Term` 物件，**下載前就知道結果**：

```json
{"Term":{"DownloadActionTypeText":"WithinAge_Download","IsSuccess":true,"ErrorMessage":null,
         "MeteredType":"None","AppliedPrice":0.0,"Age":14,
         "MaxDownloadAllowed":0,"CurrentDownloadCount":0}}
```

- 🎯 **這支就是「先測一張確認帳號能下載」那條規則的正解**——不必真的下載一張來試探，
  `check` 免費、可一次問 6 張，`IsSuccess`／`ErrorMessage`／`DownloadActionTypeText` 直接給答案。
- 已實測到的 `DownloadActionTypeText` 值：
  - `WithinAge_Download` ＝ 可下載（在訂閱允許的時間範圍內）
  - `Duplicate_Download` ＝ 這張本帳號已下載過（實測：對剛下載過的那張再 check 就變這個）
- 🔴 **推定對應關係（未實測，見 §八）**：`ap/02` 記載的
  「content is older than what you are allowed to download under your subscription」
  應該就是 `WithinAge_Download` 的反面；`MeterExpired_Shutdown` 應在 `ErrorMessage`／
  `DownloadActionTypeText` 出現。**沒有樣本可驗**——實作時**不要白名單特定字串**，
  改成「`IsSuccess !== true` 或 `DownloadActionTypeText` 不在已知可下載清單 → 當作不可下載」。

### ② `POST /v1/downloadnr/tick`（🔴 計量點）

```json
{"Ticks":[{"ItemId":"{itemid}","MediaType":"photo","Role":"Main",
           "Title":"{title}","ContentId":"{renditions[rel=Main].code}",
           "StoryNumber":null,"ContentRenditionId":2}],"StoryItemID":null}
```

- 🎯 **`ContentId` 與 `ContentRenditionId` 一律取自「`check` 回應」的 `Renditions[]` 中 `Rel:"Main"` 那筆**，
  不要硬編。上面 body 裡的 `ContentRenditionId:2`（全解析度；`1` 是 Preview）是**單一樣本觀察值**，
  `check` 回應本來就逐張帶這兩個值，照抄即可，零成本避開泛化風險。
- `Ticks` 是**陣列**，選中的 3 張可以一次送。
- 回傳 `DownloadRecorded:true`＋`OrderNumber`＋**`ClientMediaUrl`**（CloudFront 簽章 URL，
  實測有效期約 **30 分鐘**），檔名資訊在 `DownloadFileName`。
- ⚠️ 也回 `IsDuplicate`／`OverageAlert`／`CanStreamDownload`——`OverageAlert` 為 true 要當警訊回報。

### 🔒 簽章 URL 的處置（實作時遵守）

`ClientMediaUrl` 帶 `Policy`／`Signature`／`Key-Pair-Id`。它不是登入憑證，但**是一次性的付費資產取用權**。
比照 `13b` §「token 不離開頁面 JS」的精神：

- ✅ **建議做法**：`tick` 與取檔**寫在同一個 `page.evaluate()` 裡**，
  在頁面內 `fetch` 該 URL 取 blob、用 `<a download="{最終檔名}">` 觸發下載，
  簽章 URL 從頭到尾不離開瀏覽器。**順帶好處：檔名直接就是最終檔名，省掉改名步驟。**
- ⛔ **回傳值黑名單照舊**：`token`／`Bearer`／`Authorization`／完整 JWT／cookie 字串
  永遠不准出現在 `evaluate` 回傳值裡。`ClientMediaUrl` 也建議比照辦理，不要回傳到 agent 層。
- caption、編號、preview URL 是正常業務資料，照樣回傳。

## A-6 Fallback 階梯（固定順序，不准跳步、不准重試同一步）

1. API 搜尋 → preview 判讀 → `check` → `tick`
2. preview 取不到 → 退回「用 caption 文字判讀」＋ 照樣走 `check`／`tick`（**挑片品質下降，要在回報裡講**）
3. 搜尋或 `check` 整支失敗 → 完全退回 `ap/02` 現行點擊流
4. `check` 回不可下載 → **換候選**，不重試同一張
5. 疑似額度／授權到期（`IsSuccess` false 且非單張性質）→ **立刻停，不進下一階**，回報使用者

## 七、順帶發現（非本計畫範圍）

- **`sources[].type` 分 `AP`／`ThirdParty`**（150 筆樣本：AP 116／ThirdParty 34）。
  ThirdParty 代表非 AP 自攝（handout／他社供稿），**署名可能不能寫「達志影像美聯社」**。
  現行 `06` §10 的檔名後綴是寫死的 `（圖／達志影像美聯社）`——
  **ThirdParty 的照片是否該換署名，值得問使用者**（本案未處理）。
- **`ratings[0].rating`（1–5 星編輯評分）** 實測 50/50 每張都有，可以當挑片的參考訊號之一。
- **`/v1/nrsearch/search/item/details` 加 `mediaType:"photo"` 可用**，
  多出 `creditline`／`captionwriter`／`categories`／`places`／`overlines`／`copyrightnotice`。
  一般挑片用不到，需要完整署名時再打。

## 八、🔴 殘留未知（Phase 1 要補，不要當成已解決）

### 1) 限制訊息（Special Instructions／⚠️）在哪個欄位——**沒找到**

- 掃了 3 個關鍵字共 **150 筆**，`signals` **全部都是 `newscontent`**，沒有第二種值。
- `item/details` 的 54 個欄位裡，名稱含 `instruct`／`restrict`／`special`／`right`／`usage` 的
  只有 `copyrightdate` 與 `copyrightnotice`（標準版權宣告，不是限制）。
- **原因是樣本裡沒有帶 ⚠️ 的照片**，不是欄位不存在。
- **處置**：Phase 2 改規則時，**「無 ⚠️ 不開詳情頁」這條先原樣保留**。
  要拿掉它必須先找到一張真的有 Special Instructions 的照片，確認欄位名。
  ⛔ **不要因為「掃 150 筆都沒有」就宣稱照片沒有限制訊息**——`ap/02` 明確記載列表卡片有 ⚠️ 圖示。

### 2) PHOTO GALLERY 封面卡在 API 回應裡怎麼區分——**沒找到**

- `ap/02` 記載：搜尋有時只回 1 筆紅底大字的 **AP PHOTO GALLERY 標題卡**，那不是可用照片。
- 150 筆樣本的 `compositiontype` **全部都是 `StandardPrintPhoto`**，沒撞到 GALLERY 卡。
- **推測**（未驗證）：GALLERY 卡的 `compositiontype` 應該是別的值。
- **處置**：實作時**白名單** `compositiontype === 'StandardPrintPhoto'`，
  遇到其他值就當可疑、記進 `needs_review`，不要黑名單特定字串。
  **附帶好處**：即使沒驗證過 GALLERY 卡的實際值，白名單寫法也能自動擋掉它。
- `ap/02` 既有解法（改用圖輯標題全文重搜）照樣有效，不受影響。

### 3) 🔴 **`tick` 是「觀察」到的，agent 自打與頁內落地整段未驗證**

⛔ **這是實作路徑上最大的未測件，不要把 A-5 的建議做法當成已驗證。**

- 0810 唯一一次真實下載，是**點頁面的 Download 按鈕**觸發的；
  `check`／`tick` 的 body 與回應是從 network log **觀察**下來的，**不是 agent 自己打出來的**。
- 因此以下**全部未跑過**：
  - agent 在 `page.evaluate()` 裡自行 POST `tick`
  - 頁內 `fetch` 簽章 URL 取 blob
  - `<a download="{最終檔名}">` 觸發下載
  - **中文檔名**（`{簡短圖說}（圖／達志影像美聯社）.jpg`）能否正常落地 ← 最可能出問題的一項
- **為什麼現在不補測**：補測要花掉 1 張計量額度。
- **處置**：留待 **Phase 1 pilot**，用那次的 3 張計量順帶驗證，不另外花額度。

### 4) `DownloadActionTypeText` 的完整值域——只見過 2 個

只實測到 `WithinAge_Download`（可下載）與 `Duplicate_Download`（已下載過）。
`MeterExpired_Shutdown`、「older than allowed」對應什麼值**沒有樣本**。
→ 已在 A-5 訂為**白名單寫法**（不在已知可下載清單就當不可下載），不受此未知影響。
