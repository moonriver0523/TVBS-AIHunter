# ENEX 併入 S2 定時掃帶：API 直查可行性調查與導入計畫（草案）

> **狀態：計畫草案，2026-08-09 建立。本檔不修改任何既有規則**（`13`／`13b`／`05` 一字未動）。
> 目的：評估 ENEX Members Website 能否比照 AP／RT／NS 走 [`13b §1a 三站 API 直查`](../13b-S2-定時掃帶-v2省token.md) 的做法納入 S2 掃帶，並列出導入步驟與待驗項目。
> 現況基準：`13` §「來源盤點」把 ENEX 標為「暫不處理」、`05` 說 ENEX「尚無對應下載來源／流程，遇到只做編號」。本計畫若獲採納，才由使用者決定是否回頭改那兩份規則。

---

## 一、結論（先講）

**可行，而且是三站以外最乾淨的一站。** ENEX 有一支同源、cookie 驗證、接受完整 Elasticsearch DSL 的搜尋端點，**清單即文稿**——一次呼叫就能同時拿到列表與稿件全文（STORYLINE＋SHOTLIST＋引言），比 NS 更單純（NS 還要顧 1 小時 JWT），比 AP 更自由（AP 的 `PageSize` 一動就換排序）。

主要缺口只有兩個：**形式（VO／SOT／PKG 這類）與時長，ES 索引裡沒有對應欄位**；另有一個結構性難題：**ENEX 是多夥伴交換平台，各家 house format 不同，引言標記無法用單一 regex 機械偵測**（詳見 §4）。

## 二、已實測確認的事實（2026-08-09，Playwright 同源 `page.evaluate`）

| 項目 | 實測結果 |
|---|---|
| 站台架構 | Drupal 10；`/exchange/{id}` 詳情頁是 **JS 殼**，伺服器端只吐框架，內容靠前端渲染 |
| **端點** | `POST https://members.enex.news/elasticsearch/news/_search`（同源、cookie 驗證，`browser_evaluate` 內 fetch 即可） |
| 查詢自由度 | **接受原生 ES Query DSL**：`bool`／`term`／`range`／`sort`／`_source` 白名單／`track_total_hits` 全部可用 |
| 分頁／筆數 | `size:100` 實測回滿 100 筆；`sort:{sortDate:{order:'desc'}}` 正常 |
| **時間窗篩選** | `{range:{sortDate:{gte:<epoch_ms>}}}` 可用 — **這是 S2 每輪 diff 的關鍵**，AP／RT 都沒有這麼直接的窗過濾 |
| 量級 | 近 3 小時 **7 則**；索引總量 338,288 筆（含歷史） |
| 端點範圍 | **只 proxy `_search`**：`/elasticsearch/news/_mapping` 回 **400**。不要嘗試其他 ES 管理路徑 |
| 首頁 DOM | 伺服器端已渲染 `/exchange/{id}` 與 `/download/{id}` 連結 → **DOM 直撈 fallback 可行** |
| 寫法安全性 | 全程在同一個 `page.evaluate()` 內 fetch＋parse，**未觸發 exfil 攔截**（合乎 `13b §1a-3` 核可形態；ENEX 用 cookie，本來就不需要讀 token） |

### 欄位盤點（`_source` 共 33 個 key，實測 dump）

有用的：`title`／`description`／`partner`／`category`／`location`／`region`／`country`／`tags`／`publishedDate`／`sortDate`／`creationDate`／`lastModified`／`newslinkId`／`filename`／`thumb`／`videoLowRes`／`videoLowResCdn`／`published`／`editStatus`／`editorsChoice`／`status`。

**`description` 就是完整 dopesheet**（實測長度 730–2,769 字元），內含 `STORYLINE:`／`SHOTLIST:`／引言段與限制語樣板。**不必開詳情頁。**

雜訊（抽取白名單要砍）：`*Suggest` 系列（`titleSuggest`／`tagsSuggest`／`partnerSuggest`／`categorySuggest`／`countrySuggest`，內容與本欄重複）、`editStatusSort`、`ntscTranscodingStatus`、`popularDailyViewCount`／`totalViewCount`／`teletraxHitCount`、`modulation`／`channel`／`format`／`start`／`end`（衛星排程欄，一般素材為 null）。

## 三、對映 `13b` 的「不准砍」欄位

| `13b` 要求 | ENEX 來源 | 狀態 |
|---|---|---|
| 素材代碼 | `_id`（如 `926241`）→ 寫成 `ENEX926241`（見 §3a） | ✅ 待確認流水號不跨日重用（形狀是遞增，風險低） |
| 稿件全文 | `description` | ✅ |
| SHOTLIST 段 | `description` 內 | ✅ |
| SOUNDBITE 段與講者 | `description` 內 | ⚠️ 各夥伴標記不一，見 §4 |
| 來源 | `partner`（如 `CN CCTV`／`ES TELE5`／`IQ RUDAW`） | ✅ |
| 限制語 | **內嵌在 `description` 文字**（CCTV 前導授權樣板、`No access Chinese mainland` 等） | ⚠️ 非結構化，抽取時**整段保留、不砍**；樣板本身就是限制語 |
| 形式（VO／SOT／PKG） | **無對應欄位**（`category` 是題材分類，不是形式） | 🔴 開放項 |
| 時長 | **ES 無此欄**（`start`／`end` 是衛星排程欄、實測 null） | 🔴 開放項 |

## 三-a、素材編號與素材行寫法（2026-08-09 使用者訂案）

### 1) 素材編號＝`ENEX` ＋ ID 數字

- 格式：**`ENEX{_id}`**，例 `ENEX926241`、`ENEX999999`。中間無空格、無分隔符號。
- 來源就是 ES 回應的 `_id`（＝網址 `/exchange/{id}`／`/download/{id}` 的那組數字），**不是 `newslinkId`**（那是另一組內部編號，只留作查證備用）。
- 與 `05-material-numbering.md` 既有的 `ENEX` 前綴慣例一致。

### 2) 摘要的**第一個 `()` 放來源媒體**

- 三段式素材行的**第一個括號備註寫來源媒體簡稱**，例：`ENEX926241 (CBS) ▎…`。
- 🎯 **括號不另開一格，全部統整在第一個 `()` 裡，媒體固定寫最前面（2026-08-09 使用者訂案）**：其餘備註（限制語等）接在媒體後面、以空格分隔，**第二個 `()` 固定留給 `(BITE)`**。這樣就與 `13b` 其他站「第一個 `()` 是備註格」的結構一致，不是多開一格。
  ```
  ENEX926241 (CCTV 陸內不可用) ▎…
  ENEX926236 (CCTV 陸內不可用) (BITE) ▎…
  ENEX926234 (SKY 英國/EBU/CNNI/半島電視台不可用；NASA與圖卡GFX畫面不可用) ▎…
  ENEX926212 (CBS) (BITE) ▎…
  ```
- 值取自 `partner` 欄位。⚠️ **實測 `partner` 帶國別前綴**（`CN CCTV`／`ES TELE5`／`IQ RUDAW`），**要取後半段的媒體簡稱**（`CCTV`／`TELE5`／`RUDAW`），不要整串照抄。
- 🔴 **前綴切法待 Phase 0 定案**：目前看到的形狀都是「2 碼國碼＋空格＋媒體名」，但**未窮舉**——若有夥伴名稱本身含空格（如 `US CBS NEWS`），單純 `split(' ')[1]` 會切錯。Phase 0 要把 `partner` 全集撈出來（見下方查詢）再決定是切前綴、還是建一張對照表。
### 2c) ⛔ **不寫 URL 行（2026-08-09 使用者訂案）**

ENEX 素材行**不加 `▎連結：` 行**——素材代碼 `ENEX{id}` 本身就能定位（`/exchange/{id}`），交接檔不需要再列一次網址。
（與 `_待整併/0809-韓聯社CNA.txt` 那類 YouTube 素材不同：那些**沒有素材代碼**，URL 就是唯一的定位方式，所以要寫。）
📌 `exchange_url`／`download_url` 仍保留在**狀態檔**的 `enex` 欄位裡（機器用，供下載與調帶），只是不印進交接 txt。

### 2a) 記者現場原音**算 BITE**（2026-08-09 使用者訂案）

CCTV 的 `UPSOUND (語言) 姓名, reporter:`（記者站在現場講話）**照常標 `(BITE)` 並寫進 BITE 段**，不因為講者是記者而降階。

### 2b) 供稿方標明 AI 翻譯的引言：**忽略該標示，照常收 BITE，也不必加註提醒**（2026-08-09 使用者訂案）

`ES TELE5` 等夥伴會在稿內寫 `SOUNDBITES (TRANSLATED WITH AI)`，甚至殘留 AI 助理的對話語句。**這些都不影響收錄**：引言照寫、不標註、不記 `needs_review`。（AI 助理殘留語句本身仍不寫進素材行——那不是發言內容。）

### 3) ⛔ `TVBS` 的素材一律排除，不寫摘要

- **理由**：自家素材不需要摘要——ENEX 是交換平台，TVBS 自己上傳的內容也會回流到清單裡。
- **實作**：抽取階段就濾掉，**不進 `batch.json`**（比照 `13b` NS 的 `AUDIO TRACK`／`GRAPHIC` 機械排除）。
- 🔴 **實際字串待 Phase 0 確認**（推測是 `TW TVBS`，本次調查未撈到該筆）。判定用**大小寫不敏感的子字串比對**較安全：`/\bTVBS\b/i.test(partner)`，這樣 `TW TVBS`／`TVBS`／`TVBS NEWS` 都涵蓋得到。
- ⚠️ **這是本計畫唯一的「整則排除」規則**——其餘一律照收，不准以「地方性」「新聞價值低」自行降階（同 `13b` NS 0805 訂案）。

### Phase 0 對應查詢（撈 `partner` 全集，一次呼叫）

```js
const body = { size: 0, aggs: { partners: { terms: { field: 'partner', size: 200 } } } };
// ⚠️ 若 partner 是 text 型別會報錯，改用 'partner.keyword' 或 'partnerSuggest'；
//    aggs 是否被 proxy 放行也要一併驗（目前只確認過 query/sort/_source/range）。
//    aggs 不通就退而求其次：抓近 30 天清單只取 partner 欄位，自己去重。
```

### 兩個 🔴 開放項的候選解法（Phase 0 驗證，不預設答案）

- **時長**：① `player.freecaster.com/embed/{uuid}.json`（首頁 network 有這支，但 uuid ↔ item 的對映尚未建立）②由 `videoLowResCdn` 的 `.preview` 檔讀 metadata ③詳情頁 JS 渲染後從 DOM 讀（成本最高，等於放棄「不開詳情頁」）。
- **形式**：ENEX 可能根本不提供；若查無，就在素材行留白或標「形式未提供」，**不要用 LLM 猜**。

## 四、🔴 最大的結構性難題：引言偵測無法沿用 `sb_count`

`13b` 的 BITE 機械判準（RT／AP 數 `SOUNDBITE`、NS 看 `footageType`）**在 ENEX 直接套用會失效**，因為 ENEX 是多夥伴交換平台，每家 house format 不同。0809 抽樣 5 則就出現三種形狀：

| 夥伴 | 引言標記形狀 |
|---|---|
| `CN CCTV` | `UPSOUND (Chinese) Gao Yu'an, reporter:` ＋引號內容 |
| `ES TELE5` | `SHOTLIST:` 裡寫 `TOTALS {姓名}, {職銜}`，另起 `SOUNDBITE:` 段 |
| `IQ RUDAW` | 無標記，引言直接寫在 STORYLINE 內文的 `"…," said {姓名}` 句式 |

⚠️ **本次調查沒有驗證過引言偵測可行**：初探用的 regex 是 `/SOUNDBITE|SOT|SHOTLIST/i`，pattern 裡含 `SHOTLIST` 所以 5/5 全 true，**那是廢資料**；且 `13b` 明文禁止 `i` 旗標（`AP5467117` 版權樣板小寫 `soundbites` 實錯）。

**Phase 0 必做**：抽 50–100 則做**分夥伴標記普查**，再決定走哪條：
- (a) 每個 partner 一組 pattern 的機械判準（維護成本高，但符合「有無 BITE 由機器判」原則）；
- (b) 只對可機械判定的夥伴擋，其餘一律**照收＋寫進 `needs_review`**（合乎 `13b` 0805 訂正「兜底只判標記不判收錄」）。

## 五、登入態與掃描順序（開放項）

- **未驗**：ENEX 是 Drupal session cookie，時效通常以天計（比 NS 的 1 小時 JWT 寬鬆得多），但**本次沒驗過**。驗法很輕：隔天再打一次 `_search`，看是否仍回 200 且有資料。
- **保活**：在時效確認前，**不新增任何保活機制**——NS 的 58 分鐘保活數學是整個排程的軸心，不要為 ENEX 動它。
- ~~**掃描順序建議**：`NS → AP → RT → ENEX（附掛在尾端）`。~~ ⛔ **作廢（2026-08-09 使用者訂案，見附錄 B）**：**ENEX 不進固定掃帶排程，人工下令才跑。** 因此不需要排掃描順序，也不涉及 NS 保活的時間計算。

## 六、導入計畫（分階段）

### Phase 0 — 調查補完（不改任何規則，1 個工作階段）
1. 分夥伴標記普查 50–100 則 → 產出「partner × 引言標記形狀」對照表，決定 §4 的 (a)/(b)。
2. 驗時長來源（freecaster embed json 對映是否成立）。
3. 驗 `editStatus` 是否有「稿未到／pending」狀態（NS `early` 的類比）；查 `published:false` 與 `editStatus != PUBLISHED` 的實際意義。
4. 驗 session 時效（隔日重打）。
5. 驗 `_id` 是否跨日重用（RT `Edit No` 踩過的坑）。
6. **撈 `partner` 全集**（見 §三-a 的 aggs 查詢）→ 定案兩件事：①媒體簡稱的切法（切國別前綴 vs 建對照表）②TVBS 在 ENEX 上的實際 `partner` 字串，確認排除規則會命中。

**Phase 0 產出＝一份調查報告落 `common/investigation-logs/`，比照 `2026-08-03-三站API破解總表.txt` 的格式。**

### Phase 1 — 抽取白名單定版
- 寫 `slimEnex()`：保留 §三 表列欄位，砍 `*Suggest` 等雜訊；`description` **逐字保留、不做任何順稿或截斷**（超長整理包比照 `13b` 的 3,000 字元截斷＋標記處理）。
- 跑 `13b §0-1` 的**兩項保真驗證**：正規化逐字比對 ＋ 殘留掃描（`/&[a-zA-Z#0-9]{2,8};/` 與 `/<[^>]+>/` 皆須 0 命中）。
  ⚠️ ENEX 的 `description` 目前看起來是**純文字不是 HTML**（未見 tag），驗證要確認這點；若真是純文字，去 tag 那層可省，但殘留掃描照跑。

### Phase 2 — Pilot（影子模式，不進正式庫存）
- 連跑 3–5 輪，每輪把 ENEX 結果寫到獨立檔（不寫 `s2_state`），與人工看網站的結果比對：**則數、代碼、有無漏收**。
- 通過標準：連續 3 輪零漏收、零假 BITE。

### Phase 3 — 正式併入（**需使用者拍板才動規則**）
- `13b` 增 `§1a-4) ENEX`；`13` 的來源盤點表把 ENEX 從「暫不處理」改為已支援。
- `05` 補 ENEX 的下載路徑（見下方 follow-up）。
- fallback 階梯照 V2 形態：**ES API → 首頁 DOM 直撈 `/exchange/{id}` → 停下來問人**。

# 附錄 A：API 規格書（實作用，Phase 1 定版前為草案）

> 本附錄是給實作者／下一個 agent 直接照抄的技術規格。**規格內的程式碼都尚未通過 `13b §0-1` 的保真驗證**，Phase 1 跑完驗證才算定版。

## A-1 端點契約

| 項目 | 內容 |
|---|---|
| URL | `POST https://members.enex.news/elasticsearch/news/_search` |
| 認證 | **同源 cookie**（Drupal session），不需要 token、不需要 Authorization header |
| 呼叫方式 | **一律在 `browser_evaluate` 的同一個 `page.evaluate()` 內 fetch＋parse**（Playwright `mcp__browser__*`，不可用 claude-in-chrome，理由同 `13b §1a-0`） |
| Content-Type | `application/json` |
| Body | 原生 Elasticsearch Query DSL |
| 回應 | 標準 ES 格式：`hits.total.value` ／ `hits.hits[]._id` ／ `hits.hits[]._source`。**是純 JSON，可直接 `r.json()`**（不是 NS 的 NDJSON，也不是 RT 的 transit） |
| ⛔ 禁用 | `_mapping`／`_cat`／`_cluster` 等管理路徑——實測 `_mapping` 回 **400**，proxy 只開放 `_search` |

**失敗判讀順序**（比照 `13b §0`）：① 自己的 body 打錯 → ② Playwright profile 被鎖 → ③ 登入態過期。
⚠️ **回 0 筆時第一個懷疑對象不是「站方無素材」**——ENEX 每輪本來就只有個位數則，但 0 筆仍應先確認 session（打一次不帶時間窗的 `match_all` 看總數是否還是 33 萬）。

## A-2 標準查詢（三種，照抄即可）

### ① 每輪 diff 主查詢（時間窗 + 全欄位）

```js
// since = 上一輪的 window_start（epoch ms）；建議往前多抓 10 分鐘緩衝避免邊界漏收
const body = {
  query: { bool: { must: [
    { term: { published: true } },
    { range: { sortDate: { gte: since } } }
  ]}},
  size: 100,
  sort: { sortDate: { order: 'desc' } },
  track_total_hits: true,
  _source: ['title','description','partner','category','location','region','country',
            'tags','publishedDate','sortDate','creationDate','lastModified',
            'newslinkId','filename','thumb','videoLowResCdn','editStatus','editorsChoice','status']
};
```

- **`_source` 白名單是省 token 的主力**：不指定會連 `*Suggest` 五個重複欄位一起回。
- `size:100` 已實測可用；ENEX 量級（~7 則／3 小時）遠達不到上限，**單輪一次呼叫就能取完，不需要分頁**。真的滿 100 筆時才用 `search_after`（配 `sort` 的 `sortDate`），不要用 `from`（深分頁 ES 預設 10,000 上限）。

### ② 單則重查（pending 回頭補、查證用）

```js
const body = { query: { ids: { values: ['926241'] } }, size: 1 };
```

⚠️ **查證仍以 headline 比對為準**（`13b` RT `Edit No` 跨日重複的教訓）——即使 `_id` 看起來是全站唯一遞增流水號，Phase 0 確認前不要單靠 `_id` 採信查證結果。

### ③ 健康檢查（session 是否還活著，極輕量）

```js
const body = { query: { match_all: {} }, size: 0, track_total_hits: true };
// 回 hits.total.value ≈ 338,288 且 HTTP 200 → session 正常
```

## A-3 抽取白名單（草案，Phase 1 定版）

```js
// ⛔ 整則排除：自家素材不寫摘要（見 §三-a 第 3 條）
```

## A-4 保真驗證（Phase 1 必跑，兩項都要）

照 `13b §0-1`：

1. **逐字比對**：原始 `description` 與抽取後的 `desc` 都正規化成 `replace(/[^\p{L}\p{N}]/gu,'')` 後逐字元比對，必須完全相同。
2. **殘留掃描**：`/&[a-zA-Z#0-9]{2,8};/`（未解碼實體）與 `/<[^>]+>/`（未去乾淨的 tag）都必須 **0 命中**。

⚠️ **ENEX 的 `description` 初判是純文字（未見 HTML tag）**，若驗證確認如此，`clean()` 那層去 tag／解實體**可以省**——但第 2 項殘留掃描照跑，用來證明「真的不需要」。**不要憑印象省略，要有驗證數字。**

樣本要求：**至少 30 則、且橫跨 5 個以上不同 `partner`**（單一夥伴的樣本驗不出 house format 差異）。

## A-5 Fallback 階梯（固定順序，不准跳步、不准重試同一步）

1. **ES API**（本附錄主路徑）。
2. **失敗兩次 → 首頁 DOM 直撈**：首頁是伺服器端渲染，`document.querySelectorAll('a[href^="/exchange/"]')` 可直接拿到當前清單的 `_id`，再用查詢 ② 逐則取回。
3. **再失敗 → 停下來記進 `needs_review` 並跳過 ENEX**，不要卡住整輪（無人值守時段照 `13b §5`「半夜禁問」原則）。

⛔ **任何情況都不要 agent 自行輸入帳密**——登入頁出現就是請使用者手動登入。
