# 側錄初處理工作台——設計規格（2026-08-28）

- 性質：設計規格（已與使用者對過需求），不是規則、不是實作計畫
- 掛在：掐BITE 工作台同一個本機網站（FastAPI，預設 port 8765）的新分頁
- 測試素材：`D:\TVBS\CNN\`（四支約 65 分鐘 CNN 側錄；v1 瀏覽器必過只打 `CNN 075658 0817 增強藥專題.mp4`）

---

## 1. 要解決什麼

使用者丟進約 1 小時的 CNN／NHK 側錄，**不先跑 ASR**，用聲音結構＋畫面字卡，自動切出可能段落（廣告、主播、記者、訪問、主題大段），人核對後剪成獨立檔。所有時間碼依檔名 6 碼 offset 換成母帶 TC。

這頁**不做**掐 BITE、不產 SB 五行、不改 `common/07-bite-assistant.md`。

## 2. 不做（v1）

- Whisper／任何 ASR、Claude 視覺模型、全片 `scene_changes`
- 自動把結果送進掐BITE 分頁（之後可加，本次不串）
- 「去廣告後的單一長母帶」（本次一段一檔，不另產整支）
- NHK 字卡框調準（同一條管線能跑，v1 不保證類型準）
- 改 `sb_format.py` 的 SB 排版；offset 解析沿用現有 `scan_dir`／`offset_from_filename`

## 3. 架構

同一個 `scripts/bite_workbench.py` 行程，頁頂兩個分頁：

| 分頁 | 職責 |
|---|---|
| 掐BITE | 現況不動 |
| 側錄初處理 | 新 UI＋新 API |

新邏輯獨立成 `scripts/side_precut.py`（分析、標籤、剪檔）。工作台只負責 HTTP、背景 job、把 `Material` 傳進去。

複用、不准重寫：

- `scan_dir`／`Material`（含 `CNN 075658 …` 這種來源在前、6 碼在後的 offset；**不可**只對完整檔名呼叫 `offset_from_filename`，那個 regex 只認檔名開頭數字，這類檔會得到 0）
- `/media` FileResponse 串流
- 背景工作＋輪詢（比照 `/api/transcribe`）
- `sb_format.fmt_tc(..., 6)` 與 `offset_from_filename`（只對「純 6 碼」那一段呼叫）

旁路檔（不改原片）：`{stem} PRECUT.json`，與 `ASR.json`／`ZH.json` 同資料夾。原片 mtime 新於快取 → 分析鈕旁黃字「建議重跑」，不自動覆蓋。

依賴：現有 ffmpeg；新裝 `rapidocr-onnxruntime`（Hermes venv，與工作台同一顆 Python）。沒裝則分析 API 直接 4xx，訊息含安裝指令。

## 4. 操作流程

1. 開 http://127.0.0.1:8765 → 分頁「側錄初處理」
2. 填資料夾（測試預設可帶 `D:\TVBS\CNN`）→ 讀取
3. 選一支側錄 →「分析」（已有快取則直接掛回）
4. 畫面：左素材；右上影片＋當段資料（類型／主題／母帶 TC，可改）；下方滿寬波形色塊＋段落列表（可勾選、可拉邊界）
5. 匯出：
   - 「一鍵出全部非廣告」（預設）
   - 「只出勾選」
   - 可選「精準重編」（預設關＝stream copy）

## 5. 切段引擎（本機、零 token）

順序固定：

1. **靜音骨架**：`ffmpeg silencedetect`。預設約 `-30dB`、最短靜音 `0.6s`（實調，不寫死進規則文件）。短於約 `1.5s` 的氣口併回同一段；更長的靜音當大段落邊界。
2. **音量包絡**：低採樣 RMS／peak（給波形畫布＋廣告啟發式）。
3. **不跑全片鏡頭偵測。** 只在段落中點抽 1 張低解析幀。
4. **OCR**：裁 CNN 720×480 畫面下方約 28% → RapidOCR。有字＝主題；沒字＝主題空白、只留類型。若環境已有 OpenCC，簡體走 `s2twp`；沒裝就原樣留下，**不**因此讓分析失敗。
5. **類型（建議，人必改）**：`廣告`／`主播`／`記者`／`訪問`／`其他`。把握度：廣告 ＞ 主播／其他 ＞ 記者／訪問。啟發式（可實調）：忽然變大聲、兩頭黑或長靜音、下標幾乎沒字 → 偏廣告。
6. **主題大段**：相鄰非廣告、字卡接近 → 合併。

分析走背景 thread，前端輪詢 phase（抽音量／靜音／抽幀／OCR／合併）。65 分鐘目標：數分鐘內、零 token。

`PRECUT.json` 最小形狀：

```json
{
  "source": "CNN 075658 0817 增強藥專題.mp4",
  "offset_sec": 28618,
  "mtime": 123,
  "segments": [
    {
      "id": "s1",
      "t0": 12.0,
      "t1": 84.0,
      "tc0": "075710",
      "tc1": "075822",
      "kind": "ad",
      "topic": "",
      "ocr": "",
      "selected": false
    }
  ]
}
```

`t0`／`t1` 是檔內秒；`tc0`／`tc1` 是母帶 6 碼（`offset + t`）。`kind` 固定五個英文 key，UI 顯示中文：`ad` 廣告、`anchor` 主播、`reporter` 記者、`interview` 訪問、`other` 其他。

## 6. 畫面（版面 B）

- 頁頂：`掐BITE` | `側錄初處理`（目前分頁高亮）＋資料夾路徑＋讀取
- 左欄：素材清單（沿用現有卡片／tag）
- 右上：`<video>`（同一套 `/media`）＋當段表單（類型下拉、主題文字、母帶起迄、精準重編核取）
- 中下：滿寬波形，色塊＝類型（廣告紅、主播藍、訪問綠、記者黃、其他灰）；點色塊／列表 → `currentTime` 跳轉（沿用 pendingSeek，避免 metadata 未到靜默忽略）
- 列表：勾選、顯示母帶 TC、類型、主題、時長；可改邊界（輸入秒或 TC）
- 按鈕：分析｜一鍵出全部非廣告｜只出勾選

點段跳轉後，人改的欄位寫回記憶體；「存回 PRECUT.json」在匯出時自動做一份，另提供手動存檔以免分析中途關掉。

## 7. 剪檔

輸出目錄：`{來源資料夾}/{stem} 初處理\`  
檔名：`{來源} {母帶HHMMSS}-{母帶HHMMSS} {類型中文} {主題}.mp4`  
例：`CNN 080414-081831 主播 增強藥.mp4`

- 主題空：省略該段，不要出現空白或 `None`
- 主題做檔名清理（去掉 `\/:*?"<>|` 與過長截斷）
- 廣告預設不輸出（除非使用者勾了該段且按「只出勾選」）
- 同名覆蓋；不刪資料夾裡其他檔
- 邊界重疊：匯出前黃字警告，**不阻擋**
- 預設 `-ss`/`-to` + `-c copy`（切點吸到關鍵影格，可能差 1–2 秒）
- 勾「精準重編」：該段重編碼，切在標註秒

不覆寫原片。剪檔也是背景 job＋輪詢。

## 8. TC offset

規格來源：`common/02-tc-offset-filename.md`。  
機械來源：`Material.offset`（`scan_dir` 已處理 `SIDE_PREFIX_RE`）。

`CNN 075658 0817 增強藥專題.mp4` → offset `07:56:58`。檔內 `00:00:00` 顯示／檔名皆為 `075658`。沒 6 碼或 `000000` → offset 0，素材卡黃字警告。

## 9. 錯誤

| 情況 | 行為 |
|---|---|
| RapidOCR 未裝 | 分析 4xx，提示 `pip install rapidocr-onnxruntime` |
| ffmpeg 失敗 | job `error`，前端顯示 stderr 末段 |
| OCR 沒字 | 主題空、類型仍給建議 |
| 無 6 碼 | offset 0＋黃字 |
| 分析中重複按 | 409（同轉錄） |
| 輸出同名 | 覆蓋該檔 |
| 重疊邊界 | 警告後仍可剪 |

## 10. 測試

單元（`scripts/test_side_precut.py`，假資料，不進 500MB 影片）：

- `CNN 075658 …` offset = 7×3600+56×60+58
- 氣口 <1.5s 合併、長靜音切開
- 檔名清理、主題空時檔名不含多餘空白
- 廣告啟發式：高音量＋無 OCR → `ad`
- copy vs 精準：命令列組字正確（mock ffmpeg）

瀏覽器 v1 必過（`D:\TVBS\CNN\CNN 075658 0817 增強藥專題.mp4`）：

1. 分析產出段落（含至少一段非廣告）
2. 點段會跳到對應畫面
3. 一鍵能在 `{stem} 初處理\` 產出非廣告 mp4
4. 檔名母帶 TC = 檔內秒 + `07:56:58`

其餘三支（15／16／21 整點）當回歸，不列 v1 必過。
