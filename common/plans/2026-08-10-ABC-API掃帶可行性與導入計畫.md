# ABC NewsOne 併入掃帶：API 直查可行性調查與導入計畫（草案）

> **狀態：計畫草案，2026-08-10 建立。本檔不修改任何既有規則**（`13`／`13b`／`05` 一字未動）。
> 姊妹篇：[`2026-08-09-ENEX-API掃帶可行性與導入計畫.md`](2026-08-09-ENEX-API掃帶可行性與導入計畫.md)，本檔沿用同一套調查方法與文件結構。
> 現況基準：`13` 的來源盤點把 ABC 標為「暫不處理」、`05` 說 ABC「尚無對應下載來源／流程，遇到只做編號」。
> 站台：**ABC NewsOne（Extreme Reach AdBridge 平台）**，`https://abcnews.extremereach.com`。

## 一、結論（先講）

**可行。** 但形態與 ENEX／AP／RT 都不同：**ABC 沒有 JSON API**，它的「API 形態」是
**① 清單頁用 query string 直接查（可回 CSV）→ ② 從清單 HTML 撈 Detail ID → ③ 批次抓 Detail 頁抽欄位**。
實測一輪（當日 73 則）**3 次 `browser_evaluate` 就能把清單＋73 份完整文稿全部抽完**，一次詳情頁 UI 都不用點。

**比 ENEX 好的地方**：時長（`Length`）與分類（`Categories`）都有現成欄位，ENEX 這兩格是缺的。

🔴 **唯一的真難題是使用者要求的「排除非 ABC 素材」**——ABC NewsOne 的清單裡**確實混著 Reuters／CCTV／NIPPON TV 等外電轉發帶**（當日 73 則中至少 9 則），而**平台層級的欄位分不出來**（見 §四）。這是導入前必須先解決的關卡，不是收尾細節。

## 二、已實測確認的事實（2026-08-10 凌晨，Playwright 同源 `page.evaluate`）

| 項目 | 實測結果 |
|---|---|
| 平台 | Extreme Reach **AdBridge**（ASP.NET MVC，伺服器端渲染），入口 `/cmspage/50162/abcnewsone`，素材清單在左上角 **NEWSONENET** 按鈕 → `/Delivery/NewsDeliveries` |
| **清單端點** | `GET /Delivery/NewsSearch?{query}`（同源 cookie ＋ **CSRF token**） |
| **CSV 模式** | 同一支端點加 `getCSV=true` → `content-type: text/csv`，欄位：`DeliveryAvailableDateTime, News Story, Slug, Length, DestinationName, DeliveryStatus, DeliveryCompleteDateTime` |
| **文稿端點** | `GET /adbridge/news/Delivery/Detail/{detailId}?includeCategories=True`（HTML，約 39KB／則） |
| JSON API | **沒有**。全站掃過 `api`／`json`／`Data`／`Grid` 字樣的路徑，**0 命中**；清單與詳情都是伺服器端 HTML |
| 分頁 | `pageSize=100` 實測可用（當日 73 則一頁取完）；`page` 分頁參數存在 |
| 時間窗 | `deliveryDateStart`／`deliveryDateEnd`，格式 **`M/D/YYYY`**（美式，非 ISO），**只到日期、沒有時分** |
| 排序 | `sortColumn=DeliveryAvailableDateTime&sortDirection=1` |
| 伺服器端篩選 | `mediaCategoryId`（分類）、`searchSlug`、`searchStoryNumber`、**`newsSynopsisOrScript`（全文搜稿）**、`deliveryStatusId`、`destinationIds` |
| `showHDOnly` | `true` 與 `false` **同樣回 73 則** → 這批沒有 HD/SD 雙投遞問題，該參數可忽略 |
| 量級 | 當日（8/9 一天）**73 則**，遠多於 ENEX 的個位數 |

### CSRF token（與 ENEX 最大的操作差異）

清單端點需要 `__RequestVerificationToken`。**每輪從 DOM 現讀，不可寫死**：

```js
const tok = document.querySelector('input[name=__RequestVerificationToken]').value;
```

⚠️ token 綁 session，過期或換 session 就失效。整段「讀 token → fetch → parse」**必須寫在同一個 `page.evaluate()` 內**（同 `13b §1a-3`，token 不離開頁面 JS）。

### Detail 頁的欄位（實測 dump）

`Media Type` / `Delivery Date` / **`Slug`** / **`Story Number`** / `Destination` / **`Trafficked By`** / `Delivery Status` / **`Length`** / **`Synopsis`**（一句話摘要）/ **`Script`**（完整文稿）/ **`Categories`**。

`Script` 的標準表頭（**但覆蓋率很低，見 §四**）：
`STATUS:` / `LOCATION/STORY:` / `ADVISORIES/RESTRICTIONS/EMBARGOES:` / `MUST ONSCREEN COURTESY:` / `FORMAT:` / `VIDEO SHOWS/SHOTLIST:` / `SUPERS:` / `VIDEO PROVIDED BY:` ＋逐字稿本體。

⚠️ **HTML 實體要解碼**：`Script` 欄位的換行是 `&#10;`，不解會整篇擠成一行。**建議直接用 `13b §0-1` 的 `decodeEnt` 全套**，不要只解 5 個常見實體（ENEX 那邊踩過 `&rsquo;` 殘留）。

## 三-a、素材編號（沿用 `05` 的 ABC 前綴）

- 格式：**`ABC` ＋ `Story Number`**，例 `ABC080926021`。
- `Story Number` 的結構是 **`MMDDYY` ＋ 3 碼序號**（`080926021` ＝ 08/09/26 第 021 號），**自帶日期**，比 RT 的 4 碼 Edit No 安全（不會跨日重複）。
- ⛔ **不要用 Detail 的 `{detailId}`**（如 `638475239`）當素材代碼——那是投遞紀錄的內部 id，同一則素材投兩次會有兩個。

### 去重鍵：`Story Number`，不是 detailId（實測）

當日 73 筆裡有 5 組同 slug 重複，分兩種形狀：

| 形狀 | 例 | 處置 |
|---|---|---|
| **同 slug、同 story number、兩筆投遞** | `TopPlays0808`／`IranWarSatPKG`／`BlancheVoteSatPKG`（各 `080826062`／`080826040`／`080826017`） | **去重**，同一支素材投兩次 |
| **同 slug、不同 story number**（跨日重上） | `BrazilHelicopterCrash`（`080926004` vs `080826034`）、`ArgentinaMessiFather`（`080926002` vs `080826026`） | **各自收錄**，是不同批次的素材（比照 `13b` RT「舊稿重上」精神，但 ABC 的日期碼在代碼裡，不必另標） |

## 四、🔴 核心難題：排除非 ABC 素材

**使用者要求**：只收 ABC 與其附屬台的素材，**混在裡面的 AP／RT 等外電一定要排除**。

### 為什麼平台欄位不管用（實測打掉的兩個候選）

| 候選欄位 | 實測 | 判定 |
|---|---|---|
| `Trafficked By` | **73/73 全是 `ABC NewsOne`** | ❌ 完全不能分辨——它只表示「誰投遞的」 |
| `VIDEO PROVIDED BY` | **56/73 空白**；有值的也雜（`ABC`／`ABC News`／`ABC NEWS`／`ABC/GOOD MORNING AMERICA`／`NEWSONE NY`／`WPDE`，還有 2 則抓到 `LENGTH:`＝表頭錯位） | ❌ 覆蓋率不足、值未正規化 |

**根因**：ABC NewsOne 是**發稿平台**，不是版權標示系統。素材的真實來源寫在**文稿內文**，而且是**逐 shot 內嵌**的（`SOURCE: Reuters`、`++SOURCE++`、shot 行尾括號），不是獨立的結構化欄位。

### 實測確認：外電**確實混在裡面**

當日 73 則中，文稿內含外電 SOURCE 標注的至少 **9 則**：

| Slug | Story Number | SOURCE |
|---|---|---|
| `WW2NagasakiAnniversary` | `080926006` | Reuters／JAPAN POOL |
| `JapanMudslide` | `080926007` | Reuters／NIPPON TV |
| `ThailandSchoolShooting` | `080926008` | CCTV／CGTN |
| `ArgentinaMessiFather2` | `080826054` | Reuters |
| `CanadaWildfiresBriefing` | `080826029` | Reuters／British Columbia Government |
| `HunterBidenIntv` | `080826028` | Reuters／BBC Newsnight |
| `BlancheConfirmationReax` | `080826020` | Reuters／社群影片 |
| `UkraineUSSupplies` | `080826019` | Reuters |
| `PraguePrideParade` | `080826016` | Reuters |

📌 **形狀很清楚：國際線 slug（Japan／Thailand／Argentina／Canada／Prague…）幾乎都是 ABC 轉發的 agency 帶。** 這正是使用者要擋掉的東西——那些帶子 TVBS 本來就會從 RT／AP 自己拿，從 ABC 收等於重複，還可能踩到不同的授權條件。

### ⭐ 真正的關鍵欄位：`LOCATION/STORY:` 行**結尾的括號**（2026-08-10 擴大樣本後找到）

把樣本拉到 **3 天 335 則**後才看清楚：ABC 的來源與形式標記，主要寫在 `LOCATION/STORY:` 那一行**最後一個括號**裡。這一格是**多用途**的，值分成四類：

| 括號內容 | 意義 | 335 則中出現次數 | 處置 |
|---|---|---|---|
| **記者名**（`Rachel Scott reports`／`David Muir reports`／`Marcus Moore, London`…） | ABC 自家記者 | 約 60（20+ 種寫法） | ✅ **收（ABC 自製）** |
| **`AP`／`APTN`／`APTN & HANDOUT`／`POOL`／`FILE / REUTERS`** | 外電 | **AP 12、APTN 3、POOL 8、FILE/REUTERS 1 ＝ 24** | ⛔ **排除** |
| **`VO`／`SOTVO`／`SOCIAL`／`HANDOUT`／`FILE VIDEO`** | 素材形式（見 §四-a 拍帶） | VO 13、HANDOUT 8、SOCIAL 2、SOTVO 1、FILE VIDEO 1 | ✅ 收，但**是拍帶不是成品** |
| **呼號**（`KABC`／`WGNO`／`KOAT`／`KIVI`） | 附屬台 | 5 | ✅ **收（附屬台）** |
| 無 `LOCATION/STORY` 行 | — | **135** | 需其他判準（大宗是體育，見 §四-b） |

🔴 **這一格解掉了先前「41 則待判」的大半，也抓出我原本漏掉的外電**：`BrazilHelicopterCrash` 的 `LOCATION/STORY` 結尾就寫著 **`(AP)`**，但它**沒有** `SOURCE:` 行，所以只看 `SOURCE:` 的分類器把它判成「非外電」——**這是會直接違反使用者「一定要排除」要求的漏網形態，務必納入判準。**

### ✅ 使用者訂案：**slug 含 `PKG` ＝ ABC 自製**（2026-08-10）

**實測驗證通過（3 天 335 則）**：slug 含 `PKG`／`PACKAGE` 者 **104 則**，其中命中外電 SOURCE 的 **0 則**；反過來，35 則外電**全部**都不含 PKG。**零反例。**

⚠️ 但這條是**充分不必要條件**：不含 PKG ≠ 外電（VO 拍帶、SOTVO、NSB 訪問段都是 ABC 自製卻沒有 PKG）。所以它只能當**正向收錄訊號**，不能反過來當排除依據。

### 建議判準：三層分類器（Phase 0 要驗到零誤排才能上線）

**⚠️ 不對稱原則（重要）**：使用者說「**一定要**排除」——**把 Reuters 誤收成 ABC，比漏收一則 ABC 更糟**。
所以**只要出現任何外電 SOURCE 訊號就排除，不准讓 ABC 的正向訊號蓋過它**（外電層優先於 ABC 層）。

**取值一律從三個地方取，不要對全文自由比對**：`LOCATION/STORY` 末括號、`SOURCE:` 值、`VIDEO PROVIDED BY:` 值。

```js
// ⛔ 第 0 層：整類排除（使用者訂案，見 §四-b）
const cats = item.categories;
if (cats.includes('Sports')) return 'skip:體育';
if (cats.includes('Promos/Tie-Ins') || /^OTRC/i.test(slug)) return 'skip:例行娛樂';

// ⛔ 第 1 層：外電（優先級最高，勝過任何 ABC 正向訊號）
const WIRE = /^(AP|APTN|REUTERS|ASSOCIATED PRESS|AFP|AFPTV|CCTV|CGTN|POOL|NIPPON TV|GETTY|STORYFUL|JAPAN POOL)\b/i;
if ([locParen, ...sourceVals, providedBy].some(v => WIRE.test(v||''))) return 'skip:外電';

// ✅ 第 2 層：ABC 自製
//   a) slug 含 PKG／PACKAGE（實測零反例）
//   b) LOCATION/STORY 末括號是記者名（`… reports`／已知記者名單）
//   c) VIDEO PROVIDED BY: ABC*／NEWSONE*，或 COURTESY: ABC／GMA／This Week
//   d) FORMAT 含 GMA／WN／NEWSONE／NSB
// ✅ 第 3 層：附屬台呼號（收）— 實測 KABC／WGNO／KOAT／KIVI／WGGB／WLS／WEWS／WPDE
const OWNED = /^[WK][A-Z]{2,3}$/;     // ⚠️ 只對「括號值」比對，不對全文，見下方地雷 3
// 都沒命中 → 照收並記 needs_review
```

⚠️ **外電正則要用 `^` 錨定在「括號值的開頭」**，不要無錨定全文比對——`AP` 兩個字母在全大寫稿件裡到處都是。

### ⚠️ 三個會踩的地雷（我自己都踩過，寫下來免得重犯）

1. **`SOURCE` 不可用行首錨定**（`/^\s*SOURCE/m`）：ABC 是內嵌標注，錨定會漏掉 `WW2NagasakiAnniversary`／`JapanMudslide` 這種明明寫著 `SOURCE: Reuters` 的，害你以為 52 則「無訊號」。
2. **`SOURCE` 也不可完全不錨定**：純 `/SOURCE[:\s]/i` 會抓到內文的 `SOURCE OF POWER IRAN CONTROLS…` 這種普通英文句子。**建議只取 `SOURCE` 後 60 字元內、且比對是否命中已知供應商清單**，不要拿自由字串當來源。
3. **呼號 `\bW[A-Z]{3}\b` 不可對全文比對**：稿件是全大寫，會命中 `WITH`／`WHEN`／`KNOW`。實測全文比對得到「44/73 有地方台呼號」是**假數字**，實際只有 4 則的 SOURCE 值是呼號。

## 四-a、拍帶 vs 成品包裝：**有欄位可以區分**（2026-08-10 使用者提問，已查證）

使用者問「拍帶有沒有其他欄位可以區分」——**有，而且有兩個互補的欄位**：

### 1) `FORMAT:`（主判準，但覆蓋率 52%）

335 則實測的值域，可分成三群：

| 群 | `FORMAT` 值 | 意義 |
|---|---|---|
| **成品包裝** | `GMA PACKAGE`(19)／`WN PKG`(21)／`NewsOne PKG`(16)／`NEWSONE PKG`(8)／`NewsOne MiniPKG`(11)／`PKG`(4)／`{記者名} PKG`／`ABC NEWS LIVE PKG` | 有記者過音的完整包裝 |
| **訪問／聲刺** | `NSB`(47)／`GMA INTERVIEW`(2)／`SOTVO`(3) | 訪問段、聲刺；**`NSB` 是 ABC 的 soundbite 型態，附逐字稿** |
| 🎯 **拍帶／畫面** | **`VO`(16)／`NATS`(3)／`VIDEO SHOWS:`／`HANDOUT`** | 只有畫面＋簡短文字，無記者過音 |

⚠️ **`FORMAT` 有 160/335（48%）是空的**，不能單靠它。

### 2) `LOCATION/STORY` 末括號的形式標記（補洞用）

`(VO)`(13)／`(SOTVO)`(1)／`(SOCIAL)`(2)／`(HANDOUT)`(8)／`(FILE VIDEO)`(1) —— 這些跟 `FORMAT` 是同一套語彙，**兩者互補可把覆蓋率補上來**。

### 3) slug 命名慣例（第三道，很穩定）

ABC 的 slug 自帶形式尾綴，實測形狀非常一致：

| 尾綴 | 意義 | 例 |
|---|---|---|
| `…PKG` / `…SunPKG` / `…SatPKG` | 成品包裝 | `GMAWeatherThreatWildfiresSunPKG` |
| **`…VO`** | **拍帶（純畫面）** | `WAHospitalStandoffVO`／`CAPlaneCrashesIntoStreetVO`／`TruckHitsTVStationVO` |
| **`…SOTVO`** | 聲刺＋畫面 | `MichaelBJordanGrandmaSurpriseSOTVO` |
| **`…SOCIAL`** | 社群授權影片 | `UnitedPlaneFlatTireSOCIAL` |
| `…INTV` | 專訪 | `GMADementiaRiskINTV` |
| `…FILE` | 資料畫面 | `MetaFILE` |
| `…Speech` | 演說全長帶 | `DrewBreesHofSpeech` |

### 4) `Categories` 也有幾個素材型態類（輔助）

`Great Video`(20)／`Cleared Social Video`(3)／`File Video`(1)／`STILLS/GFX`(1)／`Vertical Video`(1)／`NewsOne Extras`(1)。
⚠️ 但 `Great Video` 實測**混著 PKG 與拍帶**（`GMADementiaRiskINTV`、`TopPlays0808` 都在裡面），**它是「畫面好看」的推薦標籤，不是型態標籤**，不可拿來當拍帶判準。

### 建議：三者取聯集，標成 `material_type` 欄位

`PKG`（成品）／`SOT`（訪問聲刺）／`VO`（拍帶）／`SOCIAL`（社群）／`FILE`（資料畫面）／`UNKNOWN`。
優先序：**`FORMAT` ＞ `LOCATION/STORY` 末括號 ＞ slug 尾綴**，三者都沒有才 `UNKNOWN`。
📌 這格對下游有用：拍帶（VO）沒有記者過音，寫三段式時**畫面段是主體、不會有 BITE**；成品 PKG 則相反。

## 四-b、⛔ 體育與例行娛樂：整類排除（2026-08-10 使用者訂案）

- **體育全部排除**——**理由是版權，ABC 的體育帶 TVBS 不能用**。
  **機械判準：`Categories` 含 `Sports`**，實測 3 天共 **59 則**（MLB／WNBA 各隊比賽、Little League 世界大賽、名人堂演說、`TopPlays` 每日精華）。
  ⚠️ 這批稿件多半**沒有 `LOCATION/STORY` 行**（135 則無此行的大宗就是它們），先排除掉可以省下大量無效判讀。
- **例行性娛樂素材排除**——**機械判準：`Categories` 含 `Promos/Tie-Ins`(44)，或 slug 以 `OTRC` 開頭**（`OTRCPrimePreview080926`／`OTRCAAFCASOTVO` 等節目宣傳與紅毯例行帶），以及 `GMAAhead*`／`GMATomorrow*`／`WKNDWorldNewsPromo*` 這類節目預告。
- 🔴 **有重疊要小心，不可直接用 `Entertainment` 整類砍**：`Entertainment`(14) 與 `Promos/Tie-Ins`(44) 相加去重後有 55 則，但裡面**混著非娛樂內容**（例如醫療線的 `GMADementiaRiskINTV` 也被歸進去）。**用 `Promos/Tie-Ins` ＋ `OTRC` 前綴排除較安全**，`Entertainment` 單獨出現時建議照收並記 `needs_review`，Phase 0 再看要不要收緊。
