## 一、先講結論

**還有空間，但最大刀不在「再破解一個新 API」，而在把已經破解的三條 API，收成 agent 不會走鐘的機械層。**

今日（2026-08-14）開三站核對：

| 站 | 登入 | 現役 API | 與 13c 配方差在哪 |
|---|---|---|---|
| NS | 正常（landing 有 Video 列表＋session） | `POST …/api/v3/stories` 仍是清單＝全文 | 沒有新端點。兩段式（先小欄位篩 NEW，再打全文）規則已寫、輪次常沒守 |
| AP | `/home` 仍會先掉到 `/live`，點 Latest 才回正軌 | `POST /v1/nrsearch/search/topic` 仍是清單；body **PageSize=16、TopicId=`116e9ab7…` 與 13c 範本一字不差** | **沒有「一次撈 100 則還保持 Latest 排序」的合法參數。** 0100 輪那 117 則是違規撈法 |
| RT | ` /all?media-types=vid` 已進 my-feed | `POST /api/search-api?hash=…` 仍在打、`limit=60`、`sort=ts`、`cursorMark=*` | **hash 已從 0803 的 `klwn20` 變成 `-eak9bv`**。再次證明 hash 只能當輪從頁面照抄，不能寫死 |

三站資料面能自動化的，13c §1a 幾乎都已經寫成「evaluate 裡 fetch＋瘦身」。0100 輪還在燒的，是：

1. 開場 8～10 次 bash 做 preflight
2. evaluate 結果落地格式各寫各的（AP 對帳假綠燈就是這樣來的）
3. `add-batch` 後退回改格式（摘要 150 字、BITE 括號）打 5～7 次 `update-entry`
4. audit／render 收尾重跑 2～3 次
5. 沒用已經上線的 `s2_batch_prep inspect`／`build`

**投報排序：落地契約 ＞ 入庫前 lint ＞ 輪次閘門 ＞ launcher 瘦身。再往下挖新 API，投報低、還可能踩靜默錯資料。**

## 二、今日摸站：能對接到哪一層（與不能）

### 2.1 已經對到、不要再發明一條路

- **NS**：Bearer 只准活在 `page.evaluate()` 裡；回傳白名單欄位。`size` 上限 100，但一次帶全文會爆 context——13c 已禁止。
- **AP 清單**：照抄頁面 body。`TopicId` 今日仍是 `116e9ab7aa044476925398d731289267`（`get-topics?location=latest,top` 的 All Latest）。`PageNumber` 翻頁、`PageSize` 永遠 16。
- **AP 詳情**：`/v1/nrsearch/search/item/details`，一則一次、`Promise.all` 包成一次 evaluate。稿在 `script.nitf`。
- **RT 清單**：首選仍是 §1b DOM（transit 壓縮，regex 會漏）。API 清單只當備援。
- **RT 詳情**：`GET /api/item/{guid}?live=false`，同源、`Promise.all`。Edit No 從 guid 推。

### 2.2 今日新確認的地雷（計畫必須寫死）

1. **AP `/home` → `/live` 仍會發生。** 開工若停在 Live Feeds，對到的是 replay／直播，不是 Latest video。規則已有「偶跳 /live」，建議閘門直接檢查 URL 含 `/home` 且左側 Latest 為選中。
2. **AP `PageSize≠16`＝正確性事故，不是省呼叫。** 0803／0804／0812 已推翻「調大 PageSize」。0100 用 API 一次倒 117 則，落地又變成 tab＋ISO，audit 全判窗外——兩件事是同一類「自創格式／自創參數」。
3. **RT hash 會變。** 0803=`klwn20`，今日=`-eak9bv`。任何「寫死 hash 的小工具」都會在下次前端發版靜默打空。
4. **獨立 HTTP collector 仍然禁止**（MASTER「明文不做」Task 6）。理由今日又被驗證一次：AP 要 cookie＋正確 TopicId＋正確 PageSize；NS token 不准出頁面；RT hash 會漂。collector 一漂就是無聲漏收。

### 2.3 沒有挖到、也不建議追的

- AP 沒有穩定的「Latest 全窗一次回」端點。`search/vod` 是另一條（VOD／Replay），不是掃帶清單。
- NS 沒有「比 stories 更瘦、又含 script」的第二支官方 API。
- RT 沒有比 DOM 清單更穩的 transit 解壓捷徑值得再花一週。
- 三段式中文摘要、BITE 講者、跨站併題——這層是編輯判斷，腳本化投報最差。

## 三、建議分批（由高投報、低行為改變 → 高風險）

狀態代號沿用 MASTER：⬜建議／🗳要裁決才做／❌明文不做。

### P0 — 正確性契約（先堵洞，再談省）

| ID | 項目 | 狀態 | 做什麼 | 預估 | 不做什麼 |
|----|------|------|--------|------|----------|
| P0-1 | AP／RT／NS **對帳快照格式寫死** | ⬜ | `s2_batch_prep.py snapshot --site {ap\|rt\|ns}`：吃 evaluate 瘦身陣列，吐出 `s2_audit.py` 認的 `CODE\|本地時間\|標題`（AP 至少 page1+page2＝32 則，13d §7）。0100 的 tab＋ISO 從此進不了「當正式快照」 | 消滅假綠燈；每輪少 1～3 次手轉格式 | 不改掃描 PageSize；不讓 snapshot 自己打站方 |
| P0-2 | 0100 揭出的 **23 則 AP 窗內漏收** | ⬜作業 | 0430（或下一輪）核實回補。這是資料洞，不是開發 | 補回真漏 | 不為了這 23 則開新 collector |
| P0-3 | 規則加一句：**evaluate 回傳若被 MCP 卸載成連結＝當資料遺失**（13d §6 已寫）＋ **快照副檔名／分隔符不對＝當沒對帳** | ⬜文字 | audit 對「已收 0 且窗外＝清單總數」直接 🔴，不要 ✅ 窗內零漏收 | 0100 那種假綠燈當場破功 | 不自動重抓 |

P0-1 對應 MASTER A2 未做子項 `snapshot`。建議升成下一波第一件。

### P1 — 入庫前機械層（0100 最肥的可刪區塊）

0100：`update-entry` 7 次、Bash 拆 evaluate 落檔數次、audit×3、render×3。幾乎都是「先入再修」與「格式即興」。

| ID | 項目 | 狀態 | 做什麼 | 預估每輪 | 依賴 |
|----|------|------|--------|----------|------|
| P1-1 | `s2_batch_prep build` 擴 **入庫前 lint** | ⬜ | 組 batch 時就擋：摘要＞150 字、有 `▎BITE：` 缺 `(BITE)`、第二括號不是 `(BITE)`、NS 缺 `footage_type`、AP／RT 缺 `sb_count`、缺 `src_text`。印 id＋哪一條，**不寫 state** | 少 4～7 次 update-entry（0100 實測整段） | 無裁決 |
| P1-2 | `s2_batch_prep compare --raw --batch` | ⬜ | A2 已列未做。只印「raw 有、batch 無」與缺欄 | 少一輪即興 `python -c` | 無 |
| P1-3 | **強制走 dump／build，不准手寫整份 batch.json** | ⬜規則 | 13d 已叫人用 inspect；再加：`add-batch` 的檔必須是 `build` 產出（檔頭記 `built_by=s2_batch_prep`）。agent 只寫 `entries.json`（id→三段式） | 0100 那種「Write 1.5 萬字 batch＋再 hex 補 src_text」整段消失 | 要改 13d 一句 |
| P1-4 | `parse_ok` 預跑 | ⬜ | build 時跑與 `s2_parse` 同一套，失敗列 id，讓 agent 改 entry 再入。0100 新入庫 82 則裡 **43 則 parse_ok=False**（NS 23／RT 14／AP 6） | 少 dashboard／稽核⑥ 的 44 則黃燈堆積 | 無 |

這一層**不碰瀏覽器、不碰 API**，只消化已經在 scratch 的資料。投報最高、行為改變最小。

### P2 — 輪次閘門（砍開場 8 次 bash）

MASTER A3 整包還是 ⬜。0100 開工：`git pull`、`pwd`、`resume`、`get`、`scratch-dir`、`needs-review list`、`待整併`×2、再 grep 舊調查報告找 NS API。

| ID | 項目 | 狀態 | 做什麼 | 預估 |
|----|------|------|--------|------|
| P2-1 | `s2_round_gate.py preflight` | ⬜ | 一次印：state 路徑、checkpoint、window、pending、needs-review 未結、scratch、`_待整併` 有無本班檔、NS／AP 目前 URL 是否在白名單（若瀏覽器已開） | 開場 8～10 次 → 1 次 |
| P2-2 | `resume --json` | ⬜ | 給閘門與其他工具組合，人讀的 resume 維持現狀 | 少拆 `head` |
| P2-3 | `postflight` | ⬜ | 頂層 checkpoint 有無推進、三站 reconcile 有無本輪、快照三站齊、render hash、未結 🔴。**只報告不阻斷**（A3 原驗收） | 收尾少「先 render 被罵缺 NS 再補 audit」 |
| P2-4 | 開場禁止 grep `investigation-logs` | ⬜文字 | 配方以 13c §1a 為準；舊總表是歷史。0100 開場 3 次 grep 調查報告＝純浪費 | 少 3 次呼叫 |

### P3 — API 對接「加深」但不做 collector

原則：**還是 Playwright `browser_evaluate` 打站內 API**；腳本只提供**可貼上的配方檔**與**回傳→快照轉換**。Token／cookie／hash 不准出頁面、不准寫進 repo。

| ID | 項目 | 狀態 | 做什麼 | 預估 | 風險 |
|----|------|------|--------|------|------|
| P3-1 | 把 13c 三站 evaluate 範本抽成 `scripts/s2_recipes/` 三個 `.js` 片段（NS list／AP list／AP details／RT items） | ⬜ | agent Read 一個檔、整段貼進 evaluate。減少「自己拼 PageSize／自己解 transit」 | 少自創參數；AP 正確性 | 低。這不是 collector，只是給人貼的程式碼 |
| P3-2 | NS 兩段式做成兩個固定片段：`ns_list_slim.js`（無 script）→ diff → `ns_detail_by_ids.js` | ⬜ | 對齊 13c「不要 size 開大配全稿」。0100 NS 46 則一次組 batch 長考 3 分鐘，一部分是全文進 context 太早 | NS 階段 5～8 分 → 3～5 分（視新則數） | 低 |
| P3-3 | RT 當輪 hash：evaluate 內從 `performance.getEntries()` 或現成 search-api URL 抄，禁止寫死 | ⬜併入 P3-1 | 今日 hash 已變 | 避免備援 API 打空 | 低 |
| P3-4 | AP 清單固定 page1+page2 兩次 fetch（同一次 evaluate）、立即 `snapshot` | ⬜併 P0-1 | 滿足 13d §7，且 PageSize 永不改 | 對帳真的覆蓋全窗 | 低 |
| P3-5 | 獨立 CLI／排程「自己帶 key 打三站」 | ❌ | — | — | MASTER 明文不做。今日 hash／`/live`／PageSize 再證一次 |

### P4 — 已列、投報較差或要裁決

| ID | 對應 MASTER | 本檔建議 |
|----|-------------|----------|
| T1 launcher 最小啟動 | T1 ⬜ | **仍是單輪最大刀（估 ~16% cache）**，但是唯一有實質風險的一刀。建議排在 P0–P2 之後、單獨一輪 A/B，不要跟 API 配方同一週改 |
| T4 規則分片 | 延後 | 維持延後。完整性測試成本 3–5 天，現在瓶頸不在規則長度 |
| D1 effort | 🗳 | 0812-2200 vs 0811-2200 已量不出差。等使用者定案，本檔不建議再試 |
| D4 無變動快路徑 | 🗳 | 有價值（diff=0 跳過分類），但改執行行為。先讓 P2 postflight 能穩抓「本輪新增＝0」再議 |
| D3 audit「還有 N 組未列出」 | 🗳 | 建議留。0100 分類問題靠它才看得到尾巴 |
| Task 6 固定 collector | ❌ | 維持不做 |
| 用 LLM 產三段式／自動分類 | ❌本檔新列 | 0100 長考 3 分鐘是在**寫稿**，不是在等 API。把寫稿交給小模型會換來錯 BITE／錯分類，比 3 分鐘貴 |

每一週收工條件：用最近一輪已存的 scratch raw **離線 replay**（不動三站）證明格式／lint／閘門；再用下一輪實戰看呼叫次數有沒有下來。

## 六、要使用者拍板的（本檔不自行動）

4. D1／D4 維持等裁決，本檔不預設答案。
