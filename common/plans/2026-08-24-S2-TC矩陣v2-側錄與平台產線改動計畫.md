# 第一部：交換平台 ABC／ENEX（`18`）— 🟢 低風險

## 1.1 為什麼零 schema 改動

`s2_platform_merge.py` 的流程是：候選 JSON → `build()` 產 `{站}-entries.json` ＋
`{站}-pairs.txt` → `add-batch` 入庫 → `set-category --pairs` 分類。

T/C 完全可以**接在同一個位置**：`add-batch` 之後多下一次 `set-tc --pairs`。
候選檔的 `items[]` schema（`id`／`raw_entry`／`source`／`sb_count`／`src_text`／
`category`／`needs_review_note`，見 `s2_platform_merge.py:86-106`）**一個鍵都不用加**。

⚠️ **A9 提醒**：ABC／ENEX 已由使用者訂為**獨立流程、不併入三站掃帶輪**。
本節的 `set-tc` 由跑該獨立流程的 agent 下，不是掃帶輪 agent。

## 1.2 改動清單（3 處，全部低風險）

| # | 檔案 | 改法 | 風險 |
|---|---|---|---|
| 1 | `common/18-交換平台素材整併.md` §7「分類」 | 加一段：整併完除了 `set-category`，再下一次 `set-tc --pairs`；名單只認 `TC-字典.md` | 低 |
| 2 | `s2_platform_merge.py` `build()` | **選配**：若候選檔帶 `tc` 鍵就順便吐 `{站}-tc-pairs.txt`；沒帶就不吐 | 低 |
| 3 | `s2_platform_lint.py` | **選配**：`tc` 存在時驗名（不在字典就 ❌）；不存在時**不報錯**（不是必填） | 低 |

> 第 2／3 項標「選配」是刻意的：**先跑純 B（整併端判、schema 不動）一輪**，
> 確認 `set-tc` 在這條產線上行為正常，再考慮要不要把判斷前移到交件端。
> 交件端的候選檔是 agent 產的、它已經讀過 `src_text`，前移確實更省——但那是第二步，不是第一步。

## 1.3 ⛔ 一定要照抄的既有護欄

`build()` 對分類字串有這道護欄（`s2_platform_merge.py:110-115`）：

```python
bad = [c for c in ";=/" if any(c in p for p in parts)]
if bad:
    raise SystemExit(f"⛔ {i} 的分類含 {'／'.join(bad)}，set-category --pairs 會被切錯\n   原值：{cat}")
```

**T/C 的 pairs 也必須有等價護欄**，分隔符集合要涵蓋 `set-tc` 自己用的那幾個
（`;`／`=`／`,`／`|`，實際依階段 1b 定案的格式）。
精神是**帶原始值明確失敗，不要靜默切壞成假的標籤**。

## 1.4 缺 T/C 怎麼辦：照抄 `uncat` 裁定

`build()` 已有這條裁定（`:78-80`）：

> 沒有 category 的**照樣入庫但進 `uncat`**（分類可以事後補，**素材消失補不回來**）。

T/C 完全套用同一條：**缺 T/C 照樣入庫、列進 `uncat_tc` 回報，不擋入庫。**
render 端有 fallback（有存的用存的 → 跑 `tag_tc()` → 「未分類」），所以頁面不會壞。

# 第二部：CNN／NHK 側錄（`14`）— 🔴 高風險

## 2.1 為什麼這條是唯一要改交件格式的

側錄整併端拿到的是**長逐字稿**（中位數 401 字、最長 1442，0802 實測），
一則三站素材才 150–250 字。整併端判 T/C ＝ 掃帶輪 agent 要重讀 30+ 個單元的全文，
**那才是真的貴**。而交件端（篩選 agent）本來就在逐段做歸位判斷
（`s2_state.py:1183` 硬性要求大分類，沒有就退回 `bad` 不入庫），
順手多判 T/C 幾乎不加成本。

## 2.2 🔴 動工前必須先修的既有靜默失敗

**這一項排在所有事情前面。不修就改格式，等於在一個會靜默吞資料的 parser 上加欄位。**

`s2_state.py:1032-1040` 的擬歸位解析：

```python
segs = [x.strip() for x in re.split(r"→|->", m_home.group(1))]
big = segs[0].strip("= ") if segs else big
mid = segs[1].strip("【】 ") if len(segs) > 1 else ""
sub = segs[2].strip() if len(segs) > 2 else ""
```

**`segs[3]` 以後現在就被靜默丟棄**，沒有 arity 檢查。後果：
舊格式進新 parser ＝沒 T/C、**不進 `bad`、`cmd_add_side` 回傳碼 0**——
看起來一切正常，實際上那批側錄永遠沒有 T/C。

- [ ] **修法**：加 arity 檢查。認得的欄位數以外還有東西 → 明確失敗並印出原值，
      比照 `s2_platform_merge.py:110-115` 的「帶原始值明確失敗」精神。
      ⚠️ `parse_side_txt` **目前完全沒有等價護欄**，這是它跟 `platform_merge` 的成熟度落差。

## 2.3 格式設計：⛔ 不要用位置，要用標籤

**這是本計畫最關鍵的設計決定。**

現行擬歸位行是**位置式**的：

```
擬歸位：======大分類====== → 【中主題】 → 小分題
```

而**小分題是可省略的**（`14:36`、`:87`，`sub = segs[2] if len(segs) > 2 else ""`）。
所以如果 T/C 用 `segs[3]`／`segs[4]`，**省略小分題的那些則就會把 T 讀成小分題**——
靜默錯位，而且錯得很像對的。

- [ ] **採用標籤式後綴**（新舊都能一眼看出）：

```
擬歸位：======大分類====== → 【中主題】 → 小分題 → T:政治,社會 → C:臺灣
擬歸位：======大分類====== → 【中主題】 → T:天災天氣 → C:日本          ← 省略小分題也不會錯位
```

- 解析規則：`→` 切開後，**帶 `T:`／`C:` 前綴的段落抽出來當標籤，其餘照舊按位置解**
- 這樣**舊格式（沒有 T:／C: 段）自然落在「沒有 T/C」的分支**，不需要版本旗標
- 名稱含 `→`／`;`／`=`／`,` 一律明確失敗（2.2 的護欄）

## 2.4 🔴 補標**絕對不能**用 `--overwrite`

`add-side --overwrite` 會**一併蓋掉 `raw_entry`**（`s2_state.py:1191-1192`）——
那是 S2b 子系統存在的目的（人工定稿的逐字內容）。

- [ ] **已入庫的段落要補 T/C，一律走 `set-tc --pairs`**，不走 `add-side`
- [ ] `14` 要明文寫死這條，因為「補標」直覺上會想用 `--overwrite`

## 2.5 🔴 單元 vs item：T/C 必須寫進單元裡的**每一段**

側錄的計數單位是**摺疊後單元**（摺疊鍵 `(src, 大分類, 中主題, 小分題)`，
與 `s2_validate.side_units()`／正式版 JS 同一套語意），一個單元可能是十幾個 item。

但 `set-tc` 是 **per-item** 的。而 render 端 `build_v1.fold_side()`（`:78-97`）
用 `dict(r)` 取**第一列**——**單元內只有第一段有 T/C 的話，其餘全部消失；
第一段沒有、後面有的話，整個單元看起來就是沒標。**

- [ ] **規則寫死**：一個擬歸位區段底下的**所有段落套同一組 T/C**，由 `add-side` 在解析時
      對該區段每一個 item 都寫上，不是只寫第一段
- [ ] `fold_side()` 要改成**取單元內第一個有 T/C 的**，而不是無條件取第一列（藍圖 4d）
- [ ] 驗收要抽一個多段單元，逐 item 確認 T/C 都在

4. 交件者是外部 agent 或人，**不會因為我們改了規則就立刻改行為**

- [ ] **祖父條款（🔴 2026-08-24 Fable 審查修正為兩件，不是三件）**：
  - 缺 T/C 的段落**照樣入庫但列 `uncat`**（`s2_platform_merge.py:78-80` 的裁定：素材消失補不回來）
