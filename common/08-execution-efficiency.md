# 執行效率（省Token）準則

執行本 repo 任何流程（外電批次下載、掐BITE助手、搜尋外電素材RT/AP、找AP照片、自動寫稿(CTV/SOT)、掃帶入庫、自動掐SO 等）時的瀏覽器自動化操作，一律遵守以下準則，目標：瀏覽器工具呼叫減少約60~75%、網頁snapshot回傳量減少約80~95%、整體token使用量降低約70~90%。

各流程另有步驟級省 Token 規則（與本文件併用）：
- CTV：[`cnn/01-auto-script-writing.md`](../cnn/01-auto-script-writing.md)
- SOT：[`common/06-auto-script-sot.md`](06-auto-script-sot.md)
- 掐BITE／CNN掐Bite：[`common/07-bite-assistant.md`](07-bite-assistant.md)、[`cnn/02-clip-bite.md`](../cnn/02-clip-bite.md)
- 掃帶入庫／自動掐SO／搜尋 RT·AP／找AP照片：見對應 `reuters/*`、`ap/*` 文件開頭的省 Token 節

## 準則

- **多用批次工具**：連續的「搜尋→點擊→等待」動作盡量用單次批次呼叫（例如 `browser_batch`）送出，不要每一步都拆成單獨呼叫。只有下一步動作真的需要先看結果才拆開。
- **截圖只在必要時用**：不要每點一次就截圖確認。只有在結果真的無法透過其他方式判斷時（例如第一次遇到陌生UI、不確定點擊是否命中）才截圖或zoom。
- **下載確認改用檔案系統檢查**：判斷下載是否成功，優先用 shell 指令檢查目標資料夾（例如 `Get-ChildItem D:\Downloads`）是否出現對應檔案＋檔案大小，不要用截圖確認。
- **頁面文字只抓一次**：每筆素材的限制/逐字稿只抓一次，抓到後直接寫進對應的文稿txt檔，不要重複抓取，也不要把整段原文貼進對話（除非使用者要求看原文）。
- **不重複貼長清單**：已編號的素材清單或任務清單，完整貼過一次之後，後續只用編號/代號引用，不要整份重新貼出。
- **失敗重試要精簡**：下載失敗（例如 Reuters 常見的503）先直接重點＋用檔案系統檢查結果；只有連續2-3次都失敗，才升級用 network log／accessibility tree 等更花token的診斷工具。

**Why：** 2026-07-20 使用者審視一次RT/AP批次下載+掐BITE任務的實際token消耗，發現主因是每步截圖、每筆素材整段原文貼進對話、清單重複輸出、以及503失敗時的重截圖+查log迴圈；使用者因此明確設定量化的效率目標，並要求往後同類任務都套用這套精簡流程。

**How to apply：** 執行本 repo 任何流程時的瀏覽器操作，預設套用本文件準則；沒有特別情況不需要每次向使用者重新確認。
