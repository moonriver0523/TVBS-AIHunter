## A. 現行版：使用者貼上人工篩選後的側錄內容（2026-08-02 定案，立即可用）

### 觸發

使用者在**晚班交接工作 agent 的對話裡**直接貼上一段或多段 CNN／NHK 側錄內容，要求整合進當日晚班交接。

- 貼進來的是**另一個 agent 依 [`15-歐印萬掃帶.md`](15-歐印萬掃帶.md) 產出的「TC中文大段翻譯」成品**，且**已經過人工篩選與標籤修正**。
- **使用者貼側錄內容＝一定是為了晚班交接**，不是為了掐 BITE（掐 BITE 走 [`07-bite-assistant.md`](07-bite-assistant.md)）。不必再問用途。
- ⚠️ **為什麼需要人工中繼**：歐印萬產出的內容量太大，現階段要靠人工挑出重要段落、修正錯誤角色標籤，AI 才能整併。這是暫時狀態，長期目標見下方 B。

### 分工與交接：篩選 agent 產候選 TXT → 主工作 agent 23:00 整併（2026-08-02 定案）

側錄不由主工作 agent 自己去讀原始逐字稿，改成**兩段式**：

| | 篩選 agent（拋棄式） | 主工作 agent |
|---|---|---|
| 做什麼 | 讀「掃帶歐印萬」的大段翻譯、篩選、轉成定版格式、標好擬歸位，寫成**候選 TXT** | 23:00 最終整併時讀候選 TXT，**貼到對的位置**即可 |
| 為什麼分開 | 18 支大段翻譯約 76KB／2–3 萬 token（0802 實測）。主 agent 的 context 要撐晚班五輪＋隔夜四輪，這些字塞進去**每一輪都會重送**；丟給拋棄式 agent 讀完即棄，只有精煉後的候選跨回來 |

**省 token 的三條硬規定**：

1. **只讀 `{檔名}_TC中文大段翻譯.txt`**——同一支旁邊還有 `_原始逐字稿.txt`、`(雙語對照版).txt`，內容重疊但更長，**不要三種都開**。
2. **候選 TXT 檔頭記錄本次消化過的來源檔名**，下一輪只讀差集（新增的），不重讀已處理過的。差集邏輯照 [`15`](15-歐印萬掃帶.md) 監控模式辦理。
3. **候選 TXT 直接寫成定版格式**：兩行式 ＋ 每則標「擬歸位：`======大分類======` → `【中主題】` → 小分題」。主 agent 只做貼上，不再轉檔、不再判斷歸屬。

**交接用檔案、不用對話**：候選 TXT 落在「掃帶歐印萬」當日子資料夾或 `Claude共用/自動掃帶系統/`，主 agent 23:00 讀一次即可，不要把逐字內容貼進對話往返。

### 📌 暫定辦法（2026-08-03 使用者定案，今日起先這樣跑）

使用者在 **22:00 前**把篩選好的兩個檔放進「掃帶歐印萬」資料夾：

```
G:\我的雲端硬碟\Autopilot\(掃帶歐印萬) 檔名取TC起頭 6位數\{MMDD} CNN側錄.txt
G:\我的雲端硬碟\Autopilot\(掃帶歐印萬) 檔名取TC起頭 6位數\{MMDD} NHK側錄.txt
```

⚠️ 是**沒有 `v2` 的那個資料夾**；資料夾裡的 `Archive` 子資料夾是舊資料，不要讀。

**主 agent 在最後一輪（23:00 最終整併）**做三件事，做完才 render：

1. 讀這兩個檔（**不存在就回報「無側錄」跳過**，不要自己去翻整個資料夾找別的檔）。
2. `add-side` 入狀態檔。⚠️ **上傳側錄的人不一定是規則的作者、也不一定懂格式**
   （2026-08-03 使用者指出），所以**一律先加 `--normalize`**——它做四件純機械的搬移
   （範圍 TC 取起點、冒號去掉成 6 碼、TC 行黏著內容就拆行、內容行開頭的 `（角色）`
   搬到 TC 行；`=== 標題 ===` 這類雜訊行丟掉）。**不改任何一個字**，符合側錄「逐字
   不准動」的鐵律。歐印萬原始檔多半還**沒有來源前綴**，用 `--source` 補；
   歸位用 `--homes` 以 TC 指定，**不必把逐字內容重打一遍**（省 token）：
   ```
   python scripts/s2_state.py --file "…/{MMDD}-s2-state.json" add-side \
     --txt "…/(掃帶歐印萬) 檔名取TC起頭 6位數/{MMDD} CNN側錄.txt" \
     --source CNN --checkpoint "{MMDD}-2200" \
     --homes "天氣/華州野火/州長宣布緊急=160106,160151; 美伊/川普喊卡攻伊/取消攻伊=170203"
   ```
   先 `--dry-run`：它會印出解析到幾段，並**預覽前兩段**（TC 行／內容行／歸位）。
   - **解析到 0 段、或預覽長得不對** → **停下來回報使用者**，不要硬塞進狀態檔，也不要自己動筆改逐字內容。
   - 真的需要重排（例如整份沒有 TC、SUPER 寫成 `主播：` 冒號式）才由 agent 出手，
     且**只准搬位置、不准改字**——側錄的逐字內容一個字都不能動。
3. `s2_render.py` 全量渲染，並核對對帳行的「側錄 M 段」有沒有增加。

歸位（大分類／中主題／小分題）由 agent 判斷，判準同下方「Agent 的工作＝格式轉換＋歸位」。
檔內若已自帶 `擬歸位：…` 行，就不必給 `--homes`。

> 這是**過渡辦法**：篩選仍由人工做（見下方 A 節），agent 只負責入庫與渲染。
> 長期目標是 agent 自主抓取＋自主篩選（B 節，⬜ 未實作）。

### ⚠️ 側錄一定要入狀態檔（2026-08-03 WP1 上線後的硬規定）

晚班交接 txt 自 2026-08-03 起由 `scripts/s2_render.py` **從狀態檔全量渲染**（見 [`13b`](13b-S2-定時掃帶-v2省token.md) §3）。render 是狀態檔的**單向投影**——**狀態檔裡沒有的東西，隔夜下一輪 render 就會把它從 txt 刪掉**。所以側錄不能只貼進 txt，必須入狀態檔：

```
python scripts/s2_state.py --file "…/{MMDD}-s2-state.json" add-side --txt 側錄候選.txt --checkpoint 22:10 --dry-run
python scripts/s2_state.py --file "…/{MMDD}-s2-state.json" add-side --txt 側錄候選.txt --checkpoint 22:10
```

- 吃兩種排版：**候選 TXT**（每則前面帶 `擬歸位：======大分類====== → 【中主題】 → 小分題`），或**直接沿用晚班交接 txt 的三層排版**（大分類／中主題／小分題／`+` 分隔都認）。
- 每段存成一則：`id` ＝ `CNN 160106` 這個 TC 鍵、`source` ＝ `SIDE_CNN`／`SIDE_NHK`、`raw_entry` ＝ **兩行式原文**（TC 行＋內容行，SUPER 照搬）、`category` ＝ 三層歸位。
- **時段標記不存進 `raw_entry`**：render 依 `first_seen_checkpoint` 自動補（`△`／`▲`／`●`），所以 `--checkpoint` 要給實際收錄的時間。
- 已在庫的段落預設**略過不覆寫**（人工定稿過的內容不被後續輪次洗掉），確定要更新才加 `--overwrite`。
- render 端按 `source` 分流排版：通訊社走三段式、側錄走兩行式（不用 `▎`、不壓縮、不設字數上限、TC 冒號格式保留）。0802 實測 68 段側錄往返 **byte 級一致**、隔夜再 render 不消失。

⚠️ **時段範圍（2026-08-02 使用者定案，暫定）**：側錄**目前只收到 23:00 最終整併為止**。[`13`](13-S2-定時掃帶.md) 的隔夜／早班續掃輪次（01:00／04:30／07:00／08:00／10:00／12:00／13:00，2026-08-04 固定排程）**只掃通訊社，不跑側錄篩選**——現階段 23:00 之後不會有新的側錄進來，跑了也是空轉。

**但接口先預留好**（使用者指示：日後可能會有隔夜側錄）：

- 隔夜側錄的**標記沿用通訊社那套**——`▲`＝23:00–07:00、`●`＝07:00–09:00、`◆`＝09:00–14:00（2026-08-04 固定排程定案邊界），加在 `CNN 160106` 這類 TC 行行首（見 [`13`](13-S2-定時掃帶.md)「隔夜續掃」）。`s2_validate.py` 三條 lane 都已支援剝標記，側錄行帶標記不會漏辨識，**腳本不必再改**。
- 要開啟時只需兩個動作：(1) 在指定的隔夜輪次呼叫篩選 agent；(2) 把本節這條「不跑側錄篩選」改成該輪要跑。**流程、格式、檔案位置、差集機制都不用動**。
- 建議開啟時**先只加一輪**（07:00 那輪，標 `●`），讓早班看得到深夜連線即可；全開多半是空轉，因為側錄檔本來就是整點陣發。

### Agent 的工作＝「格式轉換＋歸位」，不是「篩選＋摘要」

篩選已由人工完成，agent 只負責三件事：

1. **轉格式**：把 [`15`](15-歐印萬掃帶.md) 的大段翻譯格式轉成本檔「格式」節的**兩行式**。
   - TC：`16:01:06-16:01:51`（起訖、含冒號）→ **只取起點、去冒號、6 碼**：`CNN 160106`
   - 角色（SUPER）：`（主播）`／`（記者 克里斯·沃倫）` → **維持全形括號、直接接在 TC 同一行後面**（空格分隔）。⛔ **只搬位置、原字照搬**：不改角色、不補缺漏，見下方例外 5
2. **歸位**：判斷正確的 `======大分類======` → `【中主題】` → 小分題，與通訊社素材混排在同一份 txt。
   - ⚠️ **不負責回頭拆段**（2026-08-02 訂正）：講者轉折要切成獨立 TC 段落，是 [`15`](15-歐印萬掃帶.md) **產生大段翻譯當下**就該做完的事（那時才有逐句 ASR 時間戳可用）。S2b 拿到的若有「第二個講者標記嵌在內文中間」沒切開，**照搬並回報**，不要自己硬拆（沒有 TC 可依據，硬拆出來的 TC 是假的）。
3. **分組**：同一小分題下多段 TC **緊貼不空行**；換小分題用**獨立一行 `+`**（沿用 V1 既有小分題分隔規則，非新規則）。

### ⚠️ 與其他規則不同的例外（務必遵守）

| # | 例外 | 說明 |
|---|---|---|
| 1 | **維持逐字，不再壓縮成摘要** | **覆蓋**本檔下方「內容是摘要，不是逐字」的舊定案。理由：下游記者寫稿／掐 BITE 需要精確原話，二次摘要會把可用的原話磨掉 |
| 2 | **不設字數上限** | 通訊社素材的**摘要 150 字硬上限**（見 [`13`](13-S2-定時掃帶.md)「各段的分工」）**不適用側錄段落**，就是要完整逐字 |
| 3 | **不用 `▎` 分段** | `▎畫面：`／`▎BITE：` 是通訊社三段式專屬；側錄走 TC行／講者行／內容行，不寫畫面段與 BITE 段 |
| 4 | **不計入檔頭則數** | 側錄段落**完全不進**「收錄外電共X則」的統計，連「其他」也不算（2026-08-02 訂正）。理由：一段連線常切成十幾個 TC，計進去檔頭會被灌爆。`s2_validate.py stats` 已照此計算 |
| 5 | **SUPER 照搬不改** | 講者標示原封不動，不改角色、不補缺漏，只准把位置從內容行搬到 TC 行（2026-08-02 訂正）。**除非使用者當次明說「允許自行整理 SUPER」**。詳見下方「SUPER 一律照搬」節 |

### ⛔ SUPER（講者標示）一律照搬，不准動（2026-08-02 使用者訂正，覆蓋前一版）

> 🔵 **適用範圍限 A 節**（2026-08-09 加）：本節之所以這麼嚴，前提是「內容已經人工校正過」。
> **C 節的歐印萬自動通道沒有那一關，改走 [C-4](#c-4-️-super-例外這條通道准補強僅限-c) 的准補強規則。**
> 別把這條套到 C 去——那會讓自動通道全部的 `（記者）` 都停在沒有人名的狀態。

**使用者貼進來的 SUPER 是什麼，就照抄什麼**——一個字都不改。

- ❌ **不准改角色**：覺得標成 `旁白` 是誤判、覺得該是 `主播`，都**不准自己改**。貼進來的內容**已經人工篩選校正過**，agent 再動就是竄改。
- ❌ **不准補 SUPER**：TC 行沒有講者標示就**留空**，不准依內容推測「這應該是主播」自己生一個。
- ✅ 唯一准做的是**位置搬移**：[`15`](15-歐印萬掃帶.md) 把 SUPER 寫在內容行開頭，這裡要移到 TC 同一行——**只搬位置，不改字**。

**唯一例外——使用者明說開放**：若使用者在該次對話裡明確表示「**允許自行整理 SUPER**」（或同義的授權，例如「SUPER 你幫我整理」「角色標錯你直接改」），該次即可自行修正角色、補上缺漏的講者標示。授權**只對當次貼上的內容有效**，下一次貼新的側錄內容要重新授權，不得自動沿用。沒聽到這句話就一律照搬。

角色誤判該修沒錯，但那是**上游**的事：[`15-歐印萬掃帶.md`](15-歐印萬掃帶.md) 轉錄階段與人工篩選那一關負責（新聞段落不該出現 `旁白`／`廣告配音`／`群眾`，見 `15` 的講者標記規則）。到了 S2b 這一關，內容視為已定稿。

`s2_validate.py check` 的角色白黑名單與「CNN 缺 SUPER」兩條檢查**已移除**——留著會逼 agent 為了掃過去而改字。

## C. 歐印萬自動通道（2026-08-09 使用者定案，擷取已驗證）

把「掃帶歐印萬」資料夾裡公司自動化系統產出的 `{基名}.wav.txt` **自動**轉成側錄候選，
不再等使用者一段一段貼進對話。**A 節不廢除**——臨時、零星、非歐印萬來源（韓聯社／
CNA 網址那類）仍走 A。

### C-0 三條使用者定案（2026-08-09）

| # | 決定 | 影響 |
|---|---|---|
| 1 | **全收，不篩選** | 作廢 B 節的「三選一硬門檻」。收錄時**以主題分段**；同一主題內若有多個講者段落（先記者解說、後專家解說），**視為兩個小分題**（見 C-3） |
| 2 | **歸位自動匹配** | agent 自行判大分類／中主題，人工發現不對再請 AI 改。**不必事先問** |
| 3 | **小分題由 agent 自己生**，而且**要簡單講** | 用途語即可：`主播BS`／`記者連線`／`專家分析`／`SOT`／`受訪者SOT`……不要寫成一句摘要 |

### C-1 來源檔：一律 `{基名}.wav.txt`，不碰雙語對照版

- ✅ `{基名}.wav.txt` — 中文段是**大段**敘事、TC ＋ 角色齊全，正是本檔要的兩行式來源。
- ❌ `{基名}.wav(雙語對照版).txt` — 逐句破碎，那是**掐 BITE 要原文時**才用的（[`07`](07-bite-assistant.md)）。

⛔ **TC 直接沿用，不准再加偏移**——理由與實測見 [`15`](15-歐印萬掃帶.md)「TC 偏移換算」節的 2026-08-09 訂正。

### C-2 擷取由腳本做，不由模型逐字重打

```
python scripts/s2_side_from_oyw.py --report --out 候選.txt          # 全部
python scripts/s2_side_from_oyw.py --since 16:00 --out 候選.txt      # 只收 mtime 之後的
```

`--since` 的 `HH:MM` 簡寫**算出未來時間就自動退一天**（01:00 那輪下 `--since 23:00`
指的是昨晚）。要明確指定跨夜日期就寫完整的 `MM-DD HH:MM`。
> 其實 `--since` 是**可有可無**的——`add-side` 本來就冪等，每輪全掃再讓它自己略過
> 已在庫的即可，少一個會算錯的東西。`--since` 留著只為省擷取時間。

`scripts/s2_side_from_oyw.py` 只做**純機械擷取**：抓中文段、TC 去冒號取起點、角色括號
配對切出、日期取**來源檔 mtime**。**不篩選、不摘要、不改字**——側錄的逐字鐵律在這一層一樣成立。

⚠️ 三件已經踩過、規則裡必須留著的事：

1. **產生器有三種變體**（2026-08-09 實測 9 支）：`### 中文 ###`＋`文稿`（5 支）／
   `### 中文 ###` 但**沒有 `文稿` 行**（3 支）／**完全沒有 `###` 標頭**，重點摘要 →
   `#####` → `文稿`（1 支）。所以錨點是**兩層**：先找 `### 中文 ###`，找不到才退回 `文稿`。
   只認 `文稿` 會滑到**原文段**，把英文逐字稿當中文收進庫存（本工具第一版的實錯）。
2. **CJK 比例防呆**：擷取到的區塊中文字佔比 < 30% 就整支跳過並回報。上面那個錯就是
   靠這道擋下來的——**兩道防線都要留著**，不要因為錨點修好了就拿掉。
3. **日期一定要取來源檔 mtime，不是執行當下**。dedup 的 id 是 `CNN MM-DD 6碼`，
   6 碼每天會重複；日期標錯的下場不是報錯，是 `add-side` 把新內容當成「已在庫」
   **靜靜略過**——查不出來的漏收。跨夜輪次尤其要注意。

### C-3 分段：先切主題，再切講者

⚠️ **一支檔不等於一個主題**——`163927` 一支裡就有「丹麥 AI 作弊」與「德州資料中心」
兩個不相干的題目。所以順序是：

1. **先按主題切**（同一主題的連續 TC 段歸在同一個 `【中主題】` 下）。
2. **主題內再按講者切小分題**：角色一換就是新的小分題（使用者 C-0 第 1 條）。
   `--report` 會直接印出「角色連續段」，那就是小分題的候選切點，照著標即可。
3. 同一小分題底下的多段 TC **緊貼不空行**；換小分題用獨立一行 `+`。

歸位一律用 `--homes` 以 TC 指定，**不要把逐字內容重打一遍**（省 token）：

```
python scripts/s2_state.py --file "…/{MMDD}-s2-state.json" add-side \
  --txt 候選.txt --source CNN --checkpoint "{MMDD}-HHMM" --normalize --dry-run
```

先 `--dry-run` 看解析段數與預覽，對了再拿掉 `--dry-run`。

## 格式

用的是**晚班交接裡的側錄段落格式**。⚠️ **不是 SB 五行格式**（[`00-寫稿通則.md`](00-寫稿通則.md) §4 那個是寫稿階段輸出 SB 用的）。

⚠️ **2026-08-02 訂正：現行版 A 收的是「逐字」不是「摘要」**——下方原本寫「進庫存的是摘要」是舊定案，已被 A 的例外 1／2 覆蓋。走現行版時**維持逐字、不壓縮、不設字數上限**；只有未實作的長期願景 B（agent 自主篩選）才會需要二次摘要。

**兩行式：第一行「來源 ＋ `MM-DD` ＋ 6 碼 TC ＋ SUPER」，第二行起是內容**
（2026-08-02 使用者訂正取代三行式；**2026-08-09 加入日期**）：

🔴 **日期是必填的**（2026-08-09 使用者要求）：側錄是**跨夜**的，一份晚班交接會同時
含前一天晚上與當天凌晨的段落，**光看 `151542` 分不出是哪一天**。
- 格式 `MM-DD`，例：`CNN 08-09 151542 （主播）`
- `add-side --normalize` 會**自動補**，預設取 `--checkpoint` 的日期；
  檔案自己帶日期時**以檔案為準**（那是上傳者的判斷，不用推算的蓋掉）。
- ⚠️ **跨夜要小心**：凌晨的輪次收到晚上的 TC，多半是**前一天**錄的。
  腳本會警告但**不自動改**——猜錯會寫成錯的日期，而**錯的日期比沒有日期更難發現**。
  確認後用 `--tc-date MM-DD` 指定。
- ⛔ **舊格式（無日期）仍然合法**：歷史上有 141 段是 `CNN 151542`，`SIDE_RE` 必須繼續
  認得，否則它們會在品質掃與統計裡整批隱形、回報的「0 命中」是假的（0802 踩過這個坑）。
  **不要回頭去改舊資料。**

```
CNN 160106  （主播）
美國華盛頓州爆發新一波野火，迫使數千居民緊急撤離家園。消防員正在史波肯郡(Spokane County)搶救三處火場，其中最大的一處名為「Old Trails Fire」。目前已有逾1萬3千戶停電，實際受損程度須待日出後才能確認。
CNN 160151  （記者 克里斯·沃倫）
華盛頓州境內目前至少有10處大型野火延燒中，強烈熱穹頂正加劇野火風險，並帶來破紀錄高溫。
```

- **SUPER＝講者標示**，用**全形括號**寫成 `（{角色}）` 或 `（{角色} {姓名}）`，**跟 TC 同一行**、空格分隔。這與 [`15`](15-歐印萬掃帶.md) 的角色標記寫法一致，轉檔時直接搬上來即可，不必改寫成 `CNN主播` 這種形式。
- **內容另起一行**，逐字照搬，不壓縮（見 A 的例外 1／2）。
- 同一小分題下多段 TC **緊貼不空行**。

NHK 側錄同一套；NHK 常無講者，此時 SUPER 位置可改放**內容小標**或整個省略：

```
NHK 222009  內部慘況（共4張照片）
照片顯示建物牆面崩塌、瓦礫散落，內部同樣崩塌並堵住出入口。警方稱估計 20 至 30 名員工失聯，警消正確認是否仍有人受困。
```

規則：

- **歸位到三層結構底下**：這些段落跟通訊社素材行一樣，掛在 `======大分類======` → `【中主題】` → 小分題 之下。三層標記與完整範例見 [`13-S2-定時掃帶.md`](13-S2-定時掃帶.md)「庫存檔格式」。

- ⚠️ **內容逐字或摘要，看走哪一層**（2026-08-02 訂正）：**現行版 A＝維持逐字**（人工已篩選過，agent 不再壓縮，見 A 的例外 1／2）；**長期願景 B＝需二次摘要**（agent 自主篩選後才寫成摘要）。原始逐字稿一律留在「歐印萬」資料夾。
- **SUPER（講者標示）與 TC 同一行**（2026-08-02 訂正，原本規定寫成獨立下一行，已廢除）：`CNN 160106  （主播）`／`CNN 160151  （記者 克里斯·沃倫）`。全形括號、空格分隔。NHK 這類主播口播為主的常無講者，可改放內容小標或省略。
