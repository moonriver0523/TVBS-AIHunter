### 新開／整併晚班交接：必須整份套樣板（2026-07-31 使用者訂正）

1. **新開** `{MMDD}晚班交接.txt`（當日第一份庫存）時：**先複製整份大分類樣板**再寫 header、再注入素材——**不可**只輸出「今天有稿的大分類」。
2. **沒有素材的大分類也要保留標題列**（`======大陸======` 等），底下可為空（僅保留樣板慣用的空行結構即可）。
3. **增量整併**時同樣維持完整 15 格順序：漏掉的大分類要**補回空殼**，已有內容的只在對應格內增刪中主題／小分題／素材，**不重排大分類順序**。
4. 歸類時對照樣板名稱：例如俄烏戰事／俄羅斯社會影響 → **`======烏俄======`**，不要塞進「話題」只因當日先前沒開該格。
5. ❌ 錯誤：只有「中東、美國、社會…」等有料區塊。✅ 正確：時效 → 大陸 → 關稅 → 美伊 → 中東 → **烏俄** → 美國 → … → 科技 → 娛樂 → 話題（中間空區也在）。
6. 🔴 **「烏俄」大分類的中主題固定只用兩格，每天都套用，不臨場另取名字**
   （2026-08-12 使用者訂正；覆蓋上面「中主題怎麼分尚未定案，暫定由 AI 依內容判斷」
   這條的一般原則——**烏俄是特例，其餘大分類仍照 AI 自行判斷**）：

   | 中主題 | 判準 |
   |---|---|
   | `【烏打俄】` | 烏克蘭（含其盟友如英美武器援助）主動發起的攻擊、反攻、突襲行動 |
   | `【俄打烏】` | 俄羅斯主動發起的攻擊、飛彈／無人機空襲、地面進攻 |

   - 不是前線攻防的烏俄相關素材（外交會談、制裁、國內政情、經濟影響等）
     仍照一般規則自行判斷中主題名稱，**不硬塞進這兩格**。
   - 開新中主題前的 `list-topics` 檢查（見下方「開新中主題前必跑」）對這兩格
     不適用——**看到烏俄前線素材直接用固定名稱，不必先查有沒有開過**。
   - 同一則同時打也反打（互有攻防的綜合報導）→ 依**該則報導的主要敘事方向**判斷，
     不確定就找相似先例（`list-topics --big 烏俄`）比照。

五個要點：

1. **分隔符是 `======{名稱}======`**（前後各 6 個等號，同一行）。範例①② 裡看到的 `\====伊朗=====` 是 Google Docs 匯出的跳脫殘留，**以本樣板為準**。
2. **第一格是機動格**，⚠️ **2026-08-03 使用者訂正：機動格放什麼由使用者在當天「晚班交接」開啟時決定**（0802 決定的是「熊本地震」），**agent 不自行判斷要不要開、也不自行命名**。使用者沒指定就維持樣板原樣的空機動格。所以「開新分類」不是在清單中間插一格，而是使用者啟用最上面這一格。
3. **「美伊」與「中東」的分界**（2026-07-30 定義，2026-08-03 使用者細化為主體歸屬制，見下方「大分類歸位通則」）。
4. **未歸類的進「話題」**（清單最後一格）——但前提是**樣板上已有的格（如烏俄）必須先用對**，不能因為懶得開空格就把該進烏俄的丟話題。
5. **整份樣板必現**（本節上一小節，2026-07-31）：空分類也要放。

### ⭐ 開新中主題前必跑 `list-topics`（2026-08-05 訂案）

```
python scripts/s2_state.py list-topics
```

**要解的是中主題重複的真正成因：agent 每輪獨立命名、看不到既有清單。** 0805 實例——20:00 那輪替基輔攻擊開了【俄襲烏克蘭】，但 16:30 輪已經有【基輔空襲】；兩個名稱都合理，結果分裂成兩個中主題。當天 77 個中主題人工合併後剩 55。**這是「看不到」不是「不想用」。**

- **什麼時候跑**：整併階段、`set-category` 之前。成本近乎零（只讀狀態檔，零瀏覽器呼叫、零 API）。
- **看到什麼**：各大分類底下現有的中主題與則數，排序與 txt 一致（相近名稱已靠攏）。`--subs` 可連小分題一起列。
- **看完要做什麼**：**同一事件已經有名字就沿用，不要另起爐灶。** 只有真的是新事件才開新中主題。

> ⚠️ **這解決不了「命名品質」，只解決「看不見」**。命名規則（中主題該叫什麼）仍在檢討中，見 [`TODO.md`](../TODO.md)「全盤檢討分類問題」。0805 人工整理時歸納出的三條候選判準：①中主題＝**事件或議題，不是地點**（`【雅典棄屍案】`不是`【希臘】`）②同一事件的不同面向收在同一個中主題、用**小分題**細分 ③名稱要能**被下一輪的人猜到**，所以用事件的專有名詞（漢光演習、休達移民）而不是主觀切角。

### 中主題的排列順序：相近名稱自動靠攏（2026-08-05 使用者訂案，render 自動處理）

**agent 不用管這件事**——`s2_render.py` 產生 txt 時會自動重排，你照常設分類即可。

**原本的問題**：中主題順序＝素材**到貨順序**，所以跨輪的相關主題必然散開。0804 實測【歐洲野火】(18:00 到) 與【野火】(22:00 到) 中間隔了 4 個不相干的主題，只因為晚了 4 小時；【亞洲熱浪】【歐洲熱浪】【熱浪】更散在三處。

**現在的做法**：維持到貨順序，但新中主題會插到**名稱最相近的既有中主題**旁邊（共同連續子字串 ≥ 2 字）。

```
前：亞洲熱浪 歐洲野火 南亞洪災 歐洲熱浪 氣候乾旱 野火 火山 熱浪 水患
後：亞洲熱浪 歐洲熱浪 熱浪  歐洲野火 野火  南亞洪災 氣候乾旱 火山 水患
```

- ⚠️ **這只解決「排列」，不解決「重複開中主題」**。`政壇`×8 vs `政治`×22 只共用 1 個字，不會被湊在一起——那是**語意**重複，字面比對做不到，屬 [`TODO.md`](../TODO.md)「全盤檢討分類問題」的範圍。門檻設 2 字是實測結果：1 字太鬆，`美股` vs `亞股`、`政治` vs `政壇` 都會被誤湊。
- **純顯示層**：只動中主題的排列，小分題與素材順序完全不動，內容零增減。
- 📅 **0805 新檔起生效**：`0804` 那份當時正在跑，中途換排列會讓正在看的編輯錯亂，列在 `s2_render.TOPIC_ORDER_SKIP_MMDD` 排除名單裡。已歸檔的舊檔本來就不該重新渲染，這份名單留著剛好保住它們的原始排列。

### 大分類歸位通則（2026-08-03 使用者訂案）

> 🔴 **本節部分內容已知有誤，全盤檢討中（2026-08-04 使用者立案）——照做前先讀這段。**
>
> 使用者 2026-08-04 定調：**`財經（股市）`／`娛樂`／`體育` 是「題材格」，優先級高於地緣格**，理由是**這些主題非常明確、要獨立放**，不能照「越前面越優先」硬套。所以：
> - ✅ **美股歸「財經」是對的**——下方表格「美股 → 美國」那列**是錯的**，不要照做。
> - ✅ 美國體育歸「體育」、好萊塢歸「娛樂」同理。
> - ⚠️ **例外**：財經若涉及**川普政策**（例如關稅）→ 歸 **`關稅`** 或 **`美國`**，不留財經。
>
> 「越前面越優先」這條線性通則描述不了實務（0803 定版 435 則實測，依字面執行會把體育 5 則、娛樂 2 則、財經 5 則、話題 4 則全部判成歸錯，但那些其實都是正確做法）。**層級模型正在重新定義**，見 [`TODO.md`](../TODO.md)「全盤檢討分類問題」節。在那之前：**地緣格之間**的判定（下方主體歸屬制）仍然有效照用，**題材格 vs 地緣格**則依上面三條澄清處理。

**核心規則：清單越前面＝優先層級越高。一個素材同時滿足兩個大分類時，一律放最前面那一個。**

0803 實錯兩例（就是這條規則要防的）：
- ❌ 中國經濟相關 → 丟「財經」　✅ 應歸 **「大陸」**（大陸在財經之前）
- ❌ 美國政治 → 丟「政治」　　　✅ 應歸 **「美國」**（美國在政治之前）

**三個地緣格用「主體歸屬制」判定**（2026-08-03 使用者定義，先判主體再套優先序）：

| 大分類 | 收什麼 |
|---|---|
| **美伊** | 美國與伊朗之間的一切，**以及所有跟伊朗相關的事務**（伊朗國內、伊朗與他國、涉伊制裁／核談判／代理衝突中的伊朗角色） |
| **中東** | **除伊朗外**的所有中東事務——以色列、巴勒斯坦（加薩）、黎巴嫩、敘利亞、海灣國家、埃及等 |
| **烏俄** | 烏克蘭、俄羅斯，**以及美國或他國與烏俄相關者**（軍援、和談、制裁、能源戰） |

- 以色列與伊朗直接衝突 → **涉伊朗，歸「美伊」**（不是中東）。
- 加薩／以巴、黎巴嫩真主黨（未直接涉伊朗時）→ **中東**。
- 歐美對烏俄的外交政治動作 → **烏俄**（烏俄在政治之前）。

**其他高風險重疊配對，一律照「越前面越優先」機械處理**：

| 素材 | ❌ 常見誤放 | ✅ 正確 | 理由 |
|---|---|---|---|
| 中國經濟／中國科技／中共人事／中國社會案件 | 財經／科技／政治／社會 | **大陸** | 大陸最前 |
| ~~美國政治／美股／美國槍案／美國野火~~ ⚠️ **美股那項已作廢** | 政治／財經／社會／天氣 | **美國**（美股除外） | 🔴 **2026-08-04 訂正：美股歸「財經」，不歸美國**——財經是題材格、優先級更高（見本節開頭）。同理美國體育→體育、好萊塢→娛樂。**例外**：涉川普政策（如關稅）→ 關稅／美國。其餘（美國政治／槍案／野火）維持歸美國 |
| 美中貿易關稅、關稅衝擊 | 財經／美國／大陸 | **關稅** | 關稅在三者之前 |
| 颱風／野火／洪水**造成傷亡** | 天氣 | **社會** | 社會在天氣之前；純氣象（預報、高溫紀錄、無傷亡現象）才留天氣 |
| 軟性趣味、迷因、奇聞 | 娛樂／社會 | **話題** | 話題是最後收容格，前面都不符才進 |

> ⚠️ **天氣那列最容易直覺出錯**：社會排在天氣**之前**，所以「有傷亡的天氣災害」依通則歸**社會**，不要因為「這是颱風／野火」就直覺丟天氣。⚠️ 但**地緣格優先於一切**：希臘野火傷亡→仍是社會；**美國**野火傷亡→歸「美國」（美國更前面）。

**整併時發現歸錯**：照 4b「分類修正」規則搬到正確大分類（`set-category` 更新、舊位置的行移除），不要兩邊各留一半。

### T／C 標籤（2026-08-24 上線，A10 v2）

大／中／小三層**完全不動**。T／C 是**另外一條並行的軸**，給晚班交接網頁的矩陣檢視用，不影響 txt、不影響大分類歸位。

**怎麼下**：跟 `set-category` **同一批**下，不要另外找時間補。你判大分類時該則的脈絡還在，順手多judge一組標籤，成本最低。

```
python scripts/s2_state.py --file <state> set-tc --pairs "id1=政治,社會/臺灣;id2=天災天氣/日本"
```

格式 `id=T1,T2/C1,C2`——`/` 左邊是 T（議題）、右邊是 C（地緣），各自可多選、以 `,` 分隔。單側可留空（`id=/日本` 只設 C）。

**三條硬規則**：

1. ⛔ **名稱只認下面這張表**，寫錯會被退回。要加、改、拿掉名稱**只有使用者能決定**，不要自己改程式或自創名稱。
2. ⚠️ **每個 checkpoint 上限 8 次呼叫**（超過硬拒絕）。**整批一次下**，不要逐則呼叫——每次呼叫成本約 $0.07。
3. **判不出來就不要硬掛**：沒下 T/C 的則，網頁會自動退回關鍵詞啟發式或標「未分類」，**頁面不會壞**。硬掛一個錯的比留空更糟。

**查自己標了幾則**：`s2_state.py --file <state> show --fields id,cat,T,C`

> 🔴 **最容易錯的兩個形狀**（0823 實例）：
> ① 賴清德 823 紀念致詞全文用「臺澎金馬」「臺海」、**沒出現「臺灣」二字**，但主體在臺灣 → C 要掛 **臺灣**。

> **判 C 看的是「這則講的地方在哪」，不是字面上出現了哪個地名。**

#### 各產線的 T／C 由誰下（2026-08-25 補齊，A10 v2 收尾）

原本只有三站（AP／RT／NS）在下 T/C，其餘產線的素材進了狀態檔卻沒標——
render 的覆蓋率閘門會把它們算成「還沒標」，網頁上退回關鍵詞兜底。四條產線全部補齊：

| 產線 | 誰下 | 下在哪一步 |
|---|---|---|
| 三站 AP／RT／NS | 掃帶輪 agent | 跟 `set-category` **同一批** |
| 韓聯社／CNA／YouTube（[`17`](17-網址素材整併.md)） | 掃帶輪 agent（**整併端**） | 整併那批進庫後，跟 `set-category` 同批 |
| ABC／ENEX（[`18`](18-交換平台素材整併.md)） | 跑該獨立流程的 agent | `add-batch` → `set-category --pairs` → **`set-tc --pairs`** |
| CNN／NHK 側錄（[`14`](14-S2b-側錄轉譯摘要.md)） | **交件端**（篩選 agent） | 在「擬歸位」行加 `→ T:… → C:…`，`add-side` 解析時自動寫進該區段**每一段** |

⚠️ 側錄之所以下在交件端：整併端要判就得重讀 30 幾個單元的長逐字稿（中位數 401 字、
最長 1442），那才是真的貴；交件端本來就在逐段判歸位，順手多判一組幾乎不加成本。

⚠️ **側錄的 id 帶空白**（`CNN 08-24 160106`），`set-tc --pairs` 吃得下——
`;` 切開後只認第一個 `=`，id 內的空白會原樣保留。**已入庫的側錄要補標一律走
`set-tc`，⛔ 絕對不要用 `add-side --overwrite`**——那會把人工定稿的 `raw_entry` 一起蓋掉。

#### 來源預設 C（2026-08-25 使用者訂）

| 來源 | 預設 C | 例外 |
|---|---|---|
| 韓聯社 `YNA` | **南韓** | 偶有 |
| CNA（新加坡亞洲新聞台） | **新加坡** | 偶有 |
| NHK 側錄 | **日本** | 偶有 |
| CNN 側錄 | **無預設** | CNN 什麼都報，一律照內容判 |

🔴 **「預設」是起點不是終點。** 先讀內容，內容明顯指向他處就照內容判，不要因為
「這是韓聯社」就機械掛南韓：

- 韓聯社報「川普關稅衝擊南韓車廠」→ C 掛 **南韓,美國**（可多選），T 掛 **財經**
- CNA 報「印尼火山噴發」→ C 掛 **東南亞**，**不是**新加坡
- NHK 報「烏克蘭停火談判」→ C 掛 **烏克蘭**，T 掛 **烏俄**

⚠️ **T（議題）沒有預設**，一律照內容判。ABC／ENEX 使用者沒給預設，**不要自創**。

## 各站已知狀況（2026-07-28 三輪實測，細節見 `TODO.md`）

| 站 | 清單抓取 | 稿件完整度判斷 | 已知雷 |
|---|---|---|---|
| **AP** | `get_page_text` 一次穩定拿到；走 `/home` 的 Latest 分頁（空白關鍵字查詢網址會回空白頁） | 上架即有完整 STORYLINE | 清單即時更新會被插隊；彈窗 Close 偶爾點一次沒關乾淨；**SNTV＝體育且編號 `AP5…`（非 `AP4`）**，可收必標 `(SNTV)`；扁平列表文字會把下一則 SNTV 徽章黏到上一則 ID 後——**勿誤標** |
| **CNN Newsource** | 清單可正常截圖讀取 | **有 Script 欄位 ≠ 有正文**，要看有沒有 `--LEAD IN--`／`--VO SCRIPT--`；列尾 `≡🔍` 圖示比「Has Script」篩選器好用（該篩選器點了沒反應）。⚠️ **這只是判斷 `script_status`，不是收錄門檻**——見下方「NS 收錄門檻」 | modal 關閉後畫面會跳回頂端輪播；**清單時間是 GMT+0，不是台北**（見下） |
| **RT** | **清單 `get_page_text` 只抓得到單一卡片，只能靠截圖讀** | 會出現 `SHOTLIST ONLY / TEMPLATE ONLY, COMPLETE SCRIPT TO FOLLOW` | SPA 卡舊快取；**詳情頁用 Previous／Next（‹ ›）連讀**（見下） |

**共同**：清單都是即時更新、新項目不一定加在最上面，**一律用素材編號集合做差集**，不能只看頂端有沒有變。

#### ⛔ NS 收錄門檻：沒稿也要收（2026-08-02 訂正，0802 實錯）

**`≡🔍`／`--LEAD IN--`／`--VO SCRIPT--` 只用來決定 `script_status` 要填 `has_script` 還是 `pending`，不是「要不要收這則」的門檻。**

0802 實錯：整晚 NS 只收到 4 則（14:00輪2／16:00輪1／17:00輪1／之後兩輪掛零），而且**全部 `has_script`、pending 掛零**；同期 RT 收 31 則、有 2 則 pending。Newsource 是穩定上稿的站，連續 4 小時 0 則不合理——研判是把「有沒有正文」當成收錄條件，沒稿的整批跳過沒進庫存。

正確做法（決策 4 本來就這樣寫，NS 沒有例外）：

1. **窗內出現的 NS 素材一律進庫存**，不論有沒有正文。
2. 沒正文的：依 Footage Type／標題／可見資訊寫一句摘要，標 `(稿未到)`、`script_status = pending`，正常歸類。
3. 稿到了再回頭覆寫 `raw_entry`、轉 `has_script`（最終整併的 pending 清查會掃）。

#### 每輪必做的 per-source 數量回報（2026-08-02 新增）

每個檢查點回報時**逐站列出本輪新收幾則**：`本輪新增：AP 4／RT 8／NS 0／YT 3`。

⚠️ **某站掛零時不可靜默略過**，必須加一句佐證：「NS 0 則——已換算 GMT 窗 `09:00–11:00 GMT` 並下捲到窗底，該區間確實無新素材」。三站同時只有一站長時間掛零，通常是**時區換算錯**或**收錄門檻用錯**（上面兩個坑），不是真的沒素材。

### 各站時間／時區（2026-07-31 訂正，必讀）

S2 時間窗一律以**台北時間（+08）**陳述與整併，但**各站介面顯示時區不同**——比對前必須先換算，**不可把畫面數字當本地時間**：

| 站 | 介面時間標記 | 換算成台北（+08） |
|---|---|---|
| **CNN Newsource** | **`GMT` / GMT+0**（例：`31 Jul 26 12:22 GMT`） | **+8 小時**（12:22 GMT → 台北 20:22） |
| **AP Newsroom** | 列表常顯示本地相對時間／站內時鐘（依帳號設定） | 以詳情 Arrival／Creation 為準，**不要假設＝GMT** |
| **Reuters Connect** | Details 常見 `Friday, July 31st, 2026, 19:15`（實務上與台北掃帶窗對得上；若見 `GMT`／`UTC` 字樣再另換） | 見標示；有時區字樣就換算 |

**CNN 換算口訣（不可再犯）**：

- 台北 **19:30–20:30** ⇔ Newsource **11:30–12:30 GMT**
- 台北 **15:13–19:30** ⇔ Newsource **07:13–11:30 GMT**
- 台北 **17:22–19:30** ⇔ Newsource **09:22–11:30 GMT**

❌ **禁止**：看到 Newsource `12:xx` 就當成台北中午、或以為「列表很新所以掃完了」卻其實只掃到 GMT 上午／只抓了最新可見 4–5 則。  
✅ **正確**：先把目標台北窗換成 GMT 窗 → 列表**漸進下捲**收集該 GMT 區間全部 ID → 再與狀態 JSON 差集。

> 2026-07-31 實錯：掃「至 20:30」時未把 Newsource 當 GMT 處理，導致窗內 CNN 幾乎漏掃；已補規則，之後每次 S2 必換算。

#### GMT 只給掃帶 AGENT 用，不進素材行（2026-07-31 使用者訂正）

| 層 | 要不要寫 GMT／上架時刻 |
|---|---|
| **掃帶篩窗／checkpoint／狀態判斷** | **要**（純內部 +8，agent 自己心算／記在狀態 JSON） |
| **素材行 `({備註})`／摘要／`畫面：`／`BITE：`** | **不要** |
| **晚班讀庫存、下游編號／下載／寫稿** | **不需要**靠素材行裡的 GMT |

- GMT 換算是 **S2 agent 進不進本輪時間窗**的內部邏輯，**不是**給編輯看的內容欄位。
- ⚠️ **檔頭也不寫**（2026-08-03 使用者訂正，取代本節原寫的「可寫在檔頭備註」）：舊版曾允許在檔頭附「台北時間；CNN Newsource 列表 GMT 已換算 +8」，現已廢除。檔頭時間窗一律台北時間、不加任何時區備註，與上方「檔頭」節第 4 點一致。
- AP／RT 素材行本來就不寫上架時刻；Newsource **同樣不寫**。
- ❌ `PO-20FR (…；GMT 12:02＝台北20:02) …`／`JL-15FR (…；GMT 11:23) …`
- ✅ `PO-20FR (大衛營 內閣會 資料畫面) …`／`JL-15FR (ICE槍擊 目擊 CLEAN 直式 SOT) …`
- 時間窗以**檔頭「時間窗：」／狀態 JSON** 為準，不必每則重複。

### RT 詳情頁 Previous／Next（‹ ›）連讀（2026-07-31 實測補強；同日晚再升格為鐵律）

S2 或任何需**連掃多則 RT 素材**時，**固定只走這條路徑**（2026-07-31 晚實作連卡兩次後定稿——**不要再發明清單捲動／Load more 路線**）：

#### 標準 5 步（口訣：**列表最新 → 點進去 → Next 往早**）

1. **開 Video 全列表**：My Subscription **ON**、`https://www.reutersconnect.com/all?media-types=vid`（Newest First）。  
   - 等列表渲染完；需要刷新 a11y 時才 screenshot／讀 text。  
   - **讀清單頂端 1 屏即可**（確認最新 Edit No.／時間）——**不要**為了「多抓幾則」去狂按 **LOAD MORE**（見下方禁則）。
2. **點清單最上方（時間最新）那則卡片**進詳情（保留結果集）。進詳情後 URL 宜呈  
   `all?id=tag:reuters.com,…&media-types=vid`（或同等「仍掛在列表結果集」的形態）。
3. **在詳情頁用 Previous／Next（‹ ›）連讀**：aria-label `Previous`／`Next`。  
   - **Next（›）＝往時間更早**；**Previous（‹）＝往更新**。  
   - **反覆 Next** 收集到時間窗下沿（低於截止就停）。  
   - **不要**每則回清單重點下一則。
4. **每則**讀 Edit No.→`RT{4碼}`、Duration、Restrictions／SOURCE（CCTV？）、script 狀態（COMPLETE SCRIPT／TO FOLLOW）、shotlist／BITE；與狀態 JSON **差集**——新則寫 `raw_entry`，已見過只更新 `last_checked_checkpoint`（稿到可覆寫 pending）。
5. **停條件**：Details 時間**低於本輪截止**（或已連續撞上大量已在庫 ID 且時間出窗）→ 停。不要為了湊數再 LOAD MORE。

#### 禁則（卡過兩次的坑——違者重來）

| ❌ 禁止 | 為什麼 | ✅ 改做 |
|---|---|---|
| 在列表狂按 **LOAD MORE**／深捲「多撈舊稿」當主掃法 | 結果集被拉成**隔日舊帶**，頂端最新窗消失，整輪白做 | 頂端 1 屏確認最新 → **立刻點最新進詳情** → Next 往早 |
| `navigate` 到純 **`/detail?id=…`** 或 `search=all:####` 再想 ‹ › | **沒有前頁結果集 → 沒有 Next／Previous** | 一定從 `all?media-types=vid` **點卡片**進 |
| 把 ‹ › 當瀏覽器分頁切換、或清單頁翻頁 | 鍵只在**素材詳情**內有效 | 確認頁上有 `Back to results`／詳情欄再按 Next |
| 只看列表淺色就當「掃完時間窗」 | 淺色＝本 session 看過，**≠** 時間窗已覆蓋 | 以 **Details 時間戳**＋ JSON 差集為準 |
| 最新則用搜尋 Edit No. 單獨開、再手動拼下一則 | 斷結果集、又慢又易漏 | 永遠 **列表最新點進 + Next 鏈** |
