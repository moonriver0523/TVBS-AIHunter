# 初步分析（長片標準流程）

當使用者對一支影片（尤其是長片，例如整小時的新聞台錄影）要求「初步分析」時，依本流程處理，不要直接對整支片子跑完整逐字轉錄。

## 背景

對長片、畫面切換快的新聞頻道錄影直接跑完整逐字轉錄或 `scene_changes` 偵測，成本極高、甚至會超過工具輸出上限（曾發生單支65分鐘素材產出10,000行以上、17萬字以上的 `scene_changes` 結果，直接失敗）。「初步分析」的目的是用很低的成本先給使用者一份可讀的段落/主題總覽，再由使用者指定要深入處理哪些片段。

## 步驟

1. **只跑 silence 結構掃描**：呼叫 `video_analyze`，`filters` 只給 `{"silence": true}`，**不要**加 `scene_changes`（長片、畫面切換快的新聞內容用 `scene_changes` 容易爆量到上萬行）。純 silence 偵測就能給出一份精簡、仍然有用的結構骨架（65分鐘素材約200筆左右，token量落在幾千字級）。
2. **稀疏低解析度取樣畫面**：用 `video_watch`，設定極低的 `fps`（例如 `0.01`，約每100秒取1格）、`skip_audio: true`、低解析度（預設256px）。這一步很便宜，靠畫面上的字卡/下標就能看出各段落主題，不需要轉錄語音。
3. **這個階段不做語音轉錄**——完全不呼叫 Whisper。這一步只看畫面結構與靜音結構，不做內容轉錄。
4. **整理成段落/主題表**：欄位包含相對時間、依 [`02-tc-offset-filename.md`](02-tc-offset-filename.md) 換算後的實際時間、以及依畫面字卡推斷出的主題/描述。這是 Claude 自己的原創摘要工作成果，不是逐字重製來源內容，可以完整寫出並保存。
5. **存檔**：把整理好的段落表存成 `.txt`，放在來源影片**同一個資料夾**（例如來源在 `Claude共用`，分析結果也存在 `Claude共用`，不要另外存到別的位置）。

## 完成後

把段落/主題總覽回報給使用者，並詢問要針對哪個/哪些片段做更深入（取樣語音、逐句引言等級）的後續處理——不要自作主張對整支片子接著做完整轉錄。

## 版權提醒

初步分析產出的段落/主題總覽是 Claude 的原創摘要，可以完整輸出。但使用者後續若要更深入內容，仍套用一般的版權審慎原則（見 [`04-bilingual-subtitle-qa.md`](04-bilingual-subtitle-qa.md) 及各流程文件的版權注意事項）——完整逐字轉錄整支母帶內容仍然不行，只有明確指定的引言/BITE才逐字輸出。
