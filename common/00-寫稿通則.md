# 寫稿通則（跨流程共用規格）

所有會產出文字成品的流程（自動寫稿SOT／自動寫稿CTV／外電掃帶入庫／掐BITE助手／CNN掐Bite）一律套用本文件。

本文件只收**跨流程共用的規格**。各流程的輸出結構、字數上限、譯名標注格式、檔名規則、交付動作**都不在這裡**——那些三套完全不同，見各自的流程文件，不可互相套用。

## 1. 版權原則

- 摘要、完成文稿、段落主題總覽等**一律為原創改寫**，不是逐字翻譯或複製外電稿件。
- **只有明確標示來源的簡短 BITE／SB 引言可以逐字引用**，其餘旁白（OS）皆為改寫。
- **不要在對話中逐字貼出完整外電稿件內文**（shotlist／script／Storyline 全文）。使用者要求特定內容時，摘要或描述結構，僅在必要時引用簡短片段。
- 官方完整稿件（`原始文稿.txt` 等）的存檔屬**內部參考副本，非對外散布**。
- 完整逐字轉錄整支母帶內容不可行；只有明確指定的引言／BITE 才逐字輸出。

## 2. 單位與數值換算

原文出現以下單位時，一律在中文後方括號附上換算值：

| 原文單位 | 換算 |
|---|---|
| 金額（美元等） | 附新台幣換算 |
| 華氏（°F） | 換算攝氏（°C） |
| 英里 | 換算公里 |
| 英尺／碼 | 換算公尺 |
| 風速 | 換算蒲氏風力級數 |

### 數字寫法（2026-07-21 訂定，SOT／CTV 一律適用）

- **數字優先用半形阿拉伯數字**，不用中文數字。
- **「x 萬 x 千」一律簡化為「x.x 萬」**，小數點用半形 `.`。位數更多時依此類推，保留到小數點後一位即可。

| 原始寫法 | 應改為 |
|---|---|
| 五萬七千 | `5.7萬` |
| 九百五十萬三千 | `950.3萬` |
| 兩千三百萬 | `2300萬` |

- 這條的用意是**省字**：字卡與口白都有嚴格字數上限，半形數字每字只算 0.5 個全形字，`950.3萬` 比「九百五十萬三千」省下大量版面，同時更好讀。
- 例外：**成語、專有名詞、法規條號等慣用中文數字的詞不改**（例如「三三制」「九一一」「十八標」）。
- CTV 字卡與 SOT 主標題／次標題的半形標點白名單都已為此放行 `.`，見 [`../cnn/01-auto-script-writing.md`](../cnn/01-auto-script-writing.md) 的 BAR 字卡規格與 [`06-auto-script-sot.md`](06-auto-script-sot.md) 的標題規格。

## 3. 寫稿前先完成事實分層（一次寫對，不靠事後複查）

（2026-07-21 由自動寫稿(CTV) 升為通用，**SOT／掃帶入庫／CTV 一律適用**。）

寫稿前先在內部把原始文稿中的敘述分成四類，再直接依分類寫出成品；**此表不需輸出給使用者**：

| 類別 | 處理方式 |
|---|---|
| **1. 官方／警方已證實** | 可用確定語氣 |
| **2. 當事人／受訪者說法** | 第一次出現時保留「表示／聲稱／發文指出」等歸因，**不可改寫成已證實案情** |
| **3. 畫面顯示但仍有不確定性** | 官方稿若用 `appears`、`seeming`、`looks like`、`allegedly`，中文保留「疑似／看似／據稱」，**不可為了標題或字卡力度改成確定語氣** |
| **4. 未知／未公布** | 明寫「尚未公布／無法確認」，**不可把相鄰的金額、日期、人物或事件自行串成因果或等同關係** |

同時逐項守住原文精度，以下都不可自行簡化成不同事實：

- **金額**是「獲得」還是「失竊」
- **是誰的說法**（官方／當事人／目擊者）
- **身體部位**、**方向**、**先後順序**、**數字**

完成這一步後直接寫出成品；後續只跑字數、格式、TC 等確定性腳本檢查。

## 4. SB 五行格式（全 repo 唯一規格）

**所有會輸出 SB 的流程一律用這個五行格式**——掐BITE助手、CNN掐Bite、自動寫稿(SOT)、自動寫稿(CTV)。各流程**不再自訂 SB 形狀**；唯一會變動的是第 4 行 TC 欄位的寫法。

```text
SB
{職稱} {姓名}
{中文翻譯口白}
{TC欄位}
{英文/原文原句}
```

格式規則：

- 順序固定為：SB → 職稱姓名 → 中文翻譯 → TC欄位 → 英文原文。
- 中文翻譯必須是忠於原意的原創繁體中文翻譯，**不帶「」引號**。
- ⚠️ **「五行」指的是五個欄位的順序，不是「中文翻譯只能佔一行」**（2026-07-21 訂定）：
  - **中文翻譯欄位單行或多行都可以**，全流程一律接受。解析以 **TC 那行為界**：`SB` → 職稱姓名 → 中文（1 行以上）→ TC → 英文原文。
  - ⛔ **真正的鐵則是「不可殘譯」：中文必須完整對應英文原句，絕對不可為了通過字數或版面檢查把翻譯砍成殘句。** 單行或多行只是排版選擇，不影響合格與否。
  - 差別只在**每行字數上限**：**自動寫稿(CTV)** 的完成稿是剪接上字用的字幕稿，每行上限 14 全形字（所以通常會斷成多行）；**SOT／掐BITE助手／CNN掐Bite** 沒有每行上限，可含標點，寫成一長行或分行都行。
  - 詳見 [`../cnn/01-auto-script-writing.md`](../cnn/01-auto-script-writing.md) 的 SB 區塊規格。
- 英文原句**不加任何引號**（不用 `""` 也不用 `“”`）；逐字照抄來源原文，若來源是官方文稿一律以官方文稿為準，**不採信 ASR 文字**。
- 交付給使用者時輸出**純文字五行，不要包在 code fence 裡**（本文件的 code 區塊只是格式示意）。

### TC 欄位寫法（依素材來源，2026-07-21 訂定）

| 素材來源 | TC 欄位寫法 | 範例 |
|---|---|---|
| **有 `#編號` 的素材**（掐BITE方式1／自動寫稿SOT） | `#{素材編號} {TC起}-{TC訖}`，4 碼 `MMSS` | `#03 0033-0044` |
| **CNN 六碼側錄素材**（掐BITE方式2） | `CNN {TC起}-{TC訖}`，6 碼 `HHMMSS`，**已套用檔名 offset 的母帶真實時間** | `CNN 060900-060923` |
| **自動寫稿(CTV)**（CNN Newsource 單支素材） | 純 4 碼 `MMSS-MMSS`，**不加來源前綴**（全篇 SB 都來自同一支片） | `0006-0013` |
| **其他無編號素材**（掐BITE方式3） | 純起訖時間，有 offset 就用 6 碼、沒有就用 4 碼 | `060900-060923` |

⚠️ 本表 2026-07-21 修訂了舊規則「無編號素材一律不帶原始代碼」——**CNN 六碼側錄改為加 `CNN` 前綴**，以便在混來源的稿件裡一眼分辨 TC 屬於哪種時間軸。

範例（有編號）：

```text
SB
智利總統 卡斯特
那些透過非法、不正規且秘密手段越境的人，遲早必須離開我們的國家。
#03 0033-0044
Those who came in through the window in an illegal manner, in an irregular and clandestine manner, sooner rather than later, will be outside our country.
```

範例（CNN 六碼側錄）：

```text
SB
白宮記者 Kevin Liptak
他們不必造成巨大破壞或把船擊沉，就能實質關閉水道，因為船長不願冒險通過。
CNN 060900-060923
They don't have to really cause that much damage or sink them, but they still are able to essentially close the waterway because ship captains are unwilling to take the risk of trying to transit through.
```
