# 2026-07-24 — 加倍轟伊2200

## 來源

- 本案不是「使用者修改稿 vs AI初稿」的事後比對，而是**寫稿過程中的自我複查＋使用者提問**觸發的發現：
  - Claude 先寫出「重寫版」，再與雲端既有「完成文稿」比較優缺點，合併兩版優點另存「融合版」。
  - 融合版交付後，使用者要求「抽看畫面是否跟原始素材符合」，Claude 用 ffmpeg 對每個 `#XX TC` 實際截圖核對，找出 7 處 TC 落點錯誤並修正。
  - 修正後使用者追問：「你覺得寫稿時有缺哪些素材沒有的畫面嗎？我想到可能缺『油價』」，Claude 複查後確認並補充第二個發現。
- 完成文稿位置：`Claude共用\SOT自動寫稿測試\加倍轟伊2200 (1)\`（原版／重寫版／融合版三份並存，皆未覆蓋彼此）。
- 目標長度：300 秒（5 分鐘長SOT）。

## 結果先行

抽看畫面能抓到「TC 標注寫對但落點錯誤」（多半是 AP/Reuters 開頭 5-15 秒版權說明卡擋住實際畫面），以及「畫面根本沒被盤點到」兩種不同層級的問題；使用者主動用常識（「應該有油價畫面吧」）點出的，剛好是後者——**起稿盤點時只看了受訪者引言段落，沒把同一支長素材裡的其他 B-roll 一併列入候選**。

## 規則萃取

- 通用規則（候選，見 `C-006`）：
  1. 起稿盤點階段，用了同一支長素材（尤其 explainer／合輯型）的受訪者段落後，仍要檢查該素材的完整 shotlist，把未用到的獨立 B-roll 區塊也列入候選，不能因為「已經用過這支素材」就跳過其餘部分。
  2. OS 裡出現明確數字/價格轉折句（金額、漲跌、破關卡）時，起稿盤點要主動確認是否有對應畫面來源；若唯一來源是 CNN 六碼側錄的純音檔（無影像），要額外檢查素材清單裡其他素材是否有相關畫面可補，不能讓關鍵句「空畫面」。
  3. 唯一畫面來源是靜態資料照，但 OS 描述的是照片未呈現的動態情節（起火、爆炸瞬間等）時，要留意畫面與文字的一致性；必要時在標注說明字裡註明「資料照」性質。
- 風格偏好：無（本案未涉及風格判斷，純屬事實/畫面核對方法）。
- 單篇判斷：無。
