## 本次錯誤與修正

### 錯誤鏈

1. **驗證器假設 SB 中文永遠只有一行**  
   `scripts/validate_sot.py` 的 `split_ctv_body` 原實作：
   ```python
   if stripped == "SB":
       block = [body_lines[k].strip() for k in range(i + 1, min(i + 5, len(body_lines)))]
       items.append(("sb", block))
       i += 5
   ```
   且驗證只對 `block[1]`（單一 translation）做 14 字上限。  
   一旦中文多行，下一行會被誤當成 TC，英文會被誤當成 OS，整段 FAIL。

2. **寫稿代理為了過驗證反向改壞內容**  
   多行中文無法通過 → 代理把完整譯文壓成 ≤14 字單行 → 中文不完整。  
   同時選了過短 BITE（1 秒）充數，語意碎裂。

3. **流程文件與驗證器對「中文可多行」表述不一致**  
   `cnn/01-auto-script-writing.md` 寫口白「每行」上限 14 全形字（暗示可多行斷行），但驗證器實作只接受單行中文。代理讀文件以為可多行，一跑驗證又被打回。

### 使用者原話（觸發）

> BITE掐太短了 而且中文翻譯不完整

### 正確方向（待其他 agent 正式化，本案不升規）

- BITE 應選語意完整的句子／句組，TC 跟足整句，不要為了湊 SB 段數塞 1 秒碎句。
- SB 中文應完整翻譯英文原句；字數上限是**每一行** ≤14 全形字，不是整段中文只能一行。
- 驗證器若與「每行 14 字」的文件衝突，應改解析器接受多行中文，而不是逼寫稿把內容砍短。
