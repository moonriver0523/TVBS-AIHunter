## 規則成熟度

| 狀態 | 意義 | 是否直接約束寫稿 |
|---|---|---|
| `NEW` | 第一次從修改稿觀察到 | 否；適合時優先嘗試 |
| `REPEATED` | 不同稿件重複出現 | 否；視為強烈風格偏好 |
| `CONFIRMED` | 使用者明確指定為固定做法 | 是；應盡快同步核心流程 |
| `PROMPT` | 已寫入並啟用於核心自動寫稿規則 | 是 |
| `RETIRED` | 已被撤回或新規則取代 | 否 |

規則可因使用者明確指示直接由 `NEW` 升為 `CONFIRMED`；沒有明確指示時，不可因單一案例直接升成通用鐵則。

## 每次比對的固定流程

1. 保存或指向 AI 初稿、使用者修改稿與最終播出版；若完整稿件不適合入庫，至少保存可追溯的差異摘要與代表段落。
2. 逐項比較稿頭、主標、敘事線、OS、畫面、BITE、NS、深度分析、結尾、長度、TC、翻譯與授權標示。
3. 每項好做法分類為：
   - **通用規則**：跨題材可重複，可能升級 Prompt。
   - **風格偏好**：應優先評估，但容許依新聞調整。
   - **單篇判斷**：只留在案例，不升級 Prompt。
4. 把本次發現寫入 [`RULES.md`](RULES.md)，並附案例 ID、理由及成熟度。
5. 若規則升為 `PROMPT`，同步修改 [`../06-auto-script-sot.md`](../06-auto-script-sot.md) 或相應模組，並更新 [`CHANGELOG.md`](CHANGELOG.md)。
6. 檢查索引連結與規則是否互相矛盾；不得只更新其中一處。

## 檔案命名

- 案例 ID：`YYYY-MM-DD-{SLUG}`
- 案例檔：`cases/YYYY-MM-DD-{SLUG}.md`
- 一個案例可以連結外部或專案內的完整稿件，但不可覆蓋原始版本。

## 代理交接要求

新代理接手時，先讀本頁，再只讀與任務相關的有效規則和案例。若發現使用者做法與既有規則衝突，保留兩者、記錄衝突並請使用者裁決；不可靜默覆蓋。
