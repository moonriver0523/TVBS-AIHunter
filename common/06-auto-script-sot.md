# 自動寫稿(SOT)

接續 [`外電批次下載`](../reuters/05-batch-download.md) 下載＋改名完成的一批素材，寫成一篇完整台灣電視新聞稿。**不會自動接續下載流程執行，一定要使用者明確下令才啟動**（避免下載完就自動生成稿子，跳過人工審核判斷內容是否恰當）。

瀏覽器與 AP 照片步驟套用 [`08-execution-efficiency.md`](08-execution-efficiency.md)。找 BITE／TC 一律套用 [`07-bite-assistant.md`](07-bite-assistant.md) 的省 Token 優先序；**本文件下方的找 TC 敘述若與 `07` 不一致，一律以 `07` 為準**（先文稿／既有逐字稿／有 TC 的 transcript，最後才 `video_analyze`；先選句再定位）。

**Rollback：** 省 Token 改寫前舊版見 [`_archive/common/06-auto-script-sot.pre-token-saving-2026-07-20.md`](../_archive/common/06-auto-script-sot.pre-token-saving-2026-07-20.md)。

## 省 Token 核心流程（優先遵守）

1. **盤點表要瘦**：起稿前的內部素材盤點只保留精簡欄位——`#XX 或六碼｜可用畫面一句｜有無 BITE（句數）｜NS 有無｜限制一句｜TC 來源（文稿/transcript/ASR檔）`。**不要**把每份外電文稿全文、整份 ASR、整份雙語逐字稿貼進對話。
2. **文稿只讀檔、不重貼**：官方外電文稿 txt、既有雙語逐字稿、清單檔都以本機/雲端檔案為準；對話只用編號引用。
3. **每支影片最多一次 transcription**：同一 `#XX` 或同一六碼檔，`video_analyze`（`transcription: true`）最多一次；結果可落地 `{檔名} ASR.txt` 供本篇多個 BITE 共用。已有 TC 的 RT transcript／官方文稿就**不要**再跑 ASR。
4. **先抽要出的 BITE 句，再定位 TC**：對齊 [`07-bite-assistant.md`](07-bite-assistant.md)——關鍵字命中後只核對前後約 5 秒；寫稿 context 只留「SB 原文 + TC」對照，不灌整支 ASR。
5. **CNN 六碼**：優先既有雙語逐字稿；無稿才 ASR 一次。候選以五行 SB 輸出 1–2 段即可，不貼整份逐字。
6. **完成稿落檔**：寫入 `{SLUG} 完成文稿.txt`（通常放 Claude共用 的 SLUG 資料夾）。對話交路徑 + 總長度 + 使用的 SB 數／來源編號；不要為了「再給一份」把整篇長稿重複貼兩次。
7. **自補 3 張 AP 照片**：列表卡 ⬇ 直下；無 ⚠️ 不開詳情；對話只回 3 個檔名 + 一句圖說 + 有無限制。

## 開始前必讀

執行本流程前，必須先讀 [`自動寫稿持續校稿索引`](auto-script-learning/INDEX.md) 及其中標為 `PROMPT` 的有效規則。該索引保存使用者逐篇修改後確認的寫稿方法；若本文件與索引中的有效規則衝突，以日期較新的明確規則為準，並在本次任務後修正文檔衝突。

## 輸入

- 一批已下載的影片素材，檔名 `{SLUG} #{編號} {來源}`，與對應編號的文稿 txt（`#01` 影片對應 `#01` 文稿）。
- 素材清單中若另列以 `HHMMSS` 六碼開頭的 CNN 側錄素材，即使沒有 `#編號`，仍屬於本篇可用素材，必須一併盤點。
- 每篇文稿內會說明對應影片中哪個段落是什麼內容；文稿尾端有 **"STORY"** 段落，是平面新聞的背景資訊（可引用關鍵數據/背景解說關鍵情節，但不是可用 BITE 的來源——見下方 BITE 規則）。
- SLUG 與大綱沿用先前的素材清單（優先讀已存的 `{SLUG} 素材清單.txt`，不要重貼整份清單）。

## 鐵則（不可違反）

- **預設內容只能從素材本身擷取**，不可自行以背景知識補充。若使用者明確允許上網搜尋最新資料，才可加入經可靠來源交叉核對的最新文字資訊；不得因此捏造素材中不存在的畫面或 BITE。
- **內容必須嚴格對應正確的素材編號**——寫 OS 畫面或 BITE 時，標注的 `#XX` 一定要是真的來自那個編號的素材，不可張冠李戴。
- **BITE 必須有可核對的逐字來源**：編號素材只能用官方文稿的 `SAYING / SOUNDBITE / SOT` 等明確引言段；CNN六碼側錄則使用對應雙語逐字稿或經影音轉譯定位、可核對的實際發言。文稿尾端 `STORY` 背景段落只是平面新聞背景說明，裡面提到的話即使像 BITE，也不可當成影音中存在的引言。

## 編排原則

- **內容編排順序依照素材清單的順序**（清單裡素材出現的先後）走。
- **各段落篇幅長度分配**可以參考素材清單（例如清單裡摘要篇幅暗示的比重），也可以自行依新聞價值與重大性判斷取捨、調整輕重，不必機械式平均分配。
- 起稿前先完成一份**精簡**內部素材盤點（欄位見上方省 Token 核心）：每支 `#編號` 素材及每段 CNN 六碼側錄都要列到。不得因六碼素材沒有 `#編號` 就漏掉。
- 長篇 SOT 可穿插多段 BITE 與 NATURAL SOUND（NS）建立節奏，但每段都必須有明確素材來源及 TC；NS 也要納入總長度。
- **NS 的書寫格式（2026-07-21 訂定）**：寫成單行 `NS #{編號} {TC起}-{TC訖} {一句說明}`，例如 `NS #01 0050-0053 球員登巴士歡呼`。[`scripts/validate_sot.py`](../scripts/validate_sot.py) 會依此格式自動把 NS 秒數計入總長度；**只寫裸 `NS` 沒有 TC 會被判 `[FAIL]`**，因為無法計時。

## 輸出結構（少用 Markdown 語法，依序輸出）

**格式鐵則：每個段落標題都要包在全形【】裡**（例如「【主播稿頭】」「【主標題】」「【記者OS內文與對應畫面】」），不能只寫裸文字標題。[`scripts/validate_sot.py`](../scripts/validate_sot.py) 的 `extract_section()` 是用文字裡有沒有出現「【」「##」「＃＃」這類標記來判斷段落邊界，沒有【】會抓不到邊界，導致後面所有內容（次標題、OS、SB全部）被誤判成同一個區塊，驗證結果會整批噴錯。可參考 [`2026-07-16-川想擴戰2200-AI初稿.txt`](auto-script-learning/cases/2026-07-16-川想擴戰2200-AI初稿.txt) 這份已歸檔範例的實際格式。

**1. 主播稿頭**：簡潔扼要重點，約 100 字。

**2. 主標題**：最適合當電視新聞與網路新聞的標題，18~19 個全形字元。

**3. 次標題**：依不同內容段落生成 5~8 個，各 18~19 個全形字元。

**4. 記者OS內文與對應畫面**：
- 口語化記者旁白 OS，不要太多贅字。
- 描述畫面時挑衝突性高、好看吸引觀眾的精彩畫面，**務必避免血腥與屍體**。
- 每一處畫面描述都要**完整標注** `#{素材編號} TC{時間戳記} "畫面內容"`（`#XX` 是影片檔編號，TC 是該影片檔的時間戳記）——**即使連續描述同一段素材的畫面，每處也都要完整標注，不可省略**。例：`#01 TC0005 "水柱驅離"`。

**5. 受訪者BITE**：
- BITE 講者不限受訪者，記者／主播的口白（現場連線、棚內播報）只要有可核對的逐字來源，一樣可以當 BITE 使用（見 [`掐BITE助手`](07-bite-assistant.md)）。**這是起稿盤點的主動檢查項，不是備而不用的選項**——沒有官方SAYING／SOUNDBITE標記的素材，也要主動讀一遍記者／主播口白，判斷是否有適合當BITE的句子，不要只因為沒有受訪者引言就直接歸類成「無BITE」。
- 穿插在記者 OS 段落間，**不可放在全篇新聞結尾**——結尾一定要是記者 OS 總結句。
- **SB 五行格式與 TC 欄位寫法依 [`00-寫稿通則.md`](00-寫稿通則.md)**；TC 擷取程序依 [`掐BITE助手`](07-bite-assistant.md)（本流程素材皆有 `#編號`，對應該文件「方式1」）。固定五行格式：

  ```text
  SB
  {職稱} {姓名}
  {中文翻譯口白}（不帶「」引號）
  #{素材編號} {TC起}-{TC訖}
  {英文/原文原句}
  ```

  例：

  ```text
  SB
  智利總統 卡斯特
  那些透過非法、不正規且秘密手段越境的人，遲早必須離開我們的國家。將在未來幾天提出法案勸非法移民離開智利。
  #03 0033-0044
  Those who came in through the window in an illegal manner, in an irregular and clandestine manner, sooner rather than later, will be outside our country.
  ```

- **TIMECODE 一定要核對影片檔的真實時間軸**，絕對不可以寫段落/句子編號代替真實 TC；找 TC 的精確度上限、英文原句不擴寫改寫、**先選句再定位**、每支片最多一次 ASR 等細節，全部依 [`掐BITE助手`](07-bite-assistant.md) 的省 Token 核心與「找 TC 共用原則」。RT 若文稿或網頁 transcript 已有 TC，直接取用、**不要**再跑 `video_analyze`；AP／CNN Newsource 無 TC 時，同一支片 transcription 一次後用關鍵字定位，引言文字仍以官方文稿為準。
- 若素材音軌只有 NATURAL（環境音）沒有人聲，或官方文稿未列出任何 SAYING／BITE 段落，視為**無 BITE 可用**，不可勉強轉譯湊一句。
- **CNN 六碼素材不可只拿來當背景文稿**。清單出現六碼 CNN 主播、記者或受訪者素材時，必須依 [`掐BITE助手`](07-bite-assistant.md) 的「方式2」優先讀既有雙語逐字稿、評估新聞價值並至少提出可用候選（五行 SB 1–2 段即可）；若最後不用，須能說明是內容重複、品質、長度或敘事取捨，不能因漏盤而省略。
- **讀過逐字稿不等於已使用（2026-07-20 訂定）**：清單裡任何寫明「掐一段主播或記者OS當BITE」的來源（不論是否有`#編號`），起稿前讀過該素材的逐字稿只是完成盤點的第一步，**不能就此當作已處理**。交稿前必須在下方「6. 總長度」的腳本檢查之外，額外逐項核對這份清單，確認每個明確要求掐BITE的來源，都能在完成稿裡指出對應的SB區塊、或有明確記錄「不用的原因」。

**6. 總長度**：
- 使用者若明確指定長度，以該長度為目標；未指定時，預設不可超過 2 分鐘（120 秒）。**主播稿頭不計入成稿長度**。
- 總長度＝所有 SB 秒數＋所有 NS 秒數＋記者 OS 預估朗讀秒數（記者 OS 以每分鐘 250 字換算）。畫面若只是覆蓋 OS，不重複計時。
- **交稿前必須用腳本精算總長度，不能只靠人工手算或估讀**。同理主標題／次標題的全形字數也要實際數過，不能憑感覺判斷是否落在18~19字。長篇 SOT 同樣必須控制在使用者目標附近，不因可用 BITE 多就全部塞入。
- **草稿階段不用自己先手算字數/秒數，直接讓腳本抓（2026-07-20 訂定）**：主標題／次標題／總長度是否合格，人工估算很容易估錯又浪費時間——寫草稿時字數/秒數大致抓感覺即可，不必逐字心算，直接跑一次 `validate_sot.py`，看 `[FAIL]` 訊息報的實際字數/秒數再針對性修正，通常比自己先算一輪再跑腳本驗證更快、更準。
- **用 [`scripts/validate_sot.py`](../scripts/validate_sot.py) 做這項精算**：`python scripts/validate_sot.py "{SLUG} 完成文稿.txt" [--target-seconds N] [--videos-dir 素材資料夾]`，會自動檢查主標/次標字數、SB的TC是否有效、總長度加總是否超出目標（並可選擇性用 `ffprobe` 核對TC是否超出實際影片長度）。完稿後、寫入/上傳前跑一次，有 `[FAIL]` 要修正後再跑一次確認通過。

**7. 翻譯人名或地名**：
- 使用台灣地區常用譯名，參考《中央社》慣用譯名。
- 格式：`中文（英文）`，例：墨西哥總統薛恩鮑姆（Claudia Sheinbaum）。

## 8. 完稿後自補三張AP照片

文稿寫完後，**自行**到 AP Newsroom（比照 [`找AP照片`](../ap/02-photo-search.md)，自生關鍵字搜 Photo）找**三張跟這則新聞相關的照片**，**三張要挑不同人物或不同場景**，不要三張都同一個人/同一角度。

**開始搜尋前先測試帳號能否下載**：任選一張搜尋結果嘗試下載，確認流程正常。若下載回傳明確的授權/計量錯誤（例如 `MeterExpired_Shutdown`），代表是帳號下載額度或授權到期，**立即停止，不要再換關鍵字或重試**，直接回報使用者是帳號授權問題。

**找不到事件本身相關的照片時，回報「無事件照片」，不要為了湊滿三張改塞不相關的舊照/背景照片**——湊數犧牲相關性比少一張圖說更不可取。

省 Token 執行：列表卡片 ⬇ 直接下載；**沒有 ⚠️ 就不要開詳情頁**；能 batch 就 batch；對話只回三個最終檔名與一句圖說／有無限制，不貼 Photo Metadata 全文。

檔名規則跟批次下載那套 `{SLUG} #XX {來源}` **不同**，改用**簡短圖說本身當檔名**，固定加上後綴 `（圖／達志影像美聯社）`：

```text
{簡短圖說}（圖／達志影像美聯社）.jpg
```

例：

```text
美國總統川普參加活動（圖／達志影像美聯社）.jpg
伊朗再度與美軍交火（圖／達志影像美聯社）.jpg
```

這一步不需要額外等使用者下令，是自動寫稿流程本身的一部分。完成文稿與照片一併放進 Claude共用 的 SLUG 資料夾（若該資料夾已在批次下載時建立）。

## 9. 使用者修改稿回饋

當使用者拿自己的修改稿與 AI 初稿比對時，依 [`自動寫稿持續校稿索引`](auto-script-learning/INDEX.md) 執行：保存案例差異、萃取規則、標示成熟度並更新變更紀錄。除非使用者只要求口頭分析且明確禁止動作，否則在使用者確認要採用該機制或規則後，必須把結果寫回專案，不能只留在對話記憶中。
