# 歐印萬掃帶（監控／指定翻譯大段／雙語TC稿）

> **狀態：已在用（2026-07 起實測多次）。**
> 定位見 [`12-子系統地圖.md`](12-子系統地圖.md)：與 [`S2b 側錄轉譯摘要`](14-S2b-側錄轉譯摘要.md) 同樣以「掃帶歐印萬」資料夾為素材來源，但**產物粒度不同**——S2b 產出濃縮摘要、直接寫進共用 S3 庫存（`{MMDD}晚班交接.txt`）；本規則產出**完整逐字/翻譯全文**，存成獨立 txt、放在來源音檔旁邊。兩者目前各自獨立運作，本規則的產物可作為 S2b 未來摘要時的上游全文來源，但尚未串接。

## 這個子功能在做什麼

針對 [`01-shared-folders.md`](01-shared-folders.md) 所述「掃帶歐印萬」資料夾裡的側錄音檔（CNN／NHK 等側錄訊號，檔名如 `{記錄人}{來源} {6碼TC}.wav`），提供兩種觸發方式、兩種輸出格式，把整支音檔轉成帶正確母帶 TC 的繁體中文文字稿，存在原始音檔旁邊。

## 觸發方式

1. **指定檔案**：使用者報出檔名（或檔名關鍵字，例如「許岱軒CNN 042918」），並指定格式（「大段」「雙語」或兩者都要）——直接處理該檔。
2. **監控模式**：使用者要求「監控歐印萬」或詢問「資料夾有新的需要翻譯嗎」：
   - **一次性詢問**：列出資料夾差集（比對已有輸出 vs 沒有），回報並視需要處理。
   - **排程監控**：用 `CronCreate` 排一個週期性 job（例如每 15 分鐘，避開整點/半點，見 CronCreate 工具說明的 jitter 建議），prompt 內容重複「列資料夾差集 → 有新檔案就用預設格式處理 → 無新檔案只回一行」的邏輯。
   - ⚠️ **CronCreate 排程是 session-only**：7 天自動失效，session 結束也會消失，**不會跨 session 保留**。要在新 session 恢復監控，需重新呼叫一次 CronCreate（可用下方「重啟監控用 Prompt」）。

## 「已處理」的判斷依據

來源音檔（`.wav`/`.mxf`/`.mp4`）旁邊只要存在**任一種**輸出檔就視為已處理，跳過：
- `{檔名}_TC中文大段翻譯.txt`
- `{檔名}_雙語逐字稿.txt`

⚠️ **處理前務必先檢查是否已有公司自動化系統產生的既有逐字稿**（[`01-shared-folders.md`](01-shared-folders.md) 提到的 `<檔名>.txt` / `<檔名>(雙語對照版).txt`）——那是不同的檔名慣例，若存在且精確度足夠，優先直接引用，不要重新對整支素材跑 `video_analyze`。

（`{檔名}_原始逐字稿.txt`——見下方「原始逐字稿備份」——不算在判斷依據內，單獨存在不代表已處理。）

## 原始逐字稿備份（2026-08-01 起）

**每次處理新檔案時，除了主要輸出格式外，一律額外存一份 `{檔名}_原始逐字稿.txt`**，內容是 `video_analyze` 轉錄出的逐句原文（未翻譯、未濃縮），保留原始時間戳（相對於音檔起點，**不加 TC 偏移**）。

目的：避免日後想補做另一種格式（例如已有大段翻譯，之後想另外做雙語逐字稿）時，需要重新對整支音檔跑一次 `video_analyze`——重新轉錄的 token 成本與第一次幾乎相同。只要原始逐字稿還在，之後就能直接讀檔改寫，不必再轉錄。

```
原始逐字稿(未翻譯/未濃縮)— {檔名}
來源檔案:{檔名}.wav(時長 {mm:ss})
TC 起始偏移:{HH:MM:SS}(依檔名前6碼 {6碼} 換算)
備註:逐句ASR原文,保留原始時間戳(未加TC偏移),供日後製作雙語逐字稿等用途參考。

[mm:ss–mm:ss] {原文}
...（逐句）
```

## 監控範圍的重要限制：只認「監控啟動後新增」的檔案

**排程監控啟動當下，先列一次資料夾現況作為基準線。之後每輪只處理「基準線之後才出現、且尚未有輸出檔」的來源檔案。**

資料夾裡經常存在**監控啟動前就已經沒有輸出檔的舊素材**（例如橫跨數週的舊新聞：世足、伊朗、關稅等舊題材）。這些不是「剛掉進來的新檔案」，**預設一律不自動處理**，除非使用者明確指名要補做。原因：
- 這些舊檔通常代表已經過時、或已透過其他管道處理掉的素材，不代表遺漏。
- 貿然對十幾支舊檔跑完整 `video_analyze` 屬於高 token 成本、且不可逆（一次消耗大量時間與資源）的動作，屬於**要先問使用者**的範疇，不可自行判斷「反正沒輸出檔就是新的」就整批處理。

（2026-07-31 實測案例：啟動監控時發現 18 個橫跨 6/5～7/28 的舊檔沒有輸出檔，經 `AskUserQuestion` 確認後，使用者選擇「只處理往後新增的檔案」，18 個舊檔維持排除狀態。）

## TC 偏移換算

依 [`02-tc-offset-filename.md`](02-tc-offset-filename.md)：檔名前 6 碼 = `HH:MM:SS`，是這支片段在母帶時間軸上的起始時間碼，內部由 0 起算的所有時間戳都要加上這個 offset 才是輸出用的時間碼。

## 兩種輸出格式

### 1. 雙語逐字稿（`{檔名}_雙語逐字稿.txt`）

逐句／逐段中英對照，**中文翻譯在上、原文在下**（依 [`04-bilingual-subtitle-qa.md`](04-bilingual-subtitle-qa.md) 與台灣慣例：中文先）。段落長度依語音停頓自然切分，不強行切成固定長度。

> **格式來源（2026-08-01 使用者定案）**：**檔頭欄位沿用本規則既有寫法**；正文採 Archive 既有雙語文本的做法並**統一飄動處**。Archive 的 12 份 `(雙語對照版).txt` 在講者位置、段落分隔、TC 寫法、括號全半形上並不一致，以下為定版，**不再照抄個別舊檔的變體**。

```
CNN 逐字稿(雙語)— {記錄人}{來源} {6碼}(若接續前一檔案:「接續 {前一檔名}」)
來源檔案:{檔名}.wav(時長 {mm:ss})
TC 起始偏移:{HH:MM:SS}(依檔名前6碼 {6碼} 換算;若接續前檔會註明銜接關係)

### 雙語對照 ###

HH:MM:SS-HH:MM:SS
（{角色} {姓名}） {中文翻譯}
（{原文姓名}） {原文（英文/日文等）}

HH:MM:SS-HH:MM:SS
（{角色} {姓名}） {中文翻譯}
（{原文姓名}） {原文}

...（逐段）

──────────
備註:
1. 主題摘要...
2. 人名/專有名詞不確定時的音譯備註...
```

**各部分規則**

| 部分 | 規則 |
|---|---|
| **檔頭三行** | 沿用本規則既有欄位。接續前檔時標題註明「接續 {前一檔名}」 |
| **`### 雙語對照 ###`** | 檔頭之後、正文之前，獨立一行。（Archive 12 份全部都有，保留） |
| **段落結構** | **三行一組**：TC 行 → 中文行 → 原文行。**TC 獨立一行**（不與講者同行、**不加括號**、不加粗體）；講者標記寫在**中文行與原文行各自的開頭** |
| **講者標記** | 中文行用 `（{角色} {姓名}）`，角色同大段版（新聞內容限 `主播`／`記者`／`受訪者`／`專家`；`旁白`／`廣告配音`／`群眾` 僅限廣告墊檔等非新聞段落，見大段版說明）；原文行用 `（{原文姓名}）`，**一律全形括號**（Archive 有半形 `(Narrator)` 變體，不採用）。無姓名者原文行寫角色英文（`（Crowd）`／`（Narrator）`／`（Ad voice）`） |
| **段落分隔** | 組與組之間**只空一行**。**不要** `---` 水平線（Archive 部分舊檔有，不採用——長帶掃起來太吵） |
| **專名夾原文** | 同大段版：中文行的人名／機構／地名首次出現夾全形括號原文，單位依 [`00-寫稿通則.md`](00-寫稿通則.md) 換算。原文行維持原話，不加註 |
| **廣告／墊檔照收** | 同大段版，保留並標角色 |
| **不要的東西** | ❌ 開頭贅述前言（「以下是融合『中文文稿』與『原文文稿』的…」）；❌ `**粗體TC**`、`**文稿**` 等 markdown 殘留；❌ 只有起點沒有終點的 TC（`(04:56:58)`） |
| **與大段版的差異** | 雙語版**沒有**開頭重點摘要、**沒有**檔尾時間軸（那兩項是大段版專有）；改為檔尾 `──────────` 備註區，列主題摘要與音譯不確定處 |

### 2. TC中文大段翻譯（`{檔名}_TC中文大段翻譯.txt`）

**純中文、大段整理翻譯（非逐句），不附原文**。把多個 ASR 段落合併成較大的敘事段落，濃縮但保留官方公布的具體數字/地名/機構名/引述時間等事實細節（例如死傷人數、震度、機構名稱）。⚠️ **合併僅限同一講者內部**：講者角色一旦有轉折（主播→記者→專家→受訪者等）就必須切成新段落，不可為了敘事連貫把不同講者的話合併進同一段（2026-08-02 訂正，見下方表格）。**這是監控模式下沒有特別指定格式時的預設格式**（雙語逐字稿需使用者另外明確要求）。

> **格式來源（2026-08-01 使用者定案）**：**檔頭欄位沿用本規則既有的五行**（保留 TC 偏移與接續關係，供追溯換算）；**其餘一律改採 Archive 既有大段文本的做法**——開頭重點摘要、`#####` 分隔、TC 與內文同行並標講者、專名首次出現夾原文、檔尾時間軸索引、廣告／墊檔照收。參考樣本見「掃帶歐印萬」資料夾的 `Archive\` 內公司系統產出的 `<檔名>.txt`（非雙語對照版）。

```
{來源} 逐字稿(TC中文大段翻譯)— {檔名}(若接續前一檔案:「接續 {前一檔名}」)
來源檔案:{檔名}.wav(時長 {mm:ss})
TC 起始偏移:{HH:MM:SS}(依檔名前6碼 {6碼} 換算;若接續前檔會註明銜接關係)
內容:{內容摘要一行}
備註:大段整理翻譯(非逐句),僅列中文,不附原文。

- {重點一}
- {重點二}
- {重點三}

#####

HH:MM:SS-HH:MM:SS
（{角色} {姓名}） {中文敘事段落}

HH:MM:SS-HH:MM:SS
（{角色} {姓名}） {中文敘事段落}

...（逐段）

時間軸
- HH:MM:SS-HH:MM:SS （{角色} {姓名}）
- HH:MM:SS-HH:MM:SS （{角色} {姓名}）
...
```

**各部分規則**

| 部分 | 規則 |
|---|---|
| **檔頭五行** | 沿用本規則既有欄位，不變。接續前檔時標題註明「接續 {前一檔名}」（見下方「同一新聞事件的多檔接續」） |
| **重點摘要** | 檔頭之後、`#####` 之前，`- ` 開頭條列。**短帶（單則）4–5 條、長帶（整節）3 條大主題**。每條一句話講完，保留具體數字／機構名（可夾原文，如 `CENTCOM (U.S. Central Command)`） |
| **`#####` 分隔** | 重點摘要與正文之間，**獨立一行五個半形井號**。（Archive 短帶用 `### 中文 ###`／`### 原文 ###`，那是雙語檔的分法；大段檔只有中文，一律用 `#####`） |
| **段落行** | **兩行一組**（2026-08-01 使用者訂正，與雙語版一致）：**TC 獨立一行** → 下一行 `（{角色} {姓名}） {內文}`。TC 用半形連字號相接，**不加括號**、不加粗體。組與組之間空一行 |
| **講者轉折強制分段（2026-08-02 使用者訂正）** | 合併 ASR 段落成大段敘事時，**只要講者身分／角色有轉折就必須另起新段落**（新 TC），即使話題連貫不斷也不能跨講者合併成一段。例如同一則新聞裡「主播 → 記者 → 專家 → 受訪者（SOT）」這種轉場，每次角色切換都是一個分段點。判斷依據＝**講者變了就切**，不是「主題變了才切」 |
| **講者標記** | **每段必標**，全形括號寫在**內文行開頭**（不與 TC 同行）。無姓名或群體聲音只寫角色。<br>⚠️ **角色分兩類（2026-08-02 使用者訂正）**：<br>・**新聞內容只能是** `主播`／`記者`／`受訪者`／`專家`——**新聞段落標成 `旁白` 一律是轉錄誤判，必須改正**（實例：CNN 側錄主播口播被誤標旁白）。<br>・`旁白`／`廣告配音`／`群眾` **僅限**整節帶裡的廣告、節目預告、片頭片尾、現場群體聲等**非新聞內容**。<br>⚠️ **記者 vs 受訪者易混淆，是常見誤判（2026-08-02 訂正，實例：CNN 記者被誤標成受訪者）**：判斷依據看**身分**而非語氣——CNN／NHK 自家編制內的記者做連線／分析／追蹤報導，一律標 `記者`；被記者或主播訪問的**外部人士**（官員、學者、目擊者、當事人等第三方）才標 `受訪者`。同一人若在片段中身分不變，全程標記要一致，不要中途切換。 |
| **SUPER 姓名語言（2026-08-02 使用者訂正）** | 姓名**預設寫英文原名**，例如 `（記者 Amanda Davis）`；**只有知名人物**（有通用中文譯名、台灣媒體慣用中文稱呼者，例如政要、明星、常上新聞的官員）才寫中文，且比照台灣慣用譯名（見 [`00-寫稿通則.md`](00-寫稿通則.md) 川普／普欽等既有慣例）。不確定算不算「知名」時，優先用英文原名，不要自己音譯。此規則**取代**先前「有姓名就寫『記者 阿曼達·戴維斯』」的中文音譯範例。 |
| **專名夾原文** | 人名、機構、地名、專有名詞**第一次出現**時用全形括號夾原文：`費蘭·托雷斯（Ferran Torres）`、`美國中央司令部（U.S. Central Command，CENTCOM）`、`霍爾木茲海峽（Strait of Hormuz）`。同一檔內重複出現不必再夾。單位依 [`00-寫稿通則.md`](00-寫稿通則.md) 換算並夾註：`50至80英里（約80至129公里）` |
| **廣告／墊檔照收** | 整節帶裡的廣告配音、節目預告、跑馬旁白、片頭片尾**保留不省略**，標明角色（`（廣告配音）`／`（旁白）`）。這些是判斷節目段落邊界的依據，刪掉反而難對位 |
| **檔尾時間軸** | 正文之後空一行寫 `時間軸`，其下用 `- HH:MM:SS-HH:MM:SS （{角色} {姓名}）` 逐段列出，**與正文段落一一對應**、順序相同。供快速定位、掐 BITE 時對 TC 用 |

## 同一新聞事件的多檔接續

若新檔案的人名/來源前綴與資料夾內**時間上緊接的前一個檔案**相同，且內容明顯是同一則新聞事件的延續片段（例如熊本地震從第一則緊急快報一路到後續傷亡更新），則：
- 標題註明「接續 `{前一檔名}`」。
- **人名/專有名詞跨檔案維持一致**——若使用者曾針對某個名字給過修正（例如熊本地震專家「酒井慎一」曾被 ASR 誤聽為「坂井真一」，經使用者訂正後，後續所有檔案一律用訂正後的名字）。
- 重複播報的內容（NHK 常見同一則公告播報 2–3 次）只翻譯一次，並註記「此段訊息重複播報」，不逐字重譯。

## 新人名/新來源出現時

若監控中發現的新檔案，其記錄人姓名是資料夾裡**從未出現過**的新名字，處理前先用 `AskUserQuestion` 確認要用哪種格式（大段／雙語／兩者）。**若使用者未回應或直接略過（dismissed）該問題，不處理這批檔案，回報略過並等待下一步指示——不可自行套用預設格式繼續處理。**

## 重啟監控用 Prompt（開新 session 時貼上）

CronCreate 排程不會跨 session 保留，開新 session 要重新監控時，貼下面這段（依需求調整資料夾路徑與週期）：

```
監控資料夾：G:\我的雲端硬碟\Autopilot\(掃帶歐印萬) 檔名取TC起頭 6位數\

步驟：
1. 用 PowerShell 列出該資料夾所有 .wav（也留意 .mxf/.mp4）檔案，作為基準線。
2. 對每個來源音檔，檢查是否已存在對應的 "{檔名}_TC中文大段翻譯.txt" 或 "{檔名}_雙語逐字稿.txt"（只要任一種存在就算已處理過，跳過）。
3. 找出「基準線之後才新增、且尚未有任何輸出檔」的來源音檔，視為新檔案。基準線當下就存在但一直沒有輸出檔的舊素材，預設不處理。
4. 若沒有新檔案：只需簡短回覆一行「本次監控無新檔案」，不要做其他事。
```

## 與 S2b 的關係（避免混淆）

| | 本規則（歐印萬掃帶） | [`S2b`](14-S2b-側錄轉譯摘要.md) |
