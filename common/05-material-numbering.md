# 素材編號

當使用者給一份素材清單文稿（每個素材旁通常附簡短摘要，可當後續步驟的參考索引，不要更動這些摘要），要求把清單裡的外電素材逐一編號時，使用本規則。

**Rollback：** 省 Token 備註加入前舊版見 [`../_archive/common/05-material-numbering.pre-token-saving-2026-07-20.md`](../_archive/common/05-material-numbering.pre-token-saving-2026-07-20.md)。

## 省 Token 與下游銜接（不改編號完整性）

- **編號當下仍須完整輸出一次**（見下方規則 6）——這是審核／防呆鐵則，不可改成只回摘要。
- 完整編號清單輸出並經使用者確認後，下游 [`外電批次下載`](../reuters/05-batch-download.md) 會存成 `{SLUG} 素材清單.txt`；**之後禁止再把整份清單貼進對話**，只用 `#XX` 引用。
- 編號步驟本身幾乎不需瀏覽器；不要為了「好看」截圖或重排版清單。

## 要找的素材類型

- **代碼類**：`AP`／`RT`／`RTV`／`APcctv`／`ENEX`／`ABC` 開頭的字串（例如 `RT6722`、`AP4671347`）
  - **`RTV` 一律正規化為 `RT`**（2026-07-30 訂定）：來源端仍會出現 `RTV` 寫法，辨識時照收，但**寫進清單／稿單／庫存時統一寫成 `RT`**，不保留 RTV。
  - **`APcctv` ＋ 6 碼數字**是 AP 網站上的另一種編碼，**照常收錄**——它跟 `AP` ＋ 7 碼一樣都是 AP 網站素材，只是編碼格式不同。
  - 🚫 **其他前綴的 AP 供稿排除**（`vrb017589`／`stltd029775`／`un010491` 這類 stringer／UGC 供稿商代碼，通常標 `10cr`／`15cr` 點數）：要額外付費，[`S2 定時掃帶`](13-S2-定時掃帶.md) 階段直接排除不錄。
- **組合碼**：格式為 **`{2 英文字母}-{2~3 位數字}{星期兩碼}`**——**這就是 CNN Newsource 的素材代碼**（對應 [`自動寫稿(CTV)`](../cnn/01-auto-script-writing.md) 用的「CNN Newsource ID」），下載時走 CNN Newsource 那條線，不是走 RT 或 AP。
  - ⚠️ **前綴不是只有 `IN`**（2026-07-30 訂正，實測 10 種）：`IN`／`NE`／`TE`／`PO`／`NA`／`MW`／`WX`／`PY`／`SE`／`WE`，日後還可能出現沒見過的兩碼。**判斷依據是格式，不是前綴白名單。**
  - 結尾兩碼是**星期縮寫**（`MO`／`TU`／`WE`／`TH`／`FR`／`SA`／`SU`）。
  - 實例：`IN-07SU`、`PO-35TU`、`WE-018FR`、`MW-002TU`、`PY-03MO`、`NE-002SU`、`IN-116MO`。
- **URL 類**：YouTube URL、X（Twitter）的 URL、Facebook 等社群轉發連結、DVIDS（`dvidshub.net`）影片連結
  - ⚠️ **X 的 `.../status/{id}` 連結不能只看網址字串判斷（2026-07-31 訂正）**：早期規則寫「網址裡有 'Video'/'Photo' 字樣才編號」，但一般貼文分享連結（`https://x.com/{user}/status/{id}`）幾乎都不含這兩個字，導致實際上有影片/照片的貼文被整批漏編、漏下載（「俄炸朝彈2200」案例：5 則 X 連結全部因此被跳過，事後才補編號＋補下載）。**正確做法：把每個 X 連結都打開實際看內容**，再依看到的結果分流：
    - 貼文含 1 支影片 → 一般 `#XX`。
    - 貼文含多支影片（例如輪播 2 支）→ **每支影片各自獨立 `#XX`**，不要合併成一筆；文稿/備註裡註明「同一則貼文第N支，同#XX」互相對應。
    - 貼文含 1 張或多張照片 → 每張各自獨立「圖片編號」`圖#XX`，跟一般素材編號分開計數。
    - 貼文只有文字、沒有影音附件 → 不編號，當背景參考連結留在原文中即可。
  - `.../status/{id}/video/1`、`.../status/{id}/photo/1` 這種帶明確媒體路徑後綴的連結仍可直接判斷（`video`→一般編號、`photo`→圖片編號），可省去開連結確認的步驟；只有純 `.../status/{id}`（無媒體路徑後綴）才需要照上一條實際打開確認。
  - **Facebook 或其他社群平台的影片轉發連結** → 比照 YouTube，當一般素材編號（下載走 [`外電批次下載`](../reuters/05-batch-download.md) 的 `FB` 分派）
  - **DVIDS 影片連結（`https://www.dvidshub.net/video/...`）** → 當一般素材編號（下載走 [`外電批次下載`](../reuters/05-batch-download.md) 的 `DVIDS` 分派，會下載影片本體＋抓詳情頁文稿）

## 代碼對應來源

- `AP` → AP Newsroom（[`搜尋外電素材(AP)`](../ap/01-search-workflow.md)／[`找AP照片`](../ap/02-photo-search.md)）
- `RT`／`RTV`（**輸出一律寫 `RT`**）→ Reuters Connect（[`搜尋外電素材(RT)`](../reuters/01-search-workflow.md)）
- `APcctv` ＋ 6 碼 → AP Newsroom 上的另一種編碼，照常收錄
- **`{2 字母}-{數字}{星期兩碼}` 組合碼**（`IN-07SU`／`PO-35TU`／`WE-018FR`…，前綴不固定，見上節）→ CNN Newsource（[`自動寫稿(CTV)`](../cnn/01-auto-script-writing.md)）
- YouTube／X／Facebook URL → 走 `yt-dlp`／右鍵存圖，見 [`外電批次下載`](../reuters/05-batch-download.md) 的來源分派表
- DVIDS URL（`dvidshub.net`）→ `yt-dlp` 下載影片本體＋詳情頁抓文稿，見 [`外電批次下載`](../reuters/05-batch-download.md) 的 `DVIDS` 分派
- `ENEX`／`ABC` → 目前尚無對應的下載來源／流程說明，**遇到這兩種前綴只做編號，不要自行猜測去哪個網站下載**，下載階段要停下來問使用者。

## 編號規則

1. 一般素材：格式 `#` + 2 位數字，從 `#01` 開始依文稿出現順序遞增。例：`#01 RT6722`、`#12 AP4671347`。
2. 圖片素材（X 的 Photo URL）：格式 `圖#01` 開始，跟一般素材各自獨立計數，互不影響對方的序號。
3. 編號直接標注在該素材代碼/URL 的**前面**，其餘文稿內容一律不動（不重寫摘要、不調整格式、不刪改任何文字）。
4. 同一行可能出現多筆素材（例如 `RT4348 / AP4669867 / AP5464138`），每一筆都要分開各自編號，不算同一筆。
5. **重複素材處理**：同一個素材代碼在清單中第二次（含以後）出現時，不給新編號，改標注 `同#XX`（XX 為該素材第一次出現時拿到的編號）。判斷「重複」是看素材代碼本身是否相同（例如兩次都是 `RT4592`），不是看整行文字是否相同。
6. **輸出必須返還完整原始清單**：從使用者輸入的第一行到最後一行全部原樣保留，只在素材代碼／URL前插入編號。不得只輸出含素材的行、不得改成編號摘要，也不得省略標題、段落說明、人物逐字、新聞連結、文稿參考、空行或其他未編號內容。即使內容很長，仍須返還編號後的完整清單。
7. **驗證編號沒有動到原文**：完成編號後，自行核對「移除新增的 `#XX`／`同#XX`／`圖#XX` 標記後」是否與使用者原始輸入逐字相同——手動謄寫整份清單有漏字/改字風險，能用腳本比對最好，至少要逐段複查一次再輸出，不要只憑印象確認。

## 範例

輸入：

```text
RT4348 / AP4669867 / AP5464138 西班牙球迷在賽前湧入場館、嗨翻天畫面+BITE
RT4639 西班牙國內球迷觀賽嗨翻天畫面+BITE
RT4592 / AP4669917 西班牙球迷慶祝畫面+BITE
AP4669918 維也納球迷對奧地利世界盃輸給西班牙的反應BITE
RT4592
```

輸出：

```text
#01 RT4348 / #02 AP4669867 / #03 AP5464138 西班牙球迷在賽前湧入場館、嗨翻天畫面+BITE
#04 RT4639 西班牙國內球迷觀賽嗨翻天畫面+BITE
#05 RT4592 / #06 AP4669917 西班牙球迷慶祝畫面+BITE
#07 AP4669918 維也納球迷對奧地利世界盃輸給西班牙的反應BITE
同#05 RT4592
```

## 後續銜接

編號完成的清單通常會接續 [`外電批次下載`](../reuters/05-batch-download.md) 進行跨來源批次搜尋、下載與上傳，再接 [`自動寫稿(SOT)`](06-auto-script-sot.md) 寫成完成文稿。
