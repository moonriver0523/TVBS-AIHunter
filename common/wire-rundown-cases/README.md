## 這份範例跟現行 `11-wire-rundown-organizer.md` 規格的落差（先記錄、不自行改規則）

1. **多一層「大主題分類」區塊**：整份清單用 `\====主題=====`（伊波拉／伊朗／以黎／大陸／烏俄／美國政治／政治／財經／社會／天氣／體育／科技／話題）把不同國家/類別分開。現行規格只有「+」分隔同一大主題底下的小主題，**沒有**這種跨主題分類的大區塊分隔語法——這份範例代表定時盯盤累積數小時後，產出的是「跨多個大主題」的整份清單，不是單一主題稿單。
2. **稿頭有時對應多行素材代碼**（例如「法國空拍」底下接連 4 行 RT/AP 代碼），不是嚴格 1 稿頭：1 素材代碼。
3. **重量級連線段落會整段展開翻譯逐字稿，附精確 6 碼時間碼（HHMMSS）**，不是現行規格講的「一句話短摘要」。格式是：`稿頭` → `SB {起始6碼TC}` → `講者頭銜/姓名` → 多段中文翻譯（每段前面各自帶一個 6 碼 TC，标记该段落在原始連線中的位置）。這其實回答了現行規格文件開頭列的**待驗證項之一**：「6 碼 CNN 側錄素材子格式是否適用 BITE／畫面備註標記」——這份範例顯示答案是**適用，而且不只是加 BITE 標記，是整段展開附完整逐段 TC**，比原本猜測的規格更豐富。
4. **`+` 分隔符在這份範例裡的實際用法**（`天氣`主題下「歐火持續」一稿頭底下有兩個 `\+`）：分隔同一稿頭下**不同時間點/不同連線**的獨立段落（例如不同天的連線內容），跟現行規格「`+`分隔不同小主題」的定義一致但用法更細緻——這裡是同一個小主題（歐洲野火）內，不同連線片段之間也用 `+` 分開。
