## 已確認：至少兩種不同用途的產出格式

1. **晚班交接稿單**（範例①②）：格式一致，都是跨主題的 `\====主題=====` 大分類清單，涵蓋當班（14:00–23:00）所有外電摘要，於下班時（23:00）彙整收錄進「晚班交接」。這是「外電摘要」而非完成稿。
2. **單一大新聞掃帶詳單**（範例③，熊本地震）：跟①②結構完全不同——**沒有稿頭**，改用「大分類（依來源：`\=NHK=`／`\=APRT=`／`\=CNN=`）→中主題→小分題」的階層，且每筆多帶**下架/授權時限備註**（例：NHK 180天下架、APRT 可上網不下架）與**製作進度標記**（`----晚班done`／`還沒做`／`---23SOT有塞4張照片但沒有細描`）。這是單一重大事件才會開的深度掃帶記錄，用途是追蹤「這則素材有沒有被用進哪篇完成稿」，跟①②的跨主題彙整是兩回事。

## 使用者 2026-07-28 針對範例①的問答（已釐清）

1. **輕重分流標準**：純素材線索一句話摘要，CNN 連線／記者分析才整段展開附TC——這是外電摘要階段的標準做法，不是特例。
2. **CNN 連線段落不掐 BITE**：這是外電摘要，不是完成稿。CNN 只要「6碼TC＋對應段落摘要」，**不需要掐任何 BITE**（跟現行規則對「6碼 CNN 側錄素材」猜測的「適用 BITE 標記」不同，這點已訂正——摘要階段不掐 BITE，掐 BITE 是下游另一個流程的事）。
3. **稿頭層級**：範例①②其實**完全沒有稿頭**，只有「大分類＋中主題＋小分題」三層，先前判讀成「稿頭」的短標題其實是**小分題**這一層。
4. **大分類清單**：通常固定（伊朗、烏俄因戰況持續是常駐分類），但會隨時事機動增減——例如伊波拉只在近期有疫情時才開，2026-07-28 因熊本地震還多開了一個新分類。
5. **產出時機**：不是逐步即時寫入，而是**晚班（14:00–23:00）整段時間內收到的所有外電摘要，於下班時（23:00）一次彙整收錄進「晚班交接」**文件。

## 待確認（新增，範例③帶出的問題，先記錄不自行定案）

- 範例③的「大分類→中主題→小分題」跟範例①②的「大分類→小分題」是否同一套邏輯，只是③多了一層來源分類（NHK/APRT/CNN）？還是③是完全獨立的另一種文件類型（僅限單一重大突發新聞才開）？
- ③的「下架/授權時限」備註（180天下架、可上網不下架）是否也該套用在①②的一般晚班交接稿單上，或只有側錄非通訊社來源（如 NHK）才需要標？
- ③的「製作進度標記」（晚班done／還沒做／23SOT有塞...）代表這份掃帶詳單會被**持續回頭編輯**（素材用進稿子後回來標記），這跟①②「一次彙整、不回頭改」的性質不同——這種「持續維護的素材追蹤表」是否也是「定時監控模式」要支援的一種輸出型態，或只是既有掃帶入庫流程（見 `feedback_外電掃帶入庫_文稿摘要.md`）的另一種呈現，跟這次要建的「AP/RT/CNN 定時盯盤」其實是兩件不同的事，不要混為一談。
