# TC offset 檔名慣例

適用範圍：任何在 [`01-shared-folders.md`](01-shared-folders.md) 所述資料夾（尤其是「掃帶歐印萬」）裡處理的音檔／影片檔，只要檔名是（或以）數字字串命名，都套用本規則——不限於 CNN 素材，Reuters 素材與 [`掐BITE助手`](07-bite-assistant.md) 同樣適用。

## 規則

檔名的**前6碼數字**代表這支素材在原始母帶（新聞台整段錄影/直播存檔）裡的起始時間碼，解析為 `HH:MM:SS`（每段2碼：時、分、秒）。

- 例：檔名 `041628...` → offset `04:16:28`。分析工具內部回報的 `00:00:00` 要換算成輸出的 `04:16:28`，內部 `00:01:39` 換算成 `04:18:07`，以此類推——把 offset 加到每一個要輸出的時間碼上。
- 若檔名不是可辨識的數字TC字串、或是 `000000`，offset 預設為 `00:00:00`（不做任何偏移）。
- 曾有使用者描述成「8碼數字」規則，但實際範例是6碼（`HHMMSS`）。往後遇到任何數字開頭的檔名一律先取前6碼解析成 `HH:MM:SS`；若真的出現8碼（例如 `HHMMSSFF` 這種含影格數的SMPTE風格），仍只取前6碼做TC offset，其餘碼數忽略。

## 為什麼需要這個換算

這些檔案是從一段更長的母帶（新聞頻道即時監看/存檔）裡剪出來的片段，檔名本身保留了這段片段在母帶時間軸上的起始位置。任何輸出的逐字稿/摘要/引言，時間碼都必須對應母帶的實際時間，而不是這個片段檔案自己從0開始算的內部時間——否則使用者事後對照母帶或原始存檔時，時間碼會對不上、失去查找意義。

## 套用時機

任何流程只要對這類數字檔名的素材產生帶時間碼的輸出（摘要、SB引言、字幕等），都要先從檔名算出 offset，再把 offset 加到每一個要呈現的時間碼上，才把結果交給使用者。
