結論一句話
────────────────────────
NS 有清單 API（POST /api/v3/stories），一次回傳「編號＋形式＋時長＋稿件全文」，
已實測端到端成功。一輪 NS 掃帶從 40+ 次呼叫壓到 2 次，報告的五個卡點同時消滅。
但：僅在 Playwright 瀏覽器可用（原因見下），claude-in-chrome 走不通。

────────────────────────
一、API 規格（實測值）
────────────────────────
端點：POST https://newsource-content-api-530.ns.cnn.com/api/v3/stories
驗證：Authorization: Bearer {JWT}
  - JWT 在 localStorage 的 newsourceSession.token（效期 1 小時，
    頁面開著就會自動 refresh，不用自己續）
Request body（照抄改參數即可）：
  {"bundlesOnly":false,"date":"{ISO時間}","facets":{"contentType":[],
   "videoTypes":[],"categories":[],"digitalCategories":[],"videoFormats":[]},
   "filters":{"contentType":{},"videoTypes":{},"categories":{},
   "digitalCategories":{},"videoFormats":{}},"from":0,"language":["en","es"],
   "scriptOnly":false,"size":20,"sort":{"order":"ascending",
   "type":"relevancyDate"},"term":null}
可用參數：
  - from/size：分頁（size 20 起跳，可加大；窗內通常一頁就夠）
  - scriptOnly:true：只回有稿的（＝UI 上點不動的 Has Script 篩選！）
  - term：關鍵字搜尋
  - date：基準時間

回應格式注意：是「多行 JSON」（NDJSON 式，一行一個物件），
不能直接 r.json()——取含 "stories" 的那一行再 JSON.parse。

每筆 story 的關鍵欄位：
  - alternateIds.bitcentralId ＝ 我們用的 NS 編號（如 PY-04SU、WE-002SU）
  - footageType ＝ PKG／SOT／VO/SIL／RAW／BUTTED SOTS（形式直接給）
  - duration ＝ 毫秒
  - title／description（description 就是現成一句摘要）
  - content.bitcentral.script ＝ 稿件全文 HTML（--LEAD IN--/--VO SCRIPT--/
    --SUPERS-- 標記都在裡面）；hideScript 布林
  - embargo（如 ["THIRD PARTY"]）、categories、createdDate

────────────────────────
二、可直接抄的操作配方（Playwright 瀏覽器）
────────────────────────
步驟 1：browser_navigate 開 https://newsource.ns.cnn.com/landing
        （persistent profile 已登入；開著頁面 token 會自動續）
步驟 2：browser_evaluate 跑一段 JS（讀 token → fetch → 解析 NDJSON）：

() => { const tok = JSON.parse(localStorage.getItem('newsourceSession')).token;
  const body = {bundlesOnly:false, date:new Date().toISOString(),
    facets:{contentType:[],videoTypes:[],categories:[],digitalCategories:[],videoFormats:[]},
    filters:{contentType:{},videoTypes:{},categories:{},digitalCategories:{},videoFormats:{}},
    from:0, language:['en','es'], scriptOnly:false, size:30,
    sort:{order:'ascending',type:'relevancyDate'}, term:null};
  return fetch('https://newsource-content-api-530.ns.cnn.com/api/v3/stories',
    {method:'POST', headers:{'Content-Type':'application/json',
     authorization:'Bearer '+tok}, body:JSON.stringify(body)})
    .then(r=>r.text()).then(t=>{
      const d = JSON.parse(t.split('\n').find(l=>l.includes('"stories"')));
      return JSON.stringify(d.stories.content.map(it=>({
        id: it.alternateIds.bitcentralId, ft: it.footageType,
        dur: it.duration, title: it.title, desc: it.description,
        script: (it.content.bitcentral&&it.content.bitcentral.script)||'',
        embargo: it.embargo, created: it.createdDate}))); }); }

之後照常 diff → 寫三段式 → add-batch，完全不用開任何詳情頁/modal。

────────────────────────
三、為什麼 claude-in-chrome 走不通（別再試）
────────────────────────
1. localStorage/cookie 讀取被 Claude extension 隱私防護擋（就是報告三的
   「[BLOCKED: Cookie/query string data]」，網站沒問題，是 extension）。
2. 頁面裝的 AdBlock extension 會纏住 fetch 鏈，重放 API 直接 Failed to fetch。
→ NS 掃帶若要吃 API 配方，必須用 Playwright 瀏覽器（mcp__browser__* 工具）。
   NS 登入已存在 Playwright persistent profile（2026-08-03 使用者登入）。

────────────────────────
四、附帶更正報告的兩點（若退回 UI 操作仍有用）
────────────────────────
1. 卡點 3「JS 捲不動」不成立：可捲容器是一個「無 class 名的內層 div」
   （scrollHeight ~2800），直接設 element.scrollTop 有效（實測捲到 1814）。
   當時捲不動應是捲了 window/document。
2. 讀整頁 innerText 被 BLOCKED 是 extension 防護，只取特定區塊 innerText 可避開
   （報告已自行發現，這裡確認根因）。

────────────────────────
六、補充（2026-08-03 16:xx，auto mode 攔截與修法，已解）
────────────────────────
上面二節「可直接抄的操作配方」原本的寫法（page.evaluate 讀 token 回傳給 agent 層、
再用 page.context().request.post 帶 token 送出去）被 Claude Code auto mode 的
[Browser JS Exfil] classifier 直接拒絕——那個「讀秘密→agent 自己組請求送到別的
origin」的形狀跟真正的憑證竊取程式碼結構一樣。

修法：整段「讀 token → fetch → parse」都寫在同一個 page.evaluate() 裡，token
全程只活在瀏覽器的 JS engine 內，回傳值只給白名單欄位（id/footageType/duration/
description/script/has_script 等業務資料可以回傳，token/Bearer/Authorization/
JWT/cookie 永遠不准出現在回傳值）。已實測端到端通過（5 筆樣本，200 回應，
輸出完全無敏感字元）。

完整規則與可抄程式碼已寫進 13b §1a-3。這節二的舊配方程式碼仍可用來理解 API
規格（request body／回應結構），但**實際執行時要照 13b 的安全版寫法**，不要
照抄這節二的 fetch 呼叫方式（token 那行的傳遞路徑不同）。
