## V5-1. 掃描順序與輪次

### 順序固定 **NS → AP → RT → ENEX**

ENEX **排最後**，理由跟 `13c §0` 把 NS 排第一是同一件事的反面：

- NS 的 JWT 只有 **1 小時**滑動效期，`13c §0` 讓 NS 第一站是為了讓保活基準點算得準。
- 🔴 **0811-04:30 實錯**：那輪因為人工加掛 ENEX，總耗時 **56.7 分鐘**，
  而輪次中段之後再也沒碰過 NS ——**NS token 在收工前的空窗期悄悄過期**，
  一路斷線到 08:55 才被人工發現補掃。保活撞到掃帶的鎖時是直接放棄、不重試
  （鎖優先序：掃帶 > 保活），所以那一小時完全沒有人續期。
- ENEX 放最後，可以讓「三站跑完」這個時間點盡量早；而
  **`s2_scan_prompt` 收工第 7 步「關瀏覽器前最後再碰一次 NS」在 V5 是硬性的**，
  不是可選項——它就是為了補這個破口而存在的。

### 只有 4 個檢查點要掃 ENEX

| 檢查點 | 掃 ENEX？ | 依據（31 天實測，2026-08-31；01:00／20:00 為 2026-09-02 追加調整） |
|---|---|---|
| **01:00** | ⬜ **跳過** | 2026-09-02 補回排程救 RT 空窗漏收，只補三站，不掛 ENEX（使用者明確下令） |

**跳過的檢查點不用做任何事**——不查、不寫候選檔、回報裡寫一行「本輪不掃 ENEX（V5-1）」即可。ENEX 的「上次掃描 checkpoint」順延到下一個有掃的輪次，窗口會自動涵蓋被跳過的區間，不會漏收，只是延後收錄。

⚠️ **為什麼跳過不會漏收**：台北 08:00–13:00 這 5 小時 31 天只發布 7 則，
但同期間 `creationDate` 落在該區間的有 73 則——**素材是早上做的，
發布中位數延遲 6.1 小時**（最長 37 小時）。掃帶抓的是**發布時間**，
所以那批素材會在 17:00 那輪自然出現，不是被丟掉。

⛔ **時間窗絕對不可以改用 `creationDate`**，那會讓每輪去撈一批「還沒發布」的東西。

### 掃描窗跟三站同一個

ENEX 用**跟三站完全一樣的窗**：狀態檔目前的 `checkpoint` → 現在
（`resume` 看，不要猜），再往前多抓 **10 分鐘緩衝**避免邊界漏收。
緩衝造成的重疊由 `add-batch` 的 id 去重吸收，不會重複入庫。

## V5-2. ENEX API 直查（比照 `13c §1a`，走同一套省 token 原則）

### 端點

| 項目 | 內容 |
|---|---|
| URL | `POST https://members.enex.news/elasticsearch/news/_search` |
| 認證 | **同源 cookie**（Drupal session）。⛔ 不需要 token／Authorization header |
| 呼叫方式 | **整段讀取→fetch→瘦身 全部寫在同一個 `page.evaluate()` 內**（比照 `13c §0-1`／`18` 安全條款） |
| 回應 | 純 JSON，可直接 `r.json()` |
| ⛔ 禁用 | `_mapping`／`_cat`／`_cluster`（proxy 只開 `_search`，其餘回 400） |

### 🔴 `hits.total` 是**純數字**，不是 `{value: N}`

```js
// ⛔ 錯：j.hits.total.value  → undefined（ES 7+ 的慣例在這個 proxy 不成立）
// ✅ 對：
const t = j.hits.total;
const total = (t && typeof t === 'object') ? t.value : t;
```

**2026-08-31 實測**：`match_all` 回的是 `"total": 348127`（整數）。
兩份計畫書的附錄 A-1／A-2③ 與 `18 §10` 的健康檢查範本都寫成 `.value`，
**照抄會拿到 `undefined`**——而且 `JSON.stringify` 會把值為 `undefined` 的鍵
整個丟掉，回傳看起來是空物件 `{}`，很像「查不到東西」。
⚠️ 這條同時影響 `s2_platform_reconcile.py --true-count`（那個數字是你查回來餵進去的）。

### 主查詢（每輪一次，照抄）

```js
// since = 掃描窗起點的 epoch ms（往前多 10 分鐘緩衝）
const body = {
  query: { bool: { must: [ { range: { sortDate: { gte: since } } } ] } },
  size: 100,
  sort: { sortDate: { order: 'desc' } },
  track_total_hits: true,
  _source: ['title','description','partner','category','location','region','country',
            'tags','publishedDate','sortDate','newslinkId','filename','videoLowResCdn',
            'editStatus','status']
};
```

- **`_source` 白名單是省 token 的主力**：不指定會連 `*Suggest` 五個逐字重複的欄位一起回。
- 📌 **`{term:{published:true}}` 可以省**——2026-08-31 實測加不加，7 天都是 590 則，
  索引裡全部都是 published。原規格把它列為必要條件，實際是空操作。
- `size:100` 夠用：實測單輪最多約 27 則（`sortDate` 最忙的 04:30 窗約 19 則）。
  真的滿 100 才用 `search_after`（配 `sort` 的 `sortDate`），⛔ 不要用 `from`。
- **`publishedDate` 與 `sortDate` 實測完全一致**，用哪個都行，統一用 `sortDate`。

### 健康檢查（懷疑登入態時才打，極輕量）

```js
const body = { query:{ match_all:{} }, size:0, track_total_hits:true };
// total ≈ 348,000 且 HTTP 200 → session 正常
```

⚠️ **回 0 筆時第一個懷疑對象不是「站方沒素材」**——先打這支確認 session。
沒登入的話 `_search` 會回 **302**（轉登入頁），不是 401。

### 抽取白名單 `slimEnex()`（在 `page.evaluate()` 裡就瘦完）

```js
const srcShort = (p) => String(p || '').replace(/^[A-Z]{2}\s+/, '').trim();
const slimEnex = (h) => {
  const s = h._source;
  return {
    id:    'ENEX' + h._id,        // 素材代碼，例 ENEX926241（⛔ 不要用 newslinkId）
                                  // 📌 帶前綴是對的；extract 會自己剝（2026-08-31 修）
    nlid:  s.newslinkId,          // 查證備用
    title: s.title,
    desc:  String(s.description || ''),  // ⛔ 逐字保留，不順稿、不改字
    partner: s.partner,           // 原始值（CN CCTV／US CBS…）
    src:   srcShort(s.partner),   // 寫進素材行第一個 () 的媒體簡稱，例 (CBS)
    cat:   s.category,            // ⚠️ 題材分類，**不是**形式，不可拿來當 VO/SOT/PKG
    loc:   [s.location, s.country, s.region].filter(Boolean).join(' / '),
    tags:  s.tags,
    ts:    s.sortDate,            // epoch ms，換台北時間見 13f 時區規則
    file:  s.filename,
    url:   s.videoLowResCdn,      // 🔴 量時長**只能用這個**（公開、免登入、支援 Range）
    estat: s.editStatus,          // PUBLISHING NOW ＝還在上架，沒有 url 屬正常
    dl:    'https://members.enex.news/download/' + h._id   // ⛔ 會員下載頁，**不是影片**，不可拿去 ffprobe
  };
};
```

- **`desc` 就是完整 dopesheet**：STORYLINE／SHOTLIST／引言／講者職銜／限制語全在裡面，
  三段式要的東西不必再開詳情頁。0809 試跑整輪只用 **3 次 `browser_evaluate`**。
- **CCTV 授權樣板**：開頭 `/^\*\*\*[\s\S]*?\*\*\*\s*/` 那段（約 630 字元）每則都一樣，
  可機械剝除，但**剝掉要記 `cctv_license: true`**（那段本身就是使用條件）。
  ⚠️ 剝除**不影響**限制語——真正的限制語 `No access Chinese mainland`
  寫在 SHOTLIST 每段的括號裡，不在樣板內。
- **超長**：`desc` 超過 **8,000** 字元才截斷（`s2_platform_extract.SRC_TEXT_MAX`）。
  🔴 2026-08-31 由 3,000 提高：附錄 A-3 原本寫「最長 2,769，尚未觸發過」，
  實測 48 則裡 **9 則（19%）超過 3,000**、最長 5,634。而 ENEX dopesheet 是
  STORYLINE → SHOTLIST → **SOUNDBITE**，引言在最後面，截斷正好切掉它
  （實測 ENEX928973 的 4 段 SOUNDBITE 只剩 2 段）——而 `18 §2` 明訂
  `src_text` 是事後查證的**唯一依據**與 `sb_count` 的判準。⛔ 不要調回去。
- **時長**：⛔ 不要編、不要猜。用 `url`（`videoLowResCdn`）跑
  `ffprobe -v error -show_entries format=duration -of csv=p=0 "<url>"`，
  或直接讓 `s2_platform_extract.py` 代勞（它內建這一步）。
  **量到的會由 `extract` 自動補成素材行行尾的 `▎MM:SS`**（`with_duration()`，
  2026-09-01 補）——所以 `--entries` 裡的 `raw_entry` **不必自己寫時長**，
  寫了也不會被覆蓋，但 lint 會比對它跟量到的值一不一致。
  🔴 0901-1700（首輪四站）的實錯就是這個洞：ffprobe 23/23 都量到，時長卻只活在
  `enex.duration` 子物件裡，交接單上 25 則 ENEX **一則都沒有時長**，而 AP／RT 都有。

## V5-3. ENEX 的整併路徑：**走 platform 三件套，不走 `add-batch` 直入**

```
slimEnex() 陣列  →  s2_platform_extract.py enex  →  候選 JSON
                 →  s2_platform_lint.py          →  ❌ 就修，不修不准往下
                 →  s2_platform_merge.py --apply --in-round  →  狀態檔
```

### 為什麼不比照三站直接 `add-batch`

- 這三支是 2026-08-26 就寫好並驗收過的既有工具（測試 50／23／9 項全過），
  ENEX 的候選 schema、lint 規則、`needs_review` 記帳都已經在裡面，**不要重寫一套**。
- `s2_batch_prep.py` 的 `--site` 只認 `ns|ap|rt`（11 處硬編），為了 ENEX 去動它
  等於把三站每輪都在用的工具拖下水，風險不對等。

### ⚠️ 這不是 `13c §1a` 那個「dump/build 撤回強制」的坑

`13c §1a` 記過：0812 實測「規定要用 `dump`／`build`」反而更貴，因為要先寫臨時 python
把 `browser_evaluate` 的輸出轉成它吃得下的 schema。**ENEX 這條沒有那個問題**——
`s2_platform_extract.py --raw` 吃的**就是 `slimEnex()` 的原生輸出**，
零轉檔、不需要任何臨時 python。

### 指令（照抄，路徑換掉即可）

```
cd E:/GitHub/TVBS-AIHunter

    --entries "<scratch>/enex_entries_{HHMM}.json"

# ① 機械封裝成候選檔（entries 是你填的編輯判斷：category／sb_count／raw_entry）
python scripts/s2_platform_extract.py enex \
    --raw   "<scratch>/enex_raw_{HHMM}.json" \
    --entries "<scratch>/enex_entries_{HHMM}.json" \
    --checkpoint {CHECKPOINT} \
    --window-start "YYYY-MM-DD HH:MM" --window-end "YYYY-MM-DD HH:MM" \
    --out "<scratch>/{MMDD}-ENEX-state.json"

# ② 交件前 lint（有 ❌ 就停下來修）
python scripts/s2_platform_lint.py "<scratch>/{MMDD}-ENEX-state.json"

# ③ 整併進狀態檔（merge 只做 add-batch ＋ set-category 兩步）
#    中間檔會自動帶輪次（{MMDD}-ENEX-{HHMM}-entries.json），各輪各檔，
#    ⛔ 不需要也不要加 --overwrite（2026-09-01 起；在那之前第二輪起必撞「已存在」）
python scripts/s2_platform_merge.py "<scratch>/{MMDD}-ENEX-state.json" \
    --apply --in-round --file "…/{MMDD}-s2-state.json"

# ④ 🔴 set-tc —— **merge 不會幫你做這步，漏了整批就沒有 T／C**
#    merge 跑完會把「還沒有 T／C 的 id」印出來，照它給的名單下：
python scripts/s2_state.py --file "…/{MMDD}-s2-state.json" \
    set-tc --pairs "ENEX929047=T1,T2/C1;ENEX929039=T3/C2"
```

⛔ **不要跑到 ③ 就停。** `13f:275` 訂的是 `add-batch → set-category → **set-tc**` 三步，
而 `s2_platform_merge.py` 只封裝了前兩步（它是 A9 時代寫的，那時還沒有 `set-tc`）。
⚠️ T（議題）沒有預設，一律照內容判、⛔ 不要自創（`13f:301`）；當天若有機動 T，
符合的素材要**加掛**（連同既有固定 T 一起下，不是取代）——merge 收工時會提醒。

📌 **`18 §1` 那條「不准碰狀態檔」不包含這一步**：§1 的例外是「§7 經過設計的整併出口」，

### `--entries` 的鍵：裸 id 或帶前綴都可以（2026-08-31 起）

`--entries` 是 `{識別碼: {category, sb_count, raw_entry, skip}}`。
識別碼**寫 `929038` 或 `ENEX929038` 都認得**——`extract` 會先正規化。

### 🔴 `--entries` 每欄的形狀（寫之前先看，寫錯＝整份重寫）

```jsonc
{
  "ENEX929213": {
    // ✅ 物件；也可以直接寫 "烏俄/國際外交/莫迪籲普欽止戰" 字串，extract 會拆
    "category": { "大分類": "烏俄", "中主題": "國際外交", "小分題": "莫迪籲普欽止戰" },

    // ⛔ 時段標記 △▲◇◆（舊符號 ■●）不准帶——render 依收錄時間自己補，帶了會變成兩個
    // ⛔ 時長不必寫，extract 量到會自動補 ▎MM:SS（V5-2）
    "raw_entry": "ENEX929213 (SCO峰會) (BITE) ▎摘要▎畫面：…▎BITE：…"

> 寫成字串、`raw_entry` 帶了 `△`，寫完整份 23 則（118 秒）才被 lint 吐 51 項必修，
> 只好**整份重寫**（再 100 秒），第二次又被 4 則的 `🟡` 卡住。
> 事後三邊都修了：`category` 字串**現在直接收**、`🟡` 開頭本來就合法（是 lint 的
> 誤判，已修）、`△` 與 `sb_count` 型別由 ⓪ 的預檢在**寫完當下**就擋。
> ⚠️ 預檢報的都是**形狀**問題，改完只要動出問題的那幾筆，**不必重寫摘要**。

### 🔴 `--raw` 餵整包也可以（2026-09-01 起）

瀏覽器回傳被卸載成檔案時是 `{"total":…, "count":…, "items":[…]}` 這種**包一層**的形狀。
`--raw` 現在會自動拆 `items`／`hits`／`rows`／`results`，**不必先手工剝殼**。

> 🔴 同樣是 0901-2000 實錯：整包餵進去 → 迭代到 dict 的鍵（字串）→
> `AttributeError: 'str' object has no attribute 'get'` 整支掛掉，
> agent 還得回頭 grep 原始碼才看懂。現在會自動解包；真的餵成字串陣列時，
> 也改成逐筆記進 `dropped`（指名第幾筆與型別），不再整支崩。

> 🔴 **為什麼要特別寫這句**：2026-08-31 用 48 則真實素材實測，
> 這裡原本是個會**無聲吃掉整輪**的坑：`slimEnex()` 產的 `id` 帶 `ENEX` 前綴，
> 而 `extract` 當時假設是裸 id。照文件餵裸鍵 → 一則都對不上 → 48 則全進 `dropped`
> → 候選檔空的 → **extract 離開碼 0、lint 也 0**，整輪 ENEX 收 0 則卻沒有任何一處會叫。
> 已修成兩邊都容忍，並補了迴歸測試（`test_s2_platform_extract.py`）。

### 🔴 `--in-round` 是 V5 專用，非它不可

`s2_platform_merge.py` 預設在 `--apply` 前會檢查 `%USERPROFILE%\.s2-scan.lock`，
存在就中止（`exit 1`）。那條護欄是給**人工流程**用的，防的是「獨立流程跟排程輪同時
寫沒有檔案鎖的狀態檔、互相靜靜蓋掉」（`18 §0` 記過 0810 一次 44 處差點被覆蓋）。

但**掃帶輪自己從頭到尾握著那把鎖**（`s2_scan.ps1` 在叫 claude 之前就用
`FileShare::None` 開檔，一路握到 finally）。所以在輪次內呼叫，**護欄會 100% 誤擋**。
`--in-round` 就是明說「我就是那個握鎖的人」而略過這道檢查。

⛔ **人工流程永遠不要加 `--in-round`**——那道護欄對人工流程仍然必要。

### ⛔ checkpoint 一律寫 `{CHECKPOINT}`，一個字都不能改

候選檔的 `--checkpoint` 與每筆的 `first_seen_checkpoint` **必須是
`{MMDD}-{HHMM}` 這個完整格式**（例 `0901-0430`），⛔ 不要寫成 `04:30`
或視窗的講法。

**A14 實錯**：0818-2000 那輪 agent 把 checkpoint 填成查詢視窗的講法，
`first_seen_checkpoint` 就以錯誤格式入庫，外層 `s2_scan.ps1` 用精確比對算
「本輪新增」時**全部漏算 → 報 0 則**，喊出「三站都進不去」的假警報。
那個警報是用來抓真正的無聲全失敗的，**一旦會喊狼來了，真的失敗那天就會被當雜訊**。

### 對帳（ENEX 版）

`s2_audit.py` 的三站對帳**不涵蓋 ENEX**。ENEX 用自己那支：

```

`<N>` ＝ 用上面「健康檢查」那個查詢、把 `match_all` 換成本輪的時間窗、
