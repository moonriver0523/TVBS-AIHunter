## 0. 這件事的定位

- ⚠️ **人工下令才跑，不進固定掃帶排程**（2026-08-09／2026-08-10 使用者訂）。
  固定輪的 agent 讀 [`13b`](13b-S2-定時掃帶-v2省token.md)，**那裡沒有這兩站，就不要自己跑去掃**。
- **一則素材＝一則**，計進檔頭則數（跟 AP／RT／NS 一樣，不是側錄）。
- 素材行的通用格式、括號職能、摘要 150 字上限等，
  **以 [`13-S2-定時掃帶.md`](13-S2-定時掃帶.md)「素材行的寫法」為母規則**；本檔只寫**額外**或**更嚴格**的部分。
  兩者衝突時以本檔為準（本檔是特例、13 是通則）。
- **影片下載兩站都還沒打通**——只做掃帶與摘要，要下載就停下來問使用者，
  ⛔ 不要自行猜測去哪裡抓（見 [`05-material-numbering.md`](05-material-numbering.md)）。

## 1. ⛔ 絕對不要做的四件事

1. **不要改狀態檔 `{MMDD}-s2-state.json`。**
   自動掃帶每 2 小時一輪、一輪約 19 分鐘，那個檔**沒有檔案鎖**——寫入的當下若掃帶輪正在寫回，
   那幾則會**靜靜消失且不會報錯**。只寫候選檔（§2）。
   📌 **例外＝§7 的整併出口**（2026-08-31 補、2026-09-01 補完）：
   `s2_platform_merge.py --apply` 是**經過設計的整併出口**，每次呼叫 `s2_state.py`
   之前都重查一次鎖檔，所以它不是繞過本條，而是本條的**唯一合規實作**；
   緊接其後的 **`s2_state.py set-tc`**（`13f:275` 訂的第三步，merge 沒封裝）
   同屬這個出口的必要收尾，**一併不在禁令內**。
   除這條路徑以外仍然一律不准碰狀態檔，⛔ 更不要自己寫臨時 python 去改。
2. **不要下載影片、不要存檔案。** 只要文字。
3. **不要自己 render**，也不要碰 `{MMDD}晚班交接.txt` 與 `.html`。整併由主線負責。
4. **不要 `git commit` / `push`。** 規則要改就回報，由主線改。

### 安全條款（與 `13b §1a-3` 同一條，不可放寬）

- **整段「讀 token／CSRF → fetch → parse」必須寫在同一個 `page.evaluate()` 內。**
  ABC 的 `__RequestVerificationToken` **每輪從 DOM 現讀**（`input[name=__RequestVerificationToken]`），
  ⛔ 不可寫死、不可回傳到 JS 之外。
- **回傳值黑名單**：`token`／`Bearer`／`Authorization` header／完整 JWT／cookie 字串，一律不得出現在工具回傳裡。
- ⛔ **不要用 `page.context().request.*`** 打帶憑證的請求；一律走同源 `fetch`。
- 一律用 Playwright `mcp__browser__*`，**不可用 `claude-in-chrome`**（那是另一個 profile，登入態不同）。

## 2. 交件位置與候選檔格式

```
G:\我的雲端硬碟\Claude共用\自動掃帶系統\_待整併\{MMDD}-ENEX.txt          ← 人看的
G:\我的雲端硬碟\Claude共用\自動掃帶系統\_待整併\{MMDD}-ENEX-state.json   ← 整併用
G:\我的雲端硬碟\Claude共用\自動掃帶系統\_待整併\{MMDD}-ABC.txt
G:\我的雲端硬碟\Claude共用\自動掃帶系統\_待整併\{MMDD}-ABC-state.json
```

- `{MMDD}` ＝**今天**。同一天再跑一輪就加 `-r2`／`-r3`（`0810-ABC-r2.txt`），**不要覆蓋前一輪**。
- **兩份都要出**：`.txt` 給人審、`.json` 給整併端機器讀。只出 txt 會逼整併端重新剖析文字。

候選 JSON 的形狀（**照這個給，欄位名不要自創**）：

```jsonc
{
  "window_start": "2026-08-09 13:00", "window_end": "2026-08-10 01:50",
  "checkpoint": "0810-0100", "source": "ABC",
  "merged_into_handover": false,      // 整併端事後改 true，你一律給 false
  "reviewed": false,                  // 同上
  "counts": { "掃描": 73, "收錄": 14, "排除": 13 },
  "skipped": [ { "id": "…", "why": "skip:體育" } ],
  "needs_review": [ "…" ],
  "known_gaps": [ "…" ],
  "items": [{
    "id": "ABC080926021",             // ＝素材代碼，見 §3
    "source": "ABC",
    "first_seen_checkpoint": "0810-0100",
    "script_status": "has_script",
    "raw_entry": "ABC080926021 (ABC …) (BITE) ▎…▎05:00",   // 整行素材行，不含時段標記
    "category": { "大分類": "美國", "中主題": "民主黨政壇動態", "小分題": "AOC不排除選總統" },
    "sb_count": 3,
    "src_text": "站方原文全文（瘦身後）…",   // 2026-08-18 起必帶，見下
    "abc": { "detailId": "…", "slug": "…", "storyNumber": "…" }   // ENEX 用 "enex" 欄位
  }]
}
```

⚠️ **`raw_entry` 裡不要自己加時段標記（`△▲■◆`）**——render 依收錄時間自動補，寫了會變成兩個。

### 💾 每筆必帶 `src_text`（站方原文）——2026-08-18 起

三站早在 2026-08-04 就訂了這條，ENEX／ABC 的候選 schema 一直沒有，等於**三站用實錯
換來的教訓這邊還沒吸收**。內容規則與三站同一條（[`13b §543`](13b-S2-定時掃帶-v2省token.md)），
擇要：

- 放**抽取白名單瘦身後的站方稿件全文**（ENEX／ABC 各自的 script 欄位，白名單見兩份
  可行性計畫書），不是你寫的摘要。
- ⛔ **只准站方原文，不准寫任何自己的判斷、說明、備註**。要記判斷用候選檔的
  `needs_review`／`needs_review_note`。
  **RT4131 實錯**：agent 在原文尾巴接了一段中文說明，裡面的 `SHOTLIST`／`SOUNDBITE`
  字樣害假 BITE 判準誤判、**同一則誤報連續四輪**。
- **為什麼非有不可**：素材被新素材推出站方清單就再也調不回來——0804 三站回頭查
  BITE 誤判時，RT 有 4 則、AP 有 9 則**永遠查不回來**。`src_text` 是事後離線查證的
  **唯一依據**，也是 `sb_count=0` 到底是「沒有引言」還是「這種格式數不出來」的判準
  （`sb_applicable()`）。
- 成本可忽略：瘦身後單則約 1–5KB。
- `s2_platform_lint.py` 對缺這個欄位**直接 ❌**（本規則生效前交的舊檔跑 lint 時帶
  `--allow-missing-src-text` 降級）。

## 3. 素材編號

| 站 | 代碼 | 取自 | ⛔ 不要用 |
|---|---|---|---|
| ENEX | `ENEX{_id}`，例 `ENEX926241` | ES 回應的 `_id`（＝網址 `/exchange/{id}` 那組數字） | `newslinkId`（另一組內部編號，只留作查證） |
| ABC | `ABC{Story Number}`，例 `ABC080926021` | Detail 頁 `Story Number:`／清單 CSV `News Story` | `/Delivery/Detail/{id}` 網址那串（那是**投遞紀錄 id**，同一支投兩次會有兩個） |

- ABC 的 Story Number 是 **`MMDDYY` ＋ 3 碼序號**，**自帶日期**，跨日不會重複。
- **ABC 去重鍵＝Story Number，不是 detailId**：同 slug 同 story number 的兩筆投遞要去重；
  同 slug **不同** story number 是跨日重上的不同批次，**各自收錄**。

## 4. 素材行格式（兩站共用）

```
======大分類======

【中主題】
小分題
ABC080926021 (ABC 須螢幕標示ABC's "This Week") (BITE) ▎摘要▎畫面：…▎BITE：…▎05:00
ENEX926236 (CCTV 陸內不可用) (BITE) ▎摘要▎畫面：…▎BITE：…▎01:31
```

| 欄位 | 規則 |
|---|---|
| **第一括號** | **來源媒體寫最前面**，其餘備註（限制語等）接在後面以空格分隔。⚠️ **不另開第三個括號**。ENEX 取 `partner` 的**後半段媒體簡稱**（`CN CCTV`→`CCTV`）；ABC 寫 `ABC`，附屬台素材寫呼號（`WLS`／`WEWS`） |
| **第二括號 `(BITE)`** | 有可用聲音才寫（含 OS，見 §6）。寫了就一定要有 `▎BITE：` 段，缺一會被品質掃擋下 |
| **摘要** | **150 字硬上限**，超過就分句或移進畫面段 |
| **`▎畫面：`** | **必填**。只有圖片就寫「僅圖片，無動態畫面」 |
| **`▎BITE：`** | 見 §6。完全沒有人聲才寫 `▎無BITE。` |
| **時長** | **兩站都一律帶 `▎MM:SS` 收尾**。ABC 取清單 `Length` 欄；**ENEX 已可機械量到**（`s2_platform_extract.py` 對 `videoLowResCdn` 跑 ffprobe，見 §288），**`extract` 會自己補進 `raw_entry` 行尾，agent 不必手抄**。量不到的（`editStatus=PUBLISHING NOW` 等）才留白，⛔ 不要編數字、不要 `▎?`／`▎00:00` 佔位 |
| **`▎URL：`** | ⛔ **兩站都不寫**（2026-08-09 使用者訂）。素材代碼本身就能定位；URL 仍留在候選 JSON 的 `enex`／`abc` 欄位供機器調帶 |

> ⚠️ **這一節是目前最會出錯的地方**。0810 的品質掃 38 個 HIT 裡，**ABC 佔 12、ENEX 佔 3**，
> 集中在「缺 `▎畫面：`」「行尾掛時間碼」「摘要超 150 字」三種。**寫完自己對一遍上表再交件。**

## 5. ⛔ 整則排除規則

### ENEX

- **`partner` 含 `TVBS` 一律排除、不寫摘要**——自家素材回流，不需要摘要。
  判定用大小寫不敏感子字串：`/\bTVBS\b/i.test(partner)`。
- **`partner` 含 `TAIWAN PLUS` 一律排除**（2026-08-17 使用者訂）。
  判定用大小寫不敏感子字串：`/\bTAIWAN\s*PLUS\b/i.test(partner)`。
- ⚠️ **這是 ENEX 目前僅有的兩條整則排除規則**，其餘一律照收，
  ⛔ 不准以「地方性」「新聞價值低」自行降階。

### ABC（三層，**外電層優先於任何 ABC 正向訊號**）

> **不對稱原則**：把外電誤收成 ABC，**比漏收一則 ABC 更糟**（版權）。有疑慮就排除。

| 層 | 排除什麼 | 機械判準 |
|---|---|---|
| 0 | **體育**（版權，TVBS 不能用） | `Categories` 含 `Sports` |
| 0 | **例行娛樂／節目宣傳** | `Categories` 含 `Promos/Tie-Ins`，或 slug 以 `OTRC` 開頭，或 `GMAAhead*`／`GMATomorrow*`／`WKNDWorldNewsPromo*` |
| 1 | **外電**（AP／APTN／Reuters／AFP／CCTV／POOL／Getty／Storyful…） | 只比對 `LOCATION/STORY` 末括號、`SOURCE:` 值、`VIDEO PROVIDED BY:` 值三處，**正則用 `^` 錨在括號值開頭** |

**取值一律從那三個地方取，⛔ 不要對全文自由比對**——三個踩過的地雷：

1. `SOURCE` **不可行首錨定**（ABC 是內嵌標注，錨定會漏掉真的寫著 `SOURCE: Reuters` 的）
2. `SOURCE` **也不可完全不錨定**（會抓到 `SOURCE OF POWER IRAN CONTROLS…` 這種普通句子）——
   只取 `SOURCE` 後 60 字元內，且比對已知供應商清單
3. 呼號 `\bW[A-Z]{3}\b` **不可對全文比對**——稿件全大寫，會命中 `WITH`／`WHEN`／`KNOW`

### 🔴 機械判準管不到的，由 agent 判斷後**列進排除清單並註明「人工判斷」**

⛔ **不要靜默放行、也不要靜默排除。** 兩個方向都出過錯：

- **該擋沒擋**：`Categories` 沒標 `Sports` **不等於**不是體育。
  0810 兩筆使用者裁示——NFL 名人堂 GMA 包裝（只有演說、沒有賽事畫面）**排除**；
  愛國者運動會（包裝成 250 週年政策活動）**排除**。
  📌 **要看的是「畫面本身是不是體育活動」**，不是它被歸在哪一類、不是報導角度。
- **不該擋卻擋了**：`Promos/Tie-Ins` 誤殺 `ABC080926014`（失智症研究），人工翻案收錄。
  ⛔ **所以不可直接用 `Entertainment` 整類砍**（14 則裡混著醫療線內容）。

## 6. BITE 的認定：**主播／記者 OS 也算 BITE**

規則與寫法**完全比照 [`17-網址素材整併.md` §5](17-網址素材整併.md)**，不在這裡重寫。摘要：

| 帶子上有什麼 | 怎麼寫 |
|---|---|
| 有受訪者談話 | `▎BITE：身分 姓名「濃縮引言」`，多則用 `／` 分隔 |
| 沒有受訪者，但有主播／記者旁白 | `▎BITE：主播 OS 全程可用`／`▎BITE：記者 OS 全程可用` |
| 完全沒有人聲（靜音帶、純自然音） | `▎無BITE。` |

兩站的補充：

- **ENEX**：CCTV 的 `UPSOUND (語言) 姓名, reporter:`（記者現場講話）**照常標 `(BITE)`**，不因講者是記者而降階。
- **ENEX**：夥伴標 `SOUNDBITES (TRANSLATED WITH AI)` 的 → **忽略該標示，照常收 BITE，也不必加註提醒**。
  （AI 助理殘留的對話語句本身仍不寫進素材行——那不是發言內容。）
- **ABC**：沒有 `SOUNDBITE`（AP／RT 判準）也沒有 `footageType`（NS 判準）。
  可用線索：`SUPERS:`（講者字卡）、`FORMAT:` 含 `SOT`、逐字稿的 `講者名: [00:00:00] 內容` 形狀。
- ⭐ **ABC 的完整訪問稿附逐字時間碼**，對下游 [`掐BITE助手`](07-bite-assistant.md) 是現成的 TC。

## 7. 分類：⛔ 開新中主題前一定要先看現有的

```bash
python scripts/s2_state.py --file "…\{MMDD}-s2-state.json" list-topics
```

⚠️ **這是 0810 實際發生過的問題**：ENEX／ABC 的 agent 不知道交接單已經有哪些中主題，
開了一串平行的重複中主題——【颱風海豚】vs 已有的【颱風白海豚】、
【華州野火】【加州野火】vs 已有的【美國西岸野火】、
【AOC專訪】vs 已有的【民主黨政壇動態】（**根本是同一場訪問的 NS 版**）。
**同一件事散在兩處，編輯要在兩個地方找同一批素材。**

- **能掛既有的大中小分類就掛，不要刻意另開**（2026-08-09 使用者訂）。
- 真的是另一個事件才開新中主題（例：AP 胡塞攻擊紅海港口 vs 美伊，那是兩件事）。
- 拿不準就**照掛既有的並記進 `needs_review`**，讓整併端拍板——⛔ 不要自己開一格了事。

### 分類完再下一次 `set-tc`（2026-08-25 起，A10 v2）

大／中／小三層之外還有一條並行的 **T／C 軸**（議題／地緣），給晚班交接網頁的
矩陣檢視用。ENEX／ABC 過去沒下，那些則在網頁上會退回關鍵詞兜底或標「未分類」。

```bash
python scripts/s2_state.py --file "…\{MMDD}-s2-state.json"   set-tc --pairs "ENEX01=政治/歐洲;ABC03=天災天氣/美國"
```

- **接在 `set-category --pairs` 後面同一批下**，判大分類時脈絡還在，順手多判一組最便宜。
- 格式 `id=T1,T2/C1,C2`——`/` 左邊是 T、右邊是 C，各自可多選。單側可留空（`id=/日本`）。
- ⛔ **名稱只認 [`13f`](13f-S2-大分類與各站規則.md)「議題 T」／「地緣 C」那兩張表**，
  寫錯整批會被退回並記進 `tc_rejected`。**這兩站使用者沒訂預設 C，不要自創。**
- ⚠️ 每個 checkpoint 上限 8 次呼叫，**整批一次下**，不要逐則呼叫。
- **判不出來就留空**：沒下 T/C 的則照樣入庫（比照缺 category 進 `uncat` 的裁定——
  分類可以事後補、素材消失補不回來），網頁不會壞。**硬掛一個錯的比留空更糟。**

### 整併完的收尾：跑一次 `s2_topic_dedupe.py`（2026-08-18 起）

```bash
python scripts/s2_topic_dedupe.py --file "…\{MMDD}-s2-state.json"
```

上面的「開新中主題前先看現有的」只擋得住**第一層**（自己知道要查的時候）。
三站另外有兩層在把關——`s2_topic_review.py`（同義不同名／同事件被拆多主題）與
`s2_topic_dedupe.py`（5 類分類問題），ENEX／ABC 這邊過去**一層都沒有**，
0810 那串平行重複中主題（【颱風海豚】vs【颱風白海豚】…）就是這樣長出來的。

- 工具**無來源限制**，吃的是整併後的正式狀態檔，三站與交換平台一起檢查。

## 10. ABC 時間窗前端過濾＋清單對帳（2026-08-26 上線，A9 子項④⑨）

### ABC 時間窗只到「日」：CSV 模式＋前端分鐘級過濾

`GET /Delivery/NewsSearch` 的 `deliveryDateStart`／`deliveryDateEnd` 只吃 `M/D/YYYY`，
沒有時分（0810 計畫書已知限制）。**固定解法**：撈涵蓋窗口的整天份 CSV，`DeliveryAvailableDateTime`
欄位帶完整時分秒，前端自己過濾出真正窗內的則數。

🔴 **實測確認**：`DeliveryAvailableDateTime` 是**依瀏覽器本地時區顯示**（2026-08-26 18:36
台北時間查詢時，最新一筆是 `8/26/2026 6:30:22 PM`，跟當下時間只差 6 分鐘）——站方會讀
`tzOffset` cookie（`document.cookie` 裡的 `tzOffset=-8`＝`new Date().getTimezoneOffset()/60`）
把時間轉成瀏覽器所在時區再吐出來。**只要掃帶用的 Playwright profile 時區沒變過（一直是
台北），這欄位可以直接當台北時間解析，不必再換算。**

```js
// 整段「讀 token → fetch CSV → parse → 前端過濾」寫在同一個 page.evaluate() 內（§1 安全條款）
async function fetchAbcWindowRows(dateStart, dateEnd, sinceMs, untilMs) {
  const tok = document.querySelector('input[name=__RequestVerificationToken]').value;
  const qs = new URLSearchParams({
    deliveryDateStart: dateStart, deliveryDateEnd: dateEnd,   // 'M/D/YYYY'，涵蓋窗口所在的日子（可能跨兩天）
    pageSize: '1000', page: '1', getCSV: 'true',
  });
  const res = await fetch('/Delivery/NewsSearch?' + qs.toString(), {
    credentials: 'include', headers: { '__RequestVerificationToken': tok },
  });
  const text = await res.text();
  const lines = text.trim().split(/\r?\n/);
  const header = lines.shift().split(',');
  const rows = lines.map((line) => {
    const cols = line.split(',');
    const o = {}; header.forEach((h, i) => (o[h] = cols[i])); return o;
  });
  const parseDt = (s) => {
    const m = s.match(/^(\d{1,2})\/(\d{1,2})\/(\d{4})\s+(\d{1,2}):(\d{2}):(\d{2})\s*(AM|PM)$/);
    if (!m) return null;
    let [, mo, d, y, h, mi, se, ap] = m;
    h = parseInt(h, 10);
    if (ap === 'PM' && h !== 12) h += 12;
    if (ap === 'AM' && h === 12) h = 0;
    return new Date(+y, mo - 1, +d, h, +mi, +se).getTime();
  };
  return rows.filter((r) => {
    const t = parseDt(r['DeliveryAvailableDateTime']);
    return t !== null && t >= sinceMs && t <= untilMs;
  });
}
```

- `getCSV=true` 不受 CSRF 較嚴的 JSON 端點限制，實測直接同源 fetch 即可拿到 `text/csv`。
- `News Story` 欄＝ Story Number（去重鍵），`Length`＝時長，兩者都能直接沿用進候選 schema，
  不必再另外開 Detail 頁查（除非要抽 `Script` 全文）。
- 這支函式回傳的陣列**筆數就是窗內真實則數**，直接餵給下面的清單對帳。
