# CNN掐Bite

本規則是 [`指定掐Bite`](../reuters/04-designated-clip-bite.md) 的延伸情境：當 CNN Newsource 的 `SUPERS`／`SOT` 結構文稿，或 AP 式 `SHOTLIST`／`SOUNDBITE` 編號清單完全沒有 TC 時，用本流程補上句子級 TC。

除本文件記載的 TC 定位方法外，輸出格式、SB 命名慣例、中文翻譯、素材查找、不剪片、不上傳及不另存文字檔等規則，全部沿用「指定掐Bite」。

## 觸發條件

使用者提供一個已存在於下列位置的 CNN／AP 素材檔名，同時貼上該素材的官方文稿，並要求掐出一句或多句 Bite：

1. `G:\我的雲端硬碟\Claude共用\`
2. 「掃帶歐印萬」資料夾（不是名稱含 `v2` 的資料夾）

## 1. 以官方文稿為逐字權威來源

官方文稿中 `SOUNDBITE`／`SOT` 的英文逐字內容，是最後輸出的唯一英文原文來源，必須逐字照抄。

`video_analyze` 產生的語音辨識文字只用來尋找時間位置，不可取代或修正官方文稿。ASR 可能出現同音或近音錯字，例如把 `bend` 聽成 `ban`；即使 ASR 與官方文稿不同，最後仍以官方文稿為準。

## 2. 用 video_analyze 取得相對 TC

對找到的本機素材檔案呼叫 `video_analyze`，並將 filters 設為：

```text
transcription: true
```

取得整支影片逐句、精確到秒的語音辨識結果及每句 `start`、`end` 時間戳記。同一支素材只需分析一次；保留完整分析結果供後續一個或多個 Bite 共用。

`video_analyze` 時間戳記的精確度是可用上限，不宣稱比分析結果更精確。

## 3. 將官方文稿與 ASR 結果比對定位

把官方文稿中要引用的句子，對照 `video_analyze` 結果中語意相同或相近的句子：

- 取第一個對應句的 `start` 作為 Bite 相對起點。
- 取最後一個對應句的 `end` 作為 Bite 相對終點。
- ASR 有錯字但語意及前後文可確認為同一句時，仍可用來定位；英文輸出不得照抄 ASR 錯字。
- 若無法可靠判定對應句，不自行猜測 TC，應明確告知使用者無法確認。

## 4. 套用檔名 TC offset

若素材檔名開頭是六碼數字，將六碼解讀為 `HHMMSS`，並把此 offset 同時加到步驟 3 得到的相對起訖時間。

例如：

```text
檔名：001234_example.mp4
offset：00:12:34
相對 TC：00:00:08 - 00:00:15
輸出 TC：00:12:42 - 00:12:49
```

若檔名不是以有效的六碼 `HHMMSS` 開頭，offset 預設為 `00:00:00`，直接使用分析所得的相對 TC。

## 5. 選擇 Bite

- 使用者指定句子時，定位並輸出指定的一句或多句。
- 使用者只貼官方文稿、要求自行挑選時，依「有新聞價值、有衝突性」原則挑選。
- 同一素材需要追加更多句時，直接沿用第一次的完整 `video_analyze` 結果，不重新呼叫分析。

## 6. 輸出

只輸出純文字，不使用 code 區塊。每段 Bite 的順序固定為：SB → 中文翻譯 → TC → 英文原文。

> SB：{中文職稱} {英文姓名}
>
> {中文翻譯}
>
> TC：00:00:23 - 00:00:31
>
> “{官方文稿英文原文逐字}”

英文逐字必須來自使用者貼上的官方文稿，不得使用 `video_analyze` 的 ASR 文字替代。
