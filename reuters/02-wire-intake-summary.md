# 外電掃帶入庫(文稿摘要)

當使用者以此名稱呼叫（或說「把這則外電摘要入庫」「照資料庫格式建立這則」），依下列固定流程處理。

瀏覽器操作套用 [`../common/08-execution-efficiency.md`](../common/08-execution-efficiency.md)。

**Rollback：** 省 Token 改寫前舊版見 [`../_archive/reuters/02-wire-intake-summary.pre-token-saving-2026-07-20.md`](../_archive/reuters/02-wire-intake-summary.pre-token-saving-2026-07-20.md)。

## 省 Token 核心流程（優先遵守）

1. **稿件只抓一次**：搜尋 → 開詳情 → VIEW MORE 取全文，能 batch 就 batch；全文取得後立刻做結構化擷取，不要重開、重抓、重截圖。
2. **交付以 Notion 頁為主**：完整 `###...###` 結構寫進 Notion 頁面即可。對話回報精簡為：Notion 頁面連結或標題、Edit No.、Restrictions 一句、必要時「可出格式」濃縮段——**不要**在對話先貼完整十段摘要，再原樣貼進 Notion 等於輸出兩次。
3. **Restrictions 必報、全文不貼**：Restrictions 用一句話摘要回報；shotlist/script 原文不整份貼進對話（版權與 token 雙重理由）。
4. **少截圖**：確認 Edit No.／Restrictions 優先用 accessibility／文字擷取，不是每步截圖。

## 1. 在 Reuters Connect 找到素材
依 [`01-search-workflow.md`](01-search-workflow.md)：**使用「Video」分頁**搜尋（不是「Text」，也不是舊版曾用過的「All」——以最新更正的規則為準），依 Edit No. 或關鍵字定位，開啟該則詳細頁面。點擊 script 面板的「VIEW MORE」展開完整 shotlist/script（不要只看截斷的預覽），才能寫出準確、不虛構的摘要。

務必在 Details 面板核對頁面上顯示的 **Edit No.**，不要沿用先前對話中提到、未經頁面重新確認的編號——曾發生過誤把「7397」報成「7387」的情況。

## 2. 不要下載影片
僅做文字/稿件摘要，除非使用者另外要求下載影片。

## 3. 通用輸出規則（適用以下每個段落）

**開始前必讀** [`common/00-寫稿通則.md`](../common/00-寫稿通則.md)：版權原則、單位換算、**寫稿前事實分層**（四層分類與原文精度守則，摘要同樣適用）。

- 全程使用繁體中文。
- 人名/地名使用台灣慣用譯名，例如 Trump→川普、Putin→普欽、教宗→目前為「良十四世」（若教宗更替，需查證當時台灣慣用譯名）。
- **單位與數值換算**（金額→新台幣、華氏→攝氏、英里→公里、英尺碼→公尺、風速→蒲氏級數）依 [`common/00-寫稿通則.md`](../common/00-寫稿通則.md)。
- 人名、機構、專有名詞、專業術語：中文後方括號附上英文原文。
- 不要在回答中覆述問題/提示。
- 輸出時保留每個段落的 `###...###` 標題。

## 4. 逐段擷取規則

**### 標題 ###** — 找出原文第一個完整句子（通常是總標題）。格式：`中文翻譯（英文原文）`。

**### 文稿發布時間 ###** — 找出外電文字稿開頭的時間戳記（年/月/日/時/分）。

**### 地點 ###** — 找出原始 script 中「SHOWS:」後方列出的地點。格式：`完整中文地名（完整英文地名）`。若無提供，回答「無提供地點」。

**### 長度 ###** — 找出原文中「Duration」後的數值。

**### 畫面 ###** — 用 100 字以內的中文描述畫面內容。不要以「畫面內容包括...」這類開頭。

**### BITE ###** — 針對原文中以引號標示的所有發言，列出每位發言者的「姓名」、（頭銜）、以及「濃縮/簡化後的發言內容」。不加粗、不加星號。同一發言者的多句引言合併為一筆。範圍：只取 script 中「story」或「STORYLINE」段落**之前**出現的引言，之後的引言不列入。

**### 短摘要 ###** — 以繁體中文摘要單一最重要的重點，100 字以內。

**### 長摘要 ###** — 條列式摘要，3–5 點，總字數上限 400 字。

**### 標來源 ###** — 若原文含「Must on-screen courtesy」（或類似的掛名要求），完整寫出要求內容。否則回答「無」。

**### 可出格式 ###**（將以上三項合併為一個廣播可用區塊）：
- 將短摘要、畫面、BITE 內容整合成一個段落。
- 適度精簡——去除不必要的贅字，只留最關鍵資訊。
- 畫面部分前綴標籤 `<畫面>`。
- BITE 部分前綴標籤 `<BITE>`；若無 BITE，改寫 `<無BITE>`。
- 發言者頭銜保留在括號內。
- 同一發言者重複出現時合併處理。
- 直接給答案，不要覆述問題。
- 若「標來源」段落有掛名要求，在此區塊最前方加上 `(標來源)` 前綴；若「標來源」為「無」，則不加此前綴。

- **頁面標題（Name property）**：`RT{編號}－{中文短標題} {國旗emoji}`
- **Status property**：`"Incoming"`
- **Icon**：對應的國旗 emoji
